# ADR-0012 — Testing pyramid and shared fixtures

- Status: **decided**
- Date: 2026-09-14
- Deciders: QA lead (SDET), Architect, Backend lead, Frontend lead, Security engineer
- Consulted: planning brief "SDLC requirements", `docs/research/11-backend-tech.md` risk table, `docs/research/06-bybit-api.md` §15
- Related: `docs/plan/03-testing-strategy.md`, ADR-0013, `docs/plan/26-chart-engine-design.md` §14

## Context and problem statement

CandleViewer places real orders using data it reconstructs itself, through an exchange API that will fail in ways we cannot trigger on demand. The planning brief mandates a full pyramid (unit ≥ 85 % backend/engine, ≥ 80 % frontend; contract; integration; E2E; load; security; accessibility; chaos). The open question is *what the tests run against*: hitting Bybit in CI is impossible (credentials, rate limits, non-determinism, and it is a live venue), while hand-written mocks encode our misunderstandings rather than the exchange's actual behaviour.

## Decision drivers

- Determinism: CI must be reproducible and offline.
- Fidelity: tests must reflect what Bybit actually sends, including its oddities.
- Shared truth: backend (Python) and frontend/engine (TypeScript) must assert against the *same* expectations, or contract drift is inevitable.
- Speed: the full required-check set must complete in ≤ 15 minutes.

## Considered options

1. **Recorded-fixture-driven pyramid**: capture real Bybit sessions once, redact, commit to `packages/fixtures`, and drive unit/contract/integration/E2E/engine tests from them, plus golden outputs shared across languages.
2. **Hand-written mocks and synthetic generators only.**
3. **Live testnet/demo in CI** for integration tests.

## Decision outcome

**Chosen: option 1**, with a synthetic generator as a *supplement* for load and edge-case tests.

Layers:

| Layer | Scope | Tooling | Gate |
|---|---|---|---|
| Unit | Pure logic: normalizers, book application, bar builders, order-flow maths, rule IR compile/evaluate, OMS transitions, engine transform maths | pytest, Vitest | ≥ 85 % backend and engine, ≥ 80 % frontend |
| Property | Book invariants, bar determinism, decimation preserving extremes, IR round-trip, `orderLinkId` uniqueness | Hypothesis, fast-check | Must hold over 10k cases |
| Contract | OpenAPI and WS schema conformance both directions; `packages/protocol` freshness; exchange-adapter contract suite against fixtures | schemathesis, tsd, custom codecs round-trip | Required check |
| Integration | Full pipeline from recorded WS session → book → bars → order-flow → gateway frames, compared to golden outputs; OMS against a fixture-driven fake exchange | pytest + fake servers | Required check |
| E2E | Playwright against the web app **and** the Electron build, driving the synthetic/demo backend: login+TOTP, chart, footprint, DOM trading, ticket, fan-out, rules, replay, journal, admin | Playwright | Required check |
| Load | k6/Locust: WS fan-out with N clients × M topics, REST order burst, 24 h ingestion soak | k6, Locust | Nightly + pre-release |
| Performance | Engine benchmarks B1–B10; backend loop-lag and fan-out latency SLOs | custom harness | Required check on relevant paths |
| Security | CodeQL, Semgrep, Bandit, pip-audit, npm audit, Trivy, secret scanning, ZAP DAST | CI jobs | Required check |
| Accessibility | axe-core on every screen, keyboard-only traversal, screen-reader announcement assertions, contrast-token validation | axe-core + Playwright | Required check |
| Chaos | WS disconnect storms, exchange 5xx, 10018, 10002, process kill mid-submission, Postgres/QuestDB outage, disk full, slow WS client | pytest markers + toxiproxy | Nightly + pre-release |

`packages/fixtures` rules:

1. Captures are produced by a dedicated recorder script, **redacted** (no account ids, no keys, no signatures) and reviewed before commit.
2. Each fixture has a manifest: symbol, environment, date range, captured topics, message counts, known anomalies (gaps, resyncs, unusual payloads).
3. **Golden outputs** (expected bars, footprint cells, profiles, CVD series, gateway frames) are generated by a pinned tool version and consumed by both Python and TypeScript tests — this is what prevents the two sides from drifting.
4. Fixtures with anomalies are treasured: a captured sequence gap or a malformed payload becomes a permanent regression test.
5. Large fixtures are stored with Git LFS; the repository keeps a small "smoke" subset for fast local runs.

Additional binding rules:

- **No test may contact `api.bybit.com` or the live WS.** A CI network policy and a pytest guard enforce this.
- **Live smoke tests are opt-in and manual** (`pytest -m exchange_smoke`), run against demo/testnet before a release, never in the PR pipeline.
- **Flaky tests are quarantined within 24 h** and fixed or deleted within a sprint; a permanently skipped test is a defect.

### Consequences

Positive:
- CI is offline, deterministic and fast, while still asserting against real exchange behaviour.
- One golden corpus means the backend and the chart engine cannot disagree about what a footprint cell is.
- Chaos and security layers are first-class, matching the risk profile of a system that places real orders.

Negative / risks:
- Fixtures age as Bybit changes. Mitigated by a recurring per-sprint task to refresh captures and diff them against the current normalizer, plus the opt-in live smoke run before each release.
- Golden files can be updated carelessly to make a test pass. Mitigated by CODEOWNERS on `packages/fixtures/golden` and a required explanation in the PR description for any golden change.
- Fixture size. Mitigated by LFS plus the smoke subset.

### Why not the alternatives

- **Mocks only**: they encode our assumptions, so they pass precisely when we are wrong — the most dangerous property a test suite can have for an exchange integration.
- **Live testnet/demo in CI**: non-deterministic, rate-limited, credential-bearing, and unavailable when the venue is down; it would make the pipeline unreliable in exactly the way that erodes trust in tests.

## Validation

- The full required-check set completes in ≤ 15 minutes on the standard runner.
- Coverage gates enforced per package, not globally, so a well-covered package cannot mask a poorly covered one.
- A quarterly review confirms fixtures still match live Bybit payload shapes.
