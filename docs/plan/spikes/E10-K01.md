# E10-K01 — ShellPort abstraction spike (Electron vs browser vs Tauri)

Timebox: 3 days (per ticket). Branch: `spike/e10-shellport`. Promoted artefacts (production-quality,
covered by Task DoD) live at `apps/web/src/shell/`: `ShellPort.ts`, `BrowserShellAdapter.ts`,
`ElectronShellAdapter.ts`, `index.ts`. No throwaway prototype code was produced — the interface and both
adapters are small enough to write directly at production quality.

## 1. Responsibility coverage

Every shell responsibility named in ADR-0011 decision criterion 5 and `docs/plan/20-architecture.md`
§2.2 C3 maps to exactly one named method or capability flag on `ShellPort`. See the table in
`ShellPort.ts`'s module doc comment (kept there so it cannot drift from the interface it describes):

| Responsibility                                 | Port surface                                                   | Capability flag   |
| ---------------------------------------------- | -------------------------------------------------------------- | ----------------- |
| Window management & multi-window persistence   | `windows.float/redock/saveState/restoreState`                  | `floatingWindows` |
| OS-keychain bridge for the KEK (opaque handle) | `keychain.getKekHandle`                                        | `keychain`        |
| Auto-update                                    | `updates.check/apply`                                          | `autoUpdate`      |
| Deep links                                     | `deepLinks.onDeepLink`                                         | `deepLinks`       |
| Tray                                           | `tray.setStatus`                                               | `tray`            |
| OS notifications                               | `notifications.show`                                           | `osNotifications` |
| GPU info / flags                               | `gpu.info`                                                     | `gpuInfo`         |
| Crash log                                      | `crashLog.append`                                              | `crashLog`        |
| Playwright-drivability                         | n/a (verified by `apps/desktop/e2e`, not a runtime capability) | —                 |

No method is unused and no responsibility is missing a mapping.

## 2. No generic IPC escape hatch (SR-111)

`ElectronShellAdapter.ts` calls one named function per `ShellPort` method on `window.cv` (typed as
`CvBridge`). There is no method that takes a caller-supplied channel string. The bridge object itself is
built by `apps/desktop`'s preload script from `ALLOWED_IPC_CHANNELS` (`apps/desktop/src/preload/allowList.ts`,
already in the repo from E02-T04) — every channel is a compile-time constant validated on both the preload
and main-process sides. Wiring the concrete channel names into `allowList.ts` and `main/index.ts` is
E10-T02 scope (it needs real Electron IPC handlers); this spike only had to prove the _shape_ is
IPC-escape-hatch-free, which it is by construction: `CvBridge` has twelve fixed, named, typed properties
and nothing resembling `invoke(channel, ...args)`.

## 3. Honest browser degradation (US-SET-009)

`BrowserShellAdapter.ts`'s `capabilities.reason` record supplies a human-readable string for every
capability the browser cannot provide (`floatingWindows`, `tray`, `autoUpdate`, `keychain`, `deepLinks`,
`crashLog`), so the UI can hide the corresponding control with an explanation instead of showing it
disabled. `gpuInfo` is the one capability a plain browser tab can honestly provide (`WEBGL_debug_renderer_info`
via a throwaway canvas), so it reports `true` with no reason string. `osNotifications` reports `true` only
if the page already holds `Notification` permission — otherwise it is `false` with a reason, never silently
granted.

## 4. Tauri feasibility (paper only, per Out-of-scope)

Recorded for the ADR-0011 decision, no adapter built:

| Capability                         | Tauri v2 feasibility                                                                                                                         | Notes                                                                                                                                     |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| Window management / persistence    | Yes — `tauri::WindowBuilder`, `tauri-plugin-window-state`                                                                                    | Direct port; no redesign needed                                                                                                           |
| OS-keychain bridge (opaque handle) | Yes — `keyring` crate exposed via a Rust command                                                                                             | Same opaque-handle contract as Electron's `ipcMain.handle`                                                                                |
| Auto-update                        | Yes — `tauri-plugin-updater`, signature-verified                                                                                             | Comparable maturity to `electron-updater`                                                                                                 |
| Deep links                         | Yes — `tauri-plugin-deep-link`                                                                                                               | Direct port                                                                                                                               |
| Tray                               | Yes — `tauri::tray`                                                                                                                          | Direct port                                                                                                                               |
| OS notifications                   | Yes — `tauri-plugin-notification`                                                                                                            | Direct port                                                                                                                               |
| GPU info / flags                   | **Needs redesign** — Tauri has no bundled-Chromium GPU flag surface; it reads whatever the OS WebView (WebView2/WKWebView/WebKitGTK) reports | This is exactly the ADR-0011 decision criterion 4/5 gap: GPU flag control does not exist the same way, only the OS WebView's own settings |
| Playwright-drivability             | Partial — `tauri-driver` (WebDriver) exists but is less mature than Electron's native Playwright driver                                      | Would need its own e2e harness investment                                                                                                 |

This does not re-litigate ADR-0011: M0 (E06-K01/K02, merged) already measured frame-time criteria 1–4 in
Chromium; this spike only adds the criterion-5 shell-responsibility column, which was previously
unaddressed. Two of eight responsibilities (GPU flag surface, Playwright maturity) would need real
redesign work under Tauri; the other six are close to direct ports.

## 5. Decision recommendation

No change to ADR-0011's interim outcome. Electron remains the default; this spike's finding (GPU flag
control and Playwright-drivability are the two Tauri gaps under criterion 5) is appended to the ADR's
consequences section as evidence for the eventual criterion-5 decision, not a resolution of it — the
frame-time criteria (1–4) are still gated on the M0 report content, which this spike does not repeat.

## 6. Follow-up tickets

- **E10-T02** (Electron main/preload) implements `ElectronShellAdapter`'s IPC channels for real: wires
  `ALLOWED_IPC_CHANNELS`, adds `ipcMain.handle` for each of the twelve `CvBridge` methods, and threads
  `gpu.info()` through Electron's `app.getGPUInfo()`.
- **E10-T03** (window persistence) implements `windows.saveState/restoreState` against real
  `BrowserWindow` bounds and multi-monitor identifiers.
- No epic scope change needed; both tickets already exist with the right shape (confirmed by re-reading
  their briefs before writing this report).

## 7. Risk register

No new risk surfaced. R8 (Browser/GPU compat, already tracked) covers the residual Tauri-vs-Electron GPU
question this spike documents evidence for; `docs/plan/32-risk-register.md` is unchanged.
