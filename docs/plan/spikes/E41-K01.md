# E41-K01 — Journal analytics query tier (spike finding)

Decision: see [ADR-0027](../27-adrs/ADR-0027-journal-analytics-query-tier.md) — **Postgres only**.

Harness: `services/api/bench/journal_analytics/` (seeded; `make bench-journal DSN=postgresql://...` on a
scratch DB). Raw data: [`E41-K01-report.json`](E41-K01-report.json). Synthetic data only; `numeric(38,18)`.
Machine: Windows 11, PostgreSQL 16.4 (shared_buffers 512MB, fsync off), DuckDB 1.5.6, Python 3.13,
7 reps + 1 warm-up per cell; p50 / p95 ms, whole payload fetched client-side.
Columns: a totals; b totals + 7 breakdowns (symbol, side, account, setup, hour, dow, tag join);
c equity curve (trade); d MAE/MFE; e filtered (account+symbol+tag+date range).

`n/m` = not measured. Hybrid = 90-day hot window in Postgres unioned with DuckDB over older Parquet; the
harness times both legs, and `merge()` shows count/sum partials are additive at the boundary while `avg`
is not (carry sum+count). p95 outliers (e.g. covering @10k 3339 ms) are Windows scheduling noise, flagged not hidden.

## Index options
Existing indexes suffice at 10k. Covering index `(account, opened_at, symbol) INCLUDE (...)`: no consistent gain.
Daily rollup (materialised view) answers three breakdowns at 100k in ~0.5 s but cannot serve tag/hour/dow.

## RBAC
Postgres: mandatory scope predicate, client filters intersect only (tests in `tests/unit/journal_bench`).
DuckDB over raw Parquet has no row scoping; the API would have to inject the same predicate (second enforcement point).

## Metric
`journal_analytics_query_seconds` (histogram; `group_by`, `tier`) — E41-T03 must emit it.
