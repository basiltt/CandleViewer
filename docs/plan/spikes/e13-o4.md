## 1. Verdict

| Question                            | Answer                                                                                                                                                                                                                                                                                                                                                                            |
| ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Q1 worker within §4.3 at 100k bars? | **Yes, by ~17x.** Worst kernel (Ichimoku) full compute 14.8 ms (budget 250 ms); worst incremental 0.12 µs per closed bar (budget 2 ms/frame). Ten indicators full-compute 86 ms.                                                                                                                                                                                                  |
| Q2 rule-eligible today (§7.2)       | `sma`, `ema`, `rsi`, `atr`, `adx`, `vwap` (+`vwap_band_sigma`), `cvd`, `volume` (`bar_volume`), `zigzag` (`swing_high`/`swing_low`) → **9 × `server`**; the other **19 → `client_worker`**.                                                                                                                                                                                       |
| Q3 bit-for-bit or epsilon?          | **Bit-for-bit is achievable and is kept** — 0 non-identical values across all 23 output series on the recorded window and on 100k synthetic bars — _provided_ the authoritative Python kernel is a scalar recurrence with the TS kernel's exact operation order. Vectorised numpy (reassociated sums) breaks it. §14 wording is **not** amended; the 1e-8 epsilon is not adopted. |
| Q4 ten-indicator mirror cost        | CPU fine (86 ms full / 1.8 µs per closed bar for all ten). **Memory is not:** f64 output buffers for ten indicators over 100k bars = **46.5 MiB (incl. scratch) vs the ≤ 8 MB (shared with profile + drawings)** allocation. Bounded retention window required (§5).                                                                                                              |

Measurement caveats (stated, not hidden): runs used Node 20.14 `worker_threads` (V8, the same JS engine as the
Electron renderer worker) on the i7-8550U / 16 GB dev laptop shared with other agents, **not** Electron on reference
hardware. **The Gherkin AC "measured on reference hardware in Electron" is therefore OPEN**: handed off to
E13-Q03 (permanent benchmark), and the owner accepts it as open at ADR-0034 ratification. Margins are ≥ 17x, so the verdict
is not sensitive to that gap. Parity ran on the recorded fixture window, which is 450 × 1m bars, not a symbol-day.

## 2. Data

- **Benchmark:** seeded synthetic 1m model from the E06-K01/E11 generator (`bench/fixtures/bars.mjs`,
  seed `20260928`, ~0.2 % session gaps), ticks → $ at 0.01; prefixes of 1k / 10k / 100k bars, run through
  `densify()`.
- **Parity:** recorded fixture `packages/fixtures/bybit/2026-10-05/rest/kline_BTCUSDT_1_page{0,1,2}.json`
  (450 unique BTCUSDT 1m bars, contiguous). Because the window has **no real gap**, a 15-bar hole was punched
  at bar 200 so `densify()` synthesises 15 flat bars (`volume=0`, OHLC = prev close) and MACD/VWAP run across it.
  Python reads the fixture strings through `Decimal` then `float()` (the boundary); TS through `Number()`.
  Both are correctly rounded, so inputs are bit-identical. Also run on all 100k synthetic bars.
- Not used: `packages/fixtures/golden/bigtrade/` (on `main` since #2035, `a4ce528`) — it holds 542 raw trade
  prints over ~2.99 h for big-trade parity, not bars; rebuilding bars from it would test the E12 bar builder, not
  the indicator kernels, and adds nothing over the recorded kline window. The `golden/bars/*.jsonl` time-bar golden
  (180 × 1m) has no gap either.

## 4. Parity table

`max_abs = max|ts - py|`, `max_rel = max|ts - py| / max(1, |ts|)`; warm-up NaN positions matched exactly in
every series. "Stream" = scalar Python with the TS op order; "numpy" = vectorised Python.

| Indicator (outputs)       | Recorded window (450 bars, 15 synthetic) stream | Recorded, numpy                                        | 100k synthetic, stream | 100k synthetic, numpy                                       |
| ------------------------- | ----------------------------------------------- | ------------------------------------------------------ | ---------------------- | ----------------------------------------------------------- |
| SMA                       | 0 / 0 — bit-identical                           | 0 / 0                                                  | 0 / 0 — bit-identical  | 2.3e-7 / 3.9e-12 (99.7 % of values differ in the last bits) |
| MACD (macd, signal, hist) | 0 / 0 — bit-identical                           | n/a                                                    | 0 / 0 — bit-identical  | n/a                                                         |
| Ichimoku (5 lines)        | 0 / 0 — bit-identical                           | 0 / 0 (max/min are exact)                              | 0 / 0 — bit-identical  | 0 / 0                                                       |
| VWAP centre               | 0 / 0 — bit-identical                           | 1.0e-9 / 1.6e-14                                       | 0 / 0 — bit-identical  | 2.0e-5 / 3.3e-10                                            |
| VWAP σ and ±1/2/3σ bands  | 0 / 0 — bit-identical                           | **1.2e-2 / 1.2e-2 (σ); 5.7e-7 rel (±3σ) — fails 1e-8** | 0 / 0 — bit-identical  | **0.64 / 0.64 (σ); 3.2e-5 rel (±3σ) — fails 1e-8**          |

Reading:

1. Same-order IEEE-754 binary64 arithmetic (`+ - * /`, `Math.sqrt`/`math.sqrt` — both correctly rounded) is
   deterministic across CPython and V8. Bit-for-bit holds whenever the two kernels perform the same operations in
   the same order, including across densified gaps.
2. Reassociation (prefix sums, pairwise `np.cumsum`/`np.sum`) breaks bit-identity, and the epsilon does not rescue
   it everywhere: the one-pass variance `E[x²] − m²` cancels catastrophically, so the σ bands miss `1e-8` by up to
   three orders of magnitude. An epsilon contract would therefore _still_ constrain the algorithm; it only hides
   drift until a numerically unstable formula is chosen.
3. Transcendentals other than `sqrt` (`exp`, `log`, `pow`) are **not** guaranteed correctly rounded in either
   runtime. None of the four prototypes need them, and no v1 indicator does either (RSI/ADX/ATR/Stoch/CCI/MFI/CMF
   are rational), so this is a rule for kernel authors, not a blocker.

**Decision:** keep **bit-for-bit** (§14 unchanged). The parity test asserts `Object.is`-equality per value
(NaN = NaN) on the recorded window and on the seeded 100k set; the backend kernel is the canonical scalar-recurrence
form, and any vectorised variant is an optimisation that must itself be bit-identical or is not used.

## 6. Consequences for follow-up tickets

- **E13-T01 (worker runtime):** output buffers must not be retained for the full 100k-bar model. Retain a window
  of `visible + 2× visible + warmup` bars per output (recompute off-window on scroll from the BarStore, which is
  cheap per §3), or `f32` storage for display-only `client_worker` series. Sizing formula:
  `bars_window ≤ budget_bytes / (output_series × 8)`. The 8 MB cap is shared with profile + drawings, so the
  indicator share must be set by E13-T01; example: a 4 MiB indicator share with the measured 61 series gives
  4 × 1 048 576 / (61 × 8) ≈ **8.6k bars** of f64 retention — still well above any visible window.
  `server` mirrors stay f64 (bit-identical parity is defined on f64).
- **E13-T02 (backend kernel):** canonical kernels are scalar recurrences in the documented op order; numpy is
  allowed only where it is bit-identical (window max/min) — never prefix-sum or one-pass-variance forms. Mirror
  kernel source order is part of the contract; a change to either side changes both.
- **E13-Q05 (parity pack):** assert exact equality (NaN-aware) on the recorded window with a punched gap, plus the
  seeded 100k set; replace the fixture window with a recorder symbol-day once E16 lands.
- **E13-Q03 (perf benchmark):** closes the OPEN Electron/reference-hardware AC of this spike — re-measure the table in Electron on reference hardware; the spike harness is the
  starting point (promoted, not merged as-is).
- **E13-X01 (STRIDE):** every `server` indicator lets an authenticated user cause backend compute (and a parameter
  like `period=5000` × many instances scales it). Rate/instance caps and memoisation per
  `(symbol, spec_hash, params)` are E13-X01's to specify; not solved here.
- **Observability** (proposed names, unchanged from the epic): `indicator_compute_seconds{indicator,where}`,
  `indicator_parity_mismatch_total{indicator}`; the prototype also needed
  `indicator_output_bytes{where}` to see the memory cap, proposed for E13-T01.
- **Risk register:** the memory finding is mitigated by the retention design in E13-T01 and does not need a new
  RSK entry; it is recorded in ADR-0034 consequences.
