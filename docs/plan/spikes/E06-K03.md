## Honest limits (read first)

No GPU, headless Chromium, Playwright browser or docker exists in this environment. Therefore:

- **Measured for real (Node):** EDT/SDF generation, shelf packing, atlas cache load, FootprintStore upserts, number formatting,
  glyph-run building/instance packing, LOD selection, reformat cost.
- **Modelled:** GPU fill/draw cost (per-glyph constants calibrated to `26-…` §3.7's 0.4 ms GPU figure) and the whole
  Canvas-2D arm (assumed ~1.1 µs/glyph `drawImage`, one call per glyph — it cannot batch). The Canvas-2D arm is a
  spot-check per the ticket's scope trim, **not** a measurement; the ranking is structural (draw-call count), the
  absolute ms are assumptions.
- Glyph bitmaps come from a procedural rasteriser (no 2D canvas in Node), so shape fidelity and the real font
  (vendored, pinned — see Security) are untested. EDT/pack cost is real for the 24 px size class.
- **Not delivered here (needs a real browser):** golden images per LOD at DPR 1.0/2.0, DPR 1.0/1.5/2.0 fwidth check,
  IndexedDB (a Map-backed store with the same async get/put shape stands in), pixel-sampled contrast. E06-T02/E11 M3 must run these.

## B3 results (3 reps x 3 s CLI run; vitest asserts the gates over 3 reps x 1 s)

2,500 visible cells, L0 (14 px cells), two numbers per cell, outline on, ~13% double-flagged (imbalanced+estimated) cells.

| Arm                                       | p95 frame ms | Text batching ms | Outline ms | Text draw calls | Glyphs | Texture MB |
| ----------------------------------------- | ------------ | ---------------- | ---------- | --------------- | ------ | ---------- |
| SDF atlas (typical, ≈6 glyphs/cell)       | 1.87         | 0.52             | 0.19       | **1**           | 15,689 | 1.0        |
| SDF atlas (5-digit stress, 27,381 glyphs) | 2.59         | 0.97             | 0.33       | **1**           | 27,381 | 1.0        |
| SDF, outline off                          | 1.77         | 0.55             | 0          | 1               | 15,689 | 1.0        |
| Canvas-2D glyph cache (modelled)          | ~34          | 17.4             | 15.5       | 15,689          | 15,689 | ~2         |

Gate: p95 ≤ 16 ms, text ≤ 2.0 ms, ≤ 2 draw calls — **met by SDF in both load cases (modelled GPU)**; Canvas-2D fails
the draw-call gate and (as modelled) p95. This is not "within noise", so no E11 deferral of the comparison is proposed,
but the Canvas-2D absolute numbers should be re-measured in real Chromium before ADR-0002 is cited.

Outline pass cost (reported separately): ~0.19 ms typical / ~0.33 ms stress, ≈ +0.1 ms p95. Mandatory per E06-D01 §5.

## Atlas (acceptance: generated once, not per launch)

- Cold generation (73 glyphs, 24 px, two-pass EDT): 10–60 ms across runs (first run includes JIT) — consistent with the
  ~40 ms target. Cached load: **0.02 ms** (Map store; a real IndexedDB read of a 1 MiB blob must be re-measured against ≤ 5 ms).
- Cache key `(fontFamily, weight, hash(glyphSet))` = `Inter|500|<fnv1a>`; contains nothing user-identifying; stored value
  is bitmaps + glyph table only.
- Packing: deterministic (sort by height desc, codepoint asc), order hash `891e352f`, uses 65 of 1024 rows.
- Texture memory: 1 MiB nominal; driver padding is not observable here.

## Contrast

Computed (WCAG formula, E06-D01 §5 colours): raw text on bid/ask fill 2.04:1 / 3.25:1 (fail 4.5:1);
text vs the near-black outline `#0B0E11` 16.1:1 (HC theme 18.2:1). Outline path therefore clears 4.5:1. This is a
colour-pair computation, not pixel sampling of rendered output (no renderer) — M3 should add the pixel-sampled check.
Note the E06-D01 table lists ask contrast ~2.1:1; the formula on its hex values gives 3.25:1 — still failing, conclusion unchanged; flagged for E06-D01 owner.

## LOD ladder

`selectFootprintLod` implements `LOD_PROFILE_M0` (L0 ≥12 px, L1 ≥10 px, L2 ≥6 px; down-switch 10.2 / 8.5 / 5.1;
up-switch at the full threshold). Slow zoom 16→4→16 px: 3 transitions each way, **no flicker**. L2 sheds text only:
cell count unchanged, glyphs 0, frame time drops (asserted). Non-colour encodings: delta `▲/▼` glyph prefix is in the
glyph runs and atlas; imbalance outline and estimated hatch are modelled as shader costs (hatch cost per doubly-flagged
cell is included); their geometry is not rendered here.

## Reformat cost

Full → compact (1.2K) invalidates only the run cache (asserted: cell arrays unchanged). Measured ~5.7 ms for 2,500 cells
(cold JIT; warm runs lower) — slightly over the 4 ms single-frame mutation budget, so it **must spill across ≥2 frames**
(chunk the rebuild, ~1,250 cells/frame). The unit test only enforces a loose 20 ms CI-safe bound.

## What M3 must budget (for E06-T02)

1. Real WebGL2 re-measure of B3 for both arms in headless Chromium + the DPR 1.0/1.5/2.0 legibility check; goldens per LOD.
2. Chunked reformat (≥2 frames) and incremental run updates on live ticks; use `upsertFootprintCells` ranges for `bufferSubData`.
3. Instance buffer: 12 floats/glyph × 27k glyphs ≈ 1.3 MB; 1 draw up to 65,536 glyphs/chunk, report chunk count.
4. Real font rasterisation via OffscreenCanvas into the same `generateAtlas` seam; vendored, pinned font asset only
   (no CDN — STRIDE Tampering; constraint recorded for E11).
5. IndexedDB timing ≤ 5 ms, and fall back to regeneration (≤ ~60 ms) on cache miss/corruption.
6. Text shedding (L1/L2) is a real second degradation lever: frame time at L2 is the colour-quad cost only.

1024×1024 R8, single 24 px size-class, glyph set = E06-D01 §3 + space + `()`; recorded in `26-…` §16 and §3.7 confirmed (SDF).
