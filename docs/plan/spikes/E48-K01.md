# E48-K01 — Documentation toolchain spike

Ticket #1328. Decision: [ADR-0028](../27-adrs/ADR-0028-docs-toolchain.md). Prototype: throwaway, **not committed**
(local `mkdocs.yml` + venv; config reproduced at the end). Status: findings, owner approval pending.

The ticket requires the offline build to be "proven, not assumed"; it is currently **unproven**, so the ADR is
`proposed-with-deadline`, not `decided`.

## Measured prototype

Config: `mkdocs-material 9.7.7` (MIT), `docs_dir=docs/plan`, `pymdownx.superfences` custom `mermaid` fence, `search` plugin.

| Run | Wall-clock | Warnings |
|---|---|---|
| 1 | 233 s | 0 |
| 2 | 187 s | 0 |
| 3 | 201 s | 0 |

Median **201 s** — over the 3-minute hard budget when unscoped. Caveat: shared, loaded Windows machine with other
agents running, so this is an upper bound, not a CI number. The size driver: `docs/plan/` is 5.4 MB of which
**`backlog/` is 35 MB of ticket JSON** copied as static assets. A single run excluding `backlog/` and `spikes/*/`
completed in 111 s on the same loaded box (one run, indicative only). The production site must therefore scope its
content (`exclude_docs`), and E48-T02 must re-measure on a CI runner. Budget compliance is **not yet shown**.

Mermaid: `20-architecture.md` has 16 mermaid fences; the built page has **16** `class="mermaid"` blocks (1:1).
Caveats: Material renders client-side with mermaid.js loaded from a CDN by default, so for air-gapped *viewing* the
script must be vendored (`extra_javascript`); the build itself needs no network. Visual rendering not screenshot-verified.

OpenAPI: `22-api-openapi.yaml` has **165** paths / **220** operations. MkDocs copied it as a raw file only; no reference
is rendered — a renderer is the second half of the decision.

## Comparison (M = measured, D = desk)

Scores 1-5 (5 best).

| Criterion | MkDocs Material | Docusaurus | Vite/Astro + `packages/ui` |
|---|---|---|---|
| Build time on CI | 201 s unscoped, 111 s scoped (M, loaded box) | ~1-3 min at this size (D) | fastest class (D) |
| Offline build | yes by design; vendored mermaid needed to view (D) | yes, large `node_modules` (D) | yes (D) |
| Search | 4 — built-in client-side, offline | 3 — Algolia or local plugin | 2 — build own |
| Authoring for backend engineers | **5** — plain Markdown | 3 — MDX breaks on `{}` / `<` | 3 |
| Dark theme cost | 4 — `slate` palette | 4 | **5** — reuse tokens |
| Versioning | 3 — `mike` | 5 — native | 1 |
| Mermaid | 4 (M: 16/16) | 4 — official plugin | 2 — DIY |
| Link-check hooks | 4 — strict mode | 4 — broken-link throw | 2 |
| Maintenance burden | 3 — MkDocs 2.0 notice warns plugins/theming will break; pin `<2` | 3 — fast major versions | 2 — we own it |
| Licence | MIT (M) | MIT | MIT |
| Supply chain | 31 py dists (M) | several hundred npm pkgs (D) | medium (D) |

REST reference: **Redocly CLI** `build-docs` — already the OpenAPI linter, static HTML, no new dependency (D);
**Scalar** — nicer UI, new dependency, default CDN assets (D). WS reference: no off-the-shelf renderer for
`23-ws-protocol.md`; a small generator script rendering the schema bundle to Markdown tables.

## Staleness check (design only)

`make docs` regenerates `docs/reference/` into a committed tree; CI runs `make docs && git diff --exit-code docs/reference`
and fails with `DOC-002` when an operation was added to the YAML without regeneration. Not exercised here.

## Follow-ups for E48-T02 (scope adjustments)

1. Scope the build (exclude `backlog/`); re-measure 3x on CI; fail if >180 s.
2. Prove `docker run --network=none` build; vendor mermaid.js.
3. Wire Redocly `build-docs` + WS generator + `DOC-002` check.
4. Run axe, FCP, link-check, `pip-audit`.
5. Pin `mkdocs-material` with hashes and `mkdocs<2`; security-review + CODEOWNER for the new dependency group.
