## Decision 1 — Sweep driver: reuse the Playwright E2E navigation model

**Chosen:** extend the Playwright fixtures (the keyboard-only suite, `05` §9.4) with a thin
`sweep(screenId, state)` helper that runs axe (`@axe-core/playwright`, already a dependency used in
`smoke.spec.ts`), the accessibility-tree snapshot (§9.6) and the keyboard-reachability check per
screen+state, emitting records conforming to the finding schema.

| Alternative | Why rejected |
|---|---|
| Dedicated route/state enumeration harness | A second navigation model that drifts from the E2E one; duplicates the screen registry; costs more to build (E47-T04 is already 3 pts). Kept as fallback only for screens the E2E suite cannot reach. |
| Manual axe browser extension sweep | Not repeatable, no machine-readable output, cannot run nightly. |
| Lighthouse-only | Subset of axe rules; no state coverage; used as a separate §9.2 gate, not a sweep driver. |

## Decision 2 — State enumeration: fixtures first, WS-mock injection second, manual third

1. Prefer **state fixtures** shared with Storybook/visual regression (empty, loading, error, populated,
   edge-density): deterministic, no backend.
2. Where a state is runtime-only (stale >2 s, disconnected SCR-152, replay, rate-limited, GPU
   context lost) use **injection over the WS mock** (drop/delay frames, close the socket).
3. Anything neither can reach is a **manual-only row** in the matrix, never dropped.

Manual-only candidates identified from `14-screens-catalogue.md` (heuristic, to be confirmed once routes exist):

| Screen/state | Why no fixture is expected |
|---|---|
| SCR-030 low-GPU degraded / WebGL context lost | needs real GPU loss; cannot be induced in headless Chromium reliably |
| SCR-030 / SCR-050 canvas content (what a sighted user sees) | canvas pixels are invisible to axe; covered by SCR-045 table parity + manual SR |
| SCR-082 node-graph editor drag interactions | pointer-driven; keyboard alternative must be verified by hand |
| SCR-156 error boundary | requires inducing a render exception; needs a test-only throw hook |
| SCR-152 in-panel variant per panel | one state per host panel; sampled, not exhaustive |
| Live-enablement / destructive confirm dialogs | demo-only build cannot reach live environment states |

## Decision 3 — Finding record schema and location

Checked-in JSON, not a spreadsheet, so E47-T05 generates the conformance report from it.
Schema: `docs/plan/a11y/finding-record.schema.json` (JSON Schema 2020-12). Fields: `id`, `screenId`,
`state`, `componentId`, `wcagSc`, `level` (A|AA), `severity` (blocker|serious|moderate|minor),
`reproduction`, `detection{source: automated|manual, tool, heuristic}`, `owningTicket`, `status`.
Live data file (created by E47-T01): `docs/plan/a11y/findings.json`. Example: `findings.example.json`
(clearly marked as not a real finding). Validated by `scripts/tests/test_a11y_finding_schema.py`.

## Sprint plan: deep manual pass vs automated + spot check

Rationale: automated tools find roughly the structural defects (names, roles, contrast, landmarks);
canvas, dense, and destructive surfaces carry the real risk and need a human with an SR.

| Pass | Screens | Why |
|---|---|---|
| Deep manual (NVDA, keyboard-only, full §8.2 task script) | SCR-030, SCR-045, SCR-050 (canvas + DOM mirror + table parity); SCR-082 (node graph); order ticket and live-enablement/destructive confirms; SCR-152, SCR-156 | canvas/dense/destructive; money-moving |
| Automated + spot check (1 in 5 per area) | remaining screens (about 14 catalogue bands) | form/list/table chrome, well covered by axe + a11y-tree snapshot |
| Manual-only rows | the table under Decision 2 | no reachable fixture |

## Cost estimate and measurement protocol

No measured per-screen figure exists (see "Measurement status"). Protocol to produce it:

1. Run the sweep helper over the 10 prototype screens (SCR-030, 045, 050, 082, 117, 152, 156 plus three
   chosen from forms/lists) in every fixture state; record wall-clock per screen+state.
2. Extrapolate: `per_screen_seconds x 159 x mean_states`. Nightly CI budget target: <=20 min.
3. If the extrapolated automated sweep exceeds 20 min, shard by screen band; if the **manual** estimate
   exceeds the E47-T01 estimate (3 pts), attach a scope proposal (deep pass limited to the table above).
4. A second person re-runs the prototype from this document alone to confirm reproducibility.
