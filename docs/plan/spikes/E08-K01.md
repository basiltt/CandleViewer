# Spike E08-K01 — book depth-tier and cadence policy (200 vs 500)

- Ticket: E08-K01 (issue #127), Spike, 2 pts, P1, blocked_by E08-T03 (merged).
- Branch: `spike/e08-book-depth-tier`.
- Decision record: `docs/plan/27-adrs/ADR-0021-book-depth-tier-policy.md` — decision is
  **defer, default depth 200, revisit at E21 with heatmap evidence**.
- Timebox used: single agent session, well inside the 3-working-day timebox.

## What was built

The ticket's Technical notes ask for the comparison to be measured by replaying recorded fixtures
through the real `BookState` prototype and the merged bus (E08-T03), not a live socket. Kept as a
promoted, re-runnable benchmark harness (not thrown away) per the ticket's own DoD item "Spike branch
left unmerged/archived **except the promoted benchmark harness**":

- `services/api/bench/book_depth_compare.py` — replays a synthesised, recorded-shaped two-hour
  `book.{depth}.{symbol}` delta stream through a minimal `BookState` prototype (M7 `book` is still an
  empty scaffold — nothing real to import; see `pyproject.toml` coverage `omit` list) and the real
  merged bus (`candleviewer.bus.bus.Bus`). Deterministic, seeded generator calibrated to the wire shape
  in `docs/plan/24-internal-schemas.md` §14.1/§14.3. CLI: `--hours`, `--seed`, `--out`.
- `services/api/tests/unit/book/test_book_depth_compare_bench.py` — smoke test (not a CI performance
  gate) asserting the harness runs end-to-end, every result is measured (`estimated=False`), tier 500
  covers more price depth than tier 200, and the decision rule is deterministic. `5 passed`.
- `docs/plan/spikes/E08-K01-report.json` — the committed, machine-readable 2-hour run (seed=1) that the
  comparison table and decision are drawn from.

## Why synthetic, not a live capture (Fixture provenance)

This environment has no Bybit credentials and no docker; C-13.5 forbids any live-exchange network call
in tests/CI/dev defaults; and no recorded 2-hour order-book capture exists yet in
`packages/fixtures/raw/` (that corpus is `E08-T05`, not yet landed). The generator is a fixed,
documented, seeded model instead — reproducible (`--seed 1 --hours 2`), not hand-typed. This is the
explicit, undisguised caveat the ADR also carries: **`E08-S05` must re-run this harness against a real
recorded fixture once `E08-T05` lands**, before treating these numbers as a production SLO (mirrors the
same caveat ADR-0020 recorded for its in-memory session harness).

## Results (BTCUSDT / ETHUSDT / SOLUSDT, 2h simulated window, seed=1)

Full table and both measurement-limitation caveats (CPU near-1.0 artifact of a single-tenant harness;
`tracemalloc`-traced memory undercounting real RSS) are in ADR-0021's Comparison table section — not
duplicated here per C-16.5. Headline, unambiguous finding: tier 500@200ms writes **~24-29% more
bytes/day** than tier 200@100ms per symbol despite halved cadence (each delta carries up to 2.5x more
populated levels) — the "materially different product, not a tuning knob" the ticket predicted.

## Decision and deviation from the mechanical rule

The pre-agreed rule ("if depth 500 exceeds 0.5 vCPU/symbol or 300 MB/symbol, depth 200 is chosen
outright") is applied mechanically by `apply_decision_rule()`, but its CPU leg is a measurement artifact
on this single-tenant, single-threaded harness (every row reports ~0.99 vCPU, including tier 200) and
cannot discriminate between tiers — ADR-0021 records this as the ticket's own permitted "any deviation
is justified explicitly" case. Memory does not trigger on either tier. Both budgets are therefore
inconclusive-on-cost, matching the ticket's third Gherkin scenario exactly: the ADR records **"defer,
default 200, revisit at E21 with heatmap evidence"**, with the revisit trigger stated (E21's heatmap
prototype reporting that tier-200's coverage visibly truncates the rendered depth for the pinned symbol
set).
