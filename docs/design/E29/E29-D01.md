## 4. Decisions (proposed; each is a heuristic proposal pending owner validation)

### D1 Default columns (traces F1, F2, F4, F9, F12, F16)

CMP-056 ColumnPicker hides items marked ◌. Order is left to right. Sticky: Env + Account + Symbol.

**Positions:** Env badge (`DEMO`/`LIVE` text) · Account · Symbol · Side (`▲ Long` / `▼ Short`, text) · Size · Entry · Mark · uPnL (signed, USDT) · R · Liq price · Liq distance % (with proximity text, D5) · SL (price + protection chip, D3) · Lev · ◌ Margin mode · ◌ rPnL today · ◌ TP · ◌ Notional · ◌ Position idx (hedge only) · ◌ Opened · ◌ Trade group.

**Working orders:** Env · Account · Symbol · Side · Type · Qty · Filled/Qty · Price · Trigger · State (D2) · SL protection chip · Age · ◌ TIF · ◌ Flags (reduce-only, post-only, close-on-trigger) · ◌ Parent (algo/bracket) · ◌ Trade group · ◌ Origin. Untriggered conditionals: separate collapsible section "Conditional (untriggered)" with trigger spelled out ("Triggers when Mark falls to 62,000").

**Fills:** Time · Env · Account · Symbol · Side · Price · Qty · Fee (+ currency) · Liquidity (`Maker`/`Taker`) · Order id · ◌ Exec id · ◌ Trade group · ◌ Rule · ◌ Closed PnL · ◌ Slippage vs intent.

### D2 State vocabulary (traces F4–F7)

Display labels map 1:1 to B1 `lifecycle` states; the contract names stay in the data attribute and the accessible description.

| B1 state | Label | Glyph | Notes |
|---|---|---|---|
| draft / validated | not shown in blotter (ticket-local) | — | |
| submitting | Sending | ◌ | |
| submitted | Working | ● | |
| triggered | Triggered | ● | |
| partially_filled | Partial 0.200/0.500 | ◐ | |
| cancel_pending | Cancelling | ⟳ | a late fill flips it (S3) |
| amend_pending | Amending | ⟳ | pending rules in D4 |
| unknown | Unknown — checking | ? | amber; "We could not confirm this order; reconciling." |
| quarantined | Quarantined | ⛔ | critical; non-actionable except diagnostics |
| filled / cancelled / rejected / expired / killed | Filled / Cancelled / Rejected / Expired / Killed | ✓ ✕ ✕ ✕ ■ | terminal; move to Fills/History; rejected opens SCR-077 |
| (S9) untracked | Untracked (adopt) | ◇ | never rule-managed |

Protection chip (independent column, from B1 `protection` / B8): `sl_pending` "SL pending", `sl_present` "SL ✓" with price, `sl_missing` "NO SL !" critical, `not_required` "—" (reduce-only/closing). Account-level state (reconciling, stale) is a banner, not a row state.

### D3 Grouping and totals (traces F11, F12)

Default group-by: **account** (owner and manager alike), collapsible, with per-account subtotal. Alternatives in the toolbar: symbol, trade group, manager (owner only). Trade-group view: group row aggregates size and PnL (US-POS-001) and expands to per-account legs. **Totals never cross environments**: one totals row per env, each labelled; mixed demo+live is shown as two blocks, never a single sum. Manager view: server-scoped, so the account list contains only assigned accounts.

### D4 Pending amend (traces F5) — to be tested, see §8

Rule: **the cell keeps showing the last confirmed value as primary**; the requested value appears as a secondary tag. Candidate treatments for the walkthrough: (A) confirmed value + `→ 63,500 pending` tag + "Amending" state label, (B) both values stacked, (C) greyed requested value only. Recommended default: A, because it can never be read as applied (the confirmed value is never replaced). The tag has text, not only dimming. On ack the tag disappears; on rejection the row shows "Amend rejected — still 63,000" with the exchange reason, until dismissed (S2). Pending state is never optimistic for fills or positions (only for amend/cancel intent).

### D5 Liquidation proximity (traces F13; thresholds are proposals)

Escalation by distance of mark to liq price, always glyph + text: ≤5% "Watch" (△), ≤3% "Near liquidation" (!), ≤1.5% "Critical — near liquidation" (!!). Row text e.g. "! within 1.4% of liquidation" (as SCR-063). Thresholds are configurable per profile; defaults need owner confirmation and exchange-liq-model check. Assertive live region only on crossing into Critical, once per crossing.

### D6 Reconciliation correction (traces F8; wording to be tested)

Both: (1) inline row marker "Corrected" with a one-time subtle highlight (static with reduced motion) persisting until acknowledged or 60 s; (2) a dismissible non-modal banner per account. Text template: "Bybit disagreed with CandleViewer and its value is now shown. BTCUSDT size was 0.250, now 0.200 (exchange). Detected 14:02:11 UTC." The old value stays visible (struck through) in the row tooltip/detail so someone who acted on it can see what changed. Audit shows both values (F8).

### D7 Destructive-action confirm paths (traces F14, F15)

| Action | Confirm |
|---|---|
| Close position % / full | Demo: single `Enter` on a preview popover. Live: SCR-076-style dialog restating account, env, side, symbol, qty; `Enter` armed after 400 ms; `Esc` cancels |
| Cancel one order | Demo and Live: `Esc` on focused row asks nothing (cancel is safe), shows Undo-free toast; reduce-only protective orders (SL/TP) always confirm |
| Cancel all / close all in view | Dialog listing counts per account/env; Live also a typed word |
| Reverse | Dialog stating both legs (close then open), Live typed word |
| Edit SL (loosen or remove) | Confirm dialog, audited; tighten allowed directly (§8.8 item 5) |
| Flatten all | 800 ms hold with a discrete-press keyboard fallback (second `Enter`) plus typed confirm in Live |
Every mutating control emits an audit event; disabled actions show the reason (lockout, freeze, stale, viewer read-only).

### D8 Density (traces F16)

Default **compact 24 px rows**, option comfortable 32 px; target ≥24 px (F13). Design for ≥30 rows visible at default panel height; virtualise at ≥1 000 rows. Numerals in JetBrains Mono, tabular, right-aligned. This is a design assumption, not a measured trader expectation (§8).

### D9 Keyboard model (traces F13, F15)

Table is an ARIA grid, one roving tab stop; `↑/↓` rows, `←/→` cells, `Home/End` first/last, `PageUp/PageDown`, `Space` select, `Shift+↑/↓` extend. `Ctrl+Alt+1..3` tab switch inside the panel (proposed; must not clash with `Ctrl+1..9`, `Ctrl+W` conflicts with browser close in the web build — owner to confirm Electron-only). `Enter` SL/TP editor; `Ctrl+W` close selected (confirm per D7); `Ctrl+Shift+W` close all in view; `Esc` cancel focused order / dismiss; `Ctrl+Shift+F` flatten account; `Shift+F10` or `Menu` per-row actions menu; `Alt+T` data-table alternative; `Ctrl+\` region cycle. Live updates never move focus; sort via header `Enter`; sorting is frozen while a row is focused or selected for a pending action (proposed) to avoid rows jumping under the cursor.

### D10 Position detail (US-POS-004, F17)

Worth opening if it shows: header (account, env, side, size, uPnL), protection status with SL/TP prices and the controlling rule, entry executions list, fees and funding paid, MAE/MFE, attached orders, trade group and sibling legs, reconciliation history ("externally modified" notice with detected-at), journal link, "show on chart".

## 6. Accessibility notes

Side, state, protection, env and liq proximity all carry text + glyph (F13). Real table/grid semantics, `aria-sort`, totals row via `scope`, per-row menu for row actions. Live regions: polite throttled for PnL, assertive for fill/reject/critical-SL. No focus theft. High-contrast token set (`color.*.hc`) must be checked by Q05. A keyboard-only and screen-reader session is required by the ticket and is open (§8).
