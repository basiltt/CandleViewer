## What was built

Three-tier model from `docs/plan/16-design-system-brief.md` §2, realised as **Penpot token sets** so that a change to
a primitive cascades to every bound shape in every file that uses the library:

| Tier | Penpot set | Count | Rule |
|---|---|---|---|
| 1 Primitives | `primitives` | 130 | Raw values only (`palette.*` incl. `palette.light.*`, `space.*`, `size.*`, `radius.*`, `border.*`, `font.*`, `opacity.*`, `elevation.*`, `motion.*`). Never applied to shapes directly. |
| 2 Semantic (dark) | `semantic-dark` | 122 | **Every value is a `{reference}`** to tier 1. Canonical/base semantic set; also carries the non-colour tiers (space/size/radius/type/elevation) shared by every theme. |
| 2 Semantic (light override) | `semantic-light` | 81 colour tokens | Overrides only `color.*` — same names, re-pointed at `palette.light.*` (tuned, not inverted — see "Decisions"). |
| 2 Semantic (hc override) | `semantic-hc` | 6 colour tokens | Minimal high-contrast overrides: buy/sell → their existing `.hc` variants, text/border/focus-ring pushed to the strongest available primitives. |

### Themes (colour axis) and density (spacing axis) — two independent axes, not a 3×2 token matrix

Per brief §2.3, density is **not** a second parallel semantic tree: it is resolved through the existing
alias indirection (`space.*`, `size.control.height`, `size.row.height` already point at a `compact` primitive;
`size.row.height.comfortable` exists alongside it as the alternate resolution). `themes.json` declares the
mapping explicitly:

| Theme | Sets layered (later overrides earlier) |
|---|---|
| `dark` (canonical) | `primitives` → `semantic-dark` |
| `light` | `primitives` → `semantic-dark` → `semantic-light` |
| `high-contrast` | `primitives` → `semantic-dark` → `semantic-hc` |

Density is a metadata mode (`compact` / `comfortable`) recorded in `themes.json.density`, resolved by which
primitive a given semantic size/space token is aliased to — no theme file needs to change to change density.

Cascade verified live: changing `palette.blue.500` → `#FF00AA` recoloured `color.env.demo`, `color.action.primary.*`,
`color.position.entry` swatches after a theme re-activation; reverted. (Note: Penpot re-paints bound shapes on theme
toggle / set change, not synchronously on `token.value =` from the plugin API — agents must toggle the theme after
bulk edits; recorded in `docs/design/README.md`.)

### Semantic groups

- **Surface** app / canvas / raised / overlay / hover / selected / sunken — dark-first ladder on `#0B0E11` (never pure black except `sunken`).
- **Border** subtle / default / strong · **Text** primary `#E8EAED` / secondary / tertiary / disabled / inverse / link / on-action.
- **Action** primary default/hover/active (blue), secondary default/hover, **focus.ring** (blue-300, ≥3:1 on every surface tier).
- **Buy / Sell / Neutral** default / hover / subtle / **hc** (high-contrast variants for `Ctrl+Shift+H`). Green `#2EBD59` / red `#E5484D` — CVD-checked pair; every use also carries a non-colour cue (rule in `15-component-catalogue.md` §0.3).
- **Status** success / warning / danger / info × default / subtle / strong. **`danger` (red-600) is a different hue from `sell` (red-500)** on purpose.
- **Env** demo (blue) / live (red) — reserved, used nowhere else.
- **Chart** candle up/down/wick, footprint bid/ask/imbalance, profile bar/poc/valuearea, order line, position entry/sl/tp, drawing default/selected, node trigger/condition/action/logic/comment, grid/axis/crosshair, heatmap zero + bid.1–5 / ask.1–5 (default convention green-bid/red-ask).
- **Spacing aliases** inset.* / stack.* / button.padding* / field.gap / panel.padding / dialog.padding (compact density resolves to the 4-px scale).
- **Sizing** control.height 24 / row.height 24 / icon 16 (compact). **Radius** control sm / card md / dialog lg / badge pill.
- **Typography** `type.ui.*` (caption 11 → display 24, Inter) and `type.num.*` (10 → 20, **JetBrains Mono** — every numeric).

## Decisions taken (need your OK)

1. Naming: leaves that had children were suffixed `.default` (`color.buy.default`, `color.status.danger.default`) — Penpot forbids a token at a path that is also a prefix.
2. Type scale 10/11/12/13/14/16/20/24 (dense; base 13) — brief said "~1.125, tuned for dense UI".
3. Heatmap ramp reuses the green/red primitive ramps (5 stops each) rather than a separate sequential palette — fewer primitives, same cascade.
4. **Light and high-contrast themes now built** (this pass), verified by `verify_tokens.py`: light re-tunes surfaces/text/action to a
   separately-authored `palette.light.*` ramp (not a naive value-inversion of dark — explicitly checked); high-contrast is a minimal
   override set (buy/sell → `.hc`, text/border/focus pushed to max contrast). `color.status.danger.default` in light points at
   `palette.light.amber.500` (not `palette.light.red.600`, which doesn't exist and would have collapsed the danger/sell hue
   separation the proof requires — dE76 ≥ 8 in every theme).
5. Density is spacing-axis metadata (`themes.json.density`), resolved via existing aliases — no second semantic tree, per brief §2.3.
6. Comfortable-density row height alias (`space.row.height.comfortable` → `size.row.comfortable`) added alongside the existing
   compact alias so both resolutions exist in the same semantic file without a theme fork.
