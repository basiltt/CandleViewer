**Deliverable:** research plan, discussion guide, stimulus descriptions and findings report (heuristic

## Why this file exists here too

Per `docs/design/README.md`'s convention, every `E*-D*` ticket has a spec file under `docs/design/<EPIC>/`.
This ticket's primary output is a **research report** (see the full content at
`docs/research/findings/E12-bar-modes.md`), not hi-fi frames, so this file is intentionally short: it
records what a design consumer of this ticket needs from the `docs/design/` tree, and confirms no
Penpot frames were produced (out of scope for this ticket — see below).

## Scope confirmation

- **In scope for this ticket:** research plan, discussion guide, stimulus *descriptions* (not
  pixel-accurate mockups), bar-mode vocabulary, precedence rule, feasibility threshold, corrections
  filed against `14-screens-catalogue.md` / `15-component-catalogue.md`, handoff comments.
- **Out of scope (owned by E12-D02..E12-D08):** any pixel-level or hi-fi visual design. No Penpot
  frames are produced by this ticket. If a future reader expects a Penpot page named
  `E12-D01 <name>`, none exists by design — the ticket's own "Out of scope" section excludes hi-fi
  visual design, and the stimulus descriptions in the findings report are deliberately kept as text
  descriptions of candidate treatments, not rendered boards, since building rendered boards in a
  neutral tool is a task for whoever runs the real sessions (owner or recruited participant), not a
  Penpot deliverable bound to CandleViewer's design system.

## Token usage

This ticket does not bind any component to a semantic token — it is a research artefact, not a
screen or component spec. The **corrections** filed in the findings report (§9) reference existing
components (`CMP-220`, `CMP-226`) which already bind to `packages/ui/tokens/semantic-dark.tokens.json`;
no new token is proposed by this ticket. Any token gap identified by a future hi-fi ticket (E12-D02+)
should be recorded there, not here.
