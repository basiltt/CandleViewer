# E08-D05 — Hi-fi: SCR-102 Symbol search and SCR-041 Symbol/interval quick-switcher

## 1. Purpose

Specify the hi-fi frames and interaction contract for the two catalogue-fed symbol-selection surfaces
(`14-screens-catalogue.md` SCR-102, SCR-041) so `US-MKT-002`'s <=50 ms local type-ahead budget, full ARIA
combobox semantics, and the v1 scope boundary ("Bybit USDT linear perpetuals only") are visible in the
design rather than invented later by engineering. Both surfaces read the same client-side instrument
catalogue (`US-MKT-001`, E08's instruments-info cache, `GET /api/v1/instruments`, refreshed hourly
client-side / <=12 h server-side) and must render its freshness state, not just its results.

## 2. Ranking rule (binding, deterministic)

Applies identically to `CMP-213 FuzzyList` in both SCR-102 and SCR-041:

1. Exact symbol prefix match (`"BTC"` -> `BTCUSDT` before `1000BONKUSDT`)
2. Base-asset prefix match (query matches the start of the base asset, e.g. `"eth"` -> `ETHUSDT`)
3. Substring match anywhere in symbol or base/quote asset name
4. Fuzzy (subsequence) match, scored by contiguous-run length then earliest match position

Within a tier, ties break by 24 h quote volume descending. Recents (last 10 opened, most-recent-first)
and favourites (alphabetical) are shown as separate labelled groups **above** the ranked results only
when the query is empty; once the user types, recents/favourites collapse into the single ranked list
(no separate group headers while filtering) so the ranking rule above is the only ordering signal a
user sees while typing.

## 3. Rendered result count and virtualisation (50 ms budget)

- Maximum rendered rows without virtualisation: **8** (SCR-041 popover) / **20** (SCR-102 modal).
- Virtualisation threshold: `CMP-213 FuzzyList` switches to windowed rendering above **50** matched
  items; the catalogue is capped client-side to the top 200 ranked matches before render regardless of
  how many rows technically match the fuzzy pass, so the 50 ms keystroke-to-paint budget is bounded by a
  constant-size DOM diff, not by the catalogue's ~600-symbol universe size.
- No network request occurs while typing in the common case (catalogue already loaded); this is a hard
  design constraint — no per-keystroke spinner in the typing path (`SCR-102`/`SCR-041` catalogue notes).

## 4. Three distinct empty-ish states (never conflated)

| State | Trigger | Copy | Next action |
|---|---|---|---|
| **Catalogue loading** | Instruments cache empty/refreshing on first start | "Loading instrument list…" with a determinate/indeterminate progress affordance, not a bare spinner over an empty list | none while loading; **Retry** button appears only if the refresh call fails, replacing the loading copy with "Couldn't load the instrument list. [ Retry ]" |
| **No matches** | Query matches zero USDT linear perpetuals | "No USDT perpetual matches '{query}' — v1 supports Bybit USDT linear perpetuals only." | Suggested next action: "Clear search" link (CMP-021) plus, in SCR-102 only, a link to SCR-104 Scanner if the catalogue is loaded (not a bare "No data") |
| **Filtered out by scope rule** | Query matches a non-USDT-perp instrument the catalogue still holds metadata for (e.g. a delisted/legacy symbol name) | "'{query}' matches an instrument outside v1's scope (USDT linear perpetuals only)." | No action offered beyond the same Clear-search link; this state is distinguished from "no matches" so support/QA can tell "nothing like this exists" apart from "this exists but is out of scope" |

`CMP-026 EmptyState` is used for all three, distinguished by its `variant` prop
(`catalogue-loading` / `catalogue-load-failed` / `no-matches` / `scope-filtered`); no state ever renders
an empty `CMP-213 FuzzyList` with zero rows and no explanatory copy above/below it.

## 5. Delisted symbol handling (edge case)

- A symbol whose exchange status is not `Trading` is never offered as a **new selection** target: it is
  excluded from ranked search results entirely (querying its name shows the scope-filtered state above,
  not a selectable row).
- It **does** appear, marked delisted, when it is already in **history** (recents) or **favourites**, or
  is the **symbol of an already-open chart** (SCR-041's current-value display). Treatment: `CMP-011 Tag /
  Chip` reading "Delisted" (struck-through symbol text, not colour alone — `05-accessibility-standard.md`
  non-colour-encoding rule), row is non-interactive for "open chart with new subscription" but remains
  clickable to view the existing/last-known chart in a read-only historical state; order-entry entry
  points (open ladder, add-to-watchlist trade actions) are absent from its row actions — only "View
  chart (historical)" and "Remove from favourites/recents" remain.
- **Precedence vs the stale/data-confidence marker (`E08-D01`/`E08-D04`):** `delisted` is the highest-
  precedence data-confidence state (`E08-D04` §3 precedence table: `delisted > disconnected >
  reconnecting > … > stale > live`). A delisted row therefore never additionally shows a `stale`
  freshness marker — the Delisted chip fully replaces it, per the "never stacked" rule. This is annotated
  directly on the `SCR-102/delisted-row` frame.

## 6. Keyboard map (both surfaces, single spec)

| Step | Key | Focus / visible state | Announcement |
|---|---|---|---|
| Open SCR-102 | `Ctrl+P` (global) | Modal opens, focus moves to the search input, previously focused element is recorded | "Symbol search" (dialog title, via `aria-labelledby`) |
| Open SCR-041 | Click/Enter on the chart header's symbol field, or its assigned hotkey | Popover opens anchored to the field, focus moves to the search input | "Symbol and interval switcher" |
| Type | any printable key | `aria-activedescendant` moves to the top-ranked result; matched substrings highlighted | Polite live region announces result count, debounced to one announcement per ~150 ms of typing (`CMP-048` contract) |
| Navigate results | `ArrowDown` / `ArrowUp` | Visible focus ring moves between rows (roving `aria-activedescendant`, not real DOM focus) | Each row's accessible name is read on move (symbol, base/quote, recording/delisted state) |
| Navigate groups (recents/favourites, empty-query only) | `ArrowDown`/`ArrowUp` crosses group boundaries seamlessly; groups are `role="group"` with `aria-label` | — | group label announced once on entry |
| Select | `Enter` | Row's default action fires (open chart); modal/popover closes, focus returns to the chart | "{Symbol} opened" not separately announced — the resulting chart symbol change is the confirmation |
| Per-result action | `Alt+ArrowRight` opens the row's action menu (add to watchlist, open ladder, view info); `Tab` also reaches an inline row-action button group | Action menu button gets visible focus | Menu items read by role |
| Switch symbol -> interval field (SCR-041 only) | `Tab` from symbol field | Focus moves to the interval field, which behaves as `CMP-220 IntervalPicker` | "Interval: {current}" |
| Close / cancel | `Esc` | Modal/popover closes | Focus **restored to the previously focused element** (SCR-102: the element focused before `Ctrl+P`; SCR-041: the chart header symbol field) — verified per Acceptance Criteria scenario 1 |

Every step above has a defined key, a visible focus treatment, and an announced change, satisfying the
"keyboard-only operation is fully specified" acceptance scenario end to end (open -> type -> navigate ->
select -> switch the focused chart's symbol -> Esc-and-restore).

## 7. Highlighting (non-colour-reliant)

Matched substrings render inside `<mark>` (per `CMP-213` contract) styled with **font-weight 600** (vs
600->400 non-matched) **and** `color.text.accent` on `color.surface.raised` — contrast-checked at
>=4.5:1 in all three themes (dark/light/hc), same verification path as `E08-D04` §2's
`verify_tokens.py`. Weight alone must remain legible if colour is stripped (verified visually in the
Penpot frame by a greyscale export note), satisfying "highlighting does not rely on colour".

## 8. Components used (all pre-catalogued; no new components introduced)

`CMP-048` Combobox/AutoComplete (base pattern) · `CMP-160` SymbolSearchInput (SCR-102's full-page field,
extends CMP-048) · `CMP-213` FuzzyList (ranked/grouped result list, shared by both surfaces) · `CMP-219`
SymbolPicker (SCR-041's compact in-chrome field) · `CMP-220` IntervalPicker (SCR-041's interval field) ·
`CMP-011` Tag/Chip (recording indicator, Delisted chip, not-recorded chip) · `CMP-026` EmptyState (all
three empty-ish states, per §4) · `CMP-021` Link ("Clear search", "View scanner" next actions).

Every component named in `18-traceability-matrix.md` rows for `US-MKT-001`/`US-MKT-002` and in the
ticket's Scope/Deliverables list is used above; none is listed as "explicitly not needed" — all eight are
consumed by at least one of the two frames.

## 9. Copy (content-reviewed)

- Scope reminder (no matches): *"No USDT perpetual matches '{query}' — v1 supports Bybit USDT linear
  perpetuals only."*
- Scope-filtered: *"'{query}' matches an instrument outside v1's scope (USDT linear perpetuals only)."*
- Delisted explanation (chip tooltip / row detail): *"Delisted by the exchange — no longer tradable.
  Shown because it's in your history/favourites or the currently open chart."*
- Catalogue loading: *"Loading instrument list…"*
- Catalogue refresh failed: *"Couldn't load the instrument list. [ Retry ]"*
- Not-recorded chip (existing, reused from `E08-D01`/recorder vocabulary): *"Not recorded"* with a
  "Record this symbol" owner-only action (SCR-041 catalogue note).

## 10. Security notes

Every result row renders **public instrument metadata only** (symbol, base/quote, 24 h change/volume,
recording/delisted status) — no account, position, key, or internal-endpoint data appears in any result
row, empty state, or error state, for any role (Owner/Manager see identical result content). The query
string is rendered exclusively through `CMP-213`'s structural `matchRanges` highlighting (index ranges
into the known symbol string), never as raw HTML built from the query — there is no code path where user
input is interpreted as markup, eliminating injection via the highlight renderer.
