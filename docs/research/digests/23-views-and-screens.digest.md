# Digest: 23-views-and-screens.md

Source: docs/research/23-views-and-screens.md — catalogue of 21 views/screens for CandleViewer (Bybit-based DeepCharts/DeepDOM parity). Global caveat: no Bybit L3/MBO feed → iceberg/stop/order-count footprints are heuristic proxies only; history depth = however long local recorder has run.

## Views 1–10 (Charting/Orderflow)

1. **Main Chart (Price+Footprint)** — candlestick/bar/line + Deep Print footprint overlay. Inputs: `kline` REST bootstrap, `kline.{interval}.{symbol}` WS, `publicTrade.{symbol}` WS→LOCAL footprint agg, `orderbook.50/200` WS (heuristic order-input only). Settings: chart type (Candle/Bar/Line/Equi-Vol/Delta-Vol); bar mode (Time/Volume/Tick/Range/Renko/P&F); footprint cell type (Volume/Bid-Ask/Delta/Delta+Total); display mode (Profile/Box); input source (Agg Trades/Num Trades, Order=heuristic); noise filter; diagonal-imbalance threshold default 300%; 24/7 session (no ETH/RTH); bar-close countdown. No direct TV equivalent (3rd-party only).
2. **Deep Stats Rows** — per-bar numeric summary, all LOCAL from publicTrade: Total Vol, Bid Vol, Ask Vol, Delta, Max/Min Delta, Delta%, Cumulative Delta, #Trades. Settings: row select/order, compact mode, color thresholds (e.g. delta%>60=strong), rolling-N sparkline. Maps to Deepchart "Deep Stats" strip.
3. **Profile Panel (Volume/Delta Profile+TPO)** — histogram of vol/delta by price. Inputs: publicTrade WS agg LOCAL by price bucket, bootstrapped from recorder tick history (kline REST fallback for older ranges w/o ticks). Settings: period type (Composite/Multiples/Visible/Personalized/Swing-anchored); input (Volume/Agg Trades/#Trades — no true Order input, no L3); Value Area % default 70%; row size; VWAP+σ overlay; single-print/LVN highlight toggle. Maps to Deep Profile; TV Volume Profile lacks delta-profile mode.
4. **Heatmap + DOM Ladder (DeepDOM analog)** — resting liquidity heatmap behind clickable ladder. Inputs: `orderbook.50/200/500` WS (historized LOCAL for trail), `tickers` WS (best bid/ask, mark), private `order`/`position` WS overlay. Settings: depth tiers (top N); color scale linear/log; trail/decay duration; cell size; Buy/Sell color convention (OPEN DECISION — DeepCharts docs inconsistent, CandleViewer must pick own); show/hide own orders; 1-click size preset. Interactions: click=limit order, Ctrl+click=market, drag marker=modify, Esc=cancel-all, +/-=zoom. TV DOM lacks heatmap-trail/iceberg-stop proxies.
5. **Big Trades/Bubbles (Time & Sales overlay)** — flags large prints. Inputs: publicTrade WS filtered LOCAL by notional threshold (absolute or percentile). Settings: size threshold, bubble scale (linear/log), color by side, tape row count, 2nd "whale" alert threshold, symbol/category filter. TV has no native bubble overlay.
6. **CVD/Delta Panes** — cumulative & per-bar delta subchart. Inputs: publicTrade WS LOCAL agg (delta=Σbuy−Σsell qty; CVD=running sum, resettable). Settings: reset anchor (session/day/never/manual); line vs histogram; divergence auto-marking (price HH vs CVD LH etc.); SMA/EMA smoothing. TV: community scripts only, no native pane.
7. **OI/Funding/Liquidation Panes** — derivatives context. OI: `tickers` WS (`openInterest`, linear/inverse only) + `/v5/market/open-interest` REST backfill (HYBRID). Funding: `tickers` WS (`fundingRate`,`nextFundingTime`) + `/v5/market/funding/history` REST (HYBRID). Liquidations: `allLiquidation.{symbol}` WS → LOCAL time-bucketed bars/heatmap; NO REST liquidation history endpoint exists — history capped by recorder uptime. Mark/Index/basis: `tickers` WS (`markPrice`,`indexPrice`). Settings: OI absolute vs Δ-per-bar, OI/price quadrant coloring; funding stepped-line vs bar, annualized toggle; liquidation bars(long/short split) or heatmap, notional threshold filter. No DeepCharts equivalent (futures-equities only); analogous to Coinglass/Hyblock — built natively.
8. **Speed of Tape** — trade velocity/acceleration gauge. Inputs: publicTrade WS LOCAL rolling window count+notional/sec; optional "instant" shorter-window variant. Settings: window length (1s/5s/30s), gauge vs strip-chart, alert threshold (prints/sec), split by side. Maps to Deepchart Speed of Tape / DeepDOM Book Speed.
9. **Imbalance Tracker** — flags stacked/diagonal bid-ask imbalance (absorption/continuation signal). Inputs: footprint cell data LOCAL + stacking rule (N consecutive cells at ratio). Settings: imbalance ratio threshold (e.g. 300%), stack depth (e.g. min 3), diagonal vs vertical mode, per-symbol/TF thresholds, alert on new stack. Maps to Deepchart Imbalance Tracker (Orderflow tier).
10. **Market Regime Panel** — classifies trending/ranging/volatile/calm. Inputs: LOCAL composite of book-thickness clustering (orderbook WS) + realized vol (ATR from kline) + tape speed (publicTrade WS) — heuristic, no true MBO regime signal. Settings: lookback window, sensitivity/thresholds, which sub-signals included, label vs gauge display. Maps to DeepDOM Market Regime; no TV equivalent.

## Views 11–21 (Layout/Trading/Ops)

11. **Multi-Chart Layouts** — simultaneous multi-TF/multi-symbol panes. Inputs: per-pane duplicate of View-1 feeds + LOCAL shared crosshair/level sync. Settings: grid presets (1x1/2x1/2x2/1+3/custom), per-pane symbol/TF binding, crosshair-sync, level-sync, independent vs linked scaling. Hotkeys: Ctrl+1..9 layout presets. TV multi-chart is direct UX precedent; DeepCharts compact/group mode unconfirmed (open Q7 from report 04).
12. **Replay Mode** — tick/bar-by-bar historical rehearsal. Inputs: recorder's own tick DB (trades+book deltas+liquidations) LOCAL-only — Bybit has no historical MBO/replay API; fidelity capped by recorder runtime. Settings: symbol+date/time range picker, playback speed 0.5x–100x presets+scrub, simulated-order/paper-fill toggle, choose which panes stay live during replay, loop/bookmark markers. Hotkeys: space=play/pause, ←/→=step bar, Shift+←/→=step tick, R=jump to real-time. DeepCharts' own Deep Replay/MBO Replay was "still in development" per report 05; TV bar replay is bar-level only.
13. **Trading Terminal/Order Ticket** — execution surface. Inputs: private WS (`order`,`execution`,`position`,`wallet`); REST `/v5/order/create`,`/order/amend`,`/order/cancel`,`/position/trading-stop`; `/v5/market/instruments-info` for tick/lot/leverage. Settings: default order type, qty presets (fixed/%-equity/risk-% calculator), TP/SL attach mode (ticks/%/R-multiple), 1-click trading toggle w/ confirm-off warning, hotkey size ladder, category/leverage selector. Hotkeys: B/S=buy/sell market, number keys=size presets, Ctrl+Enter=submit, Esc=cancel, global flatten-all+confirm.
14. **Positions & Orders** — consolidated cross-symbol/sub-account view. Inputs: private WS `position`/`order` per sub-account; REST `/v5/position/list`,`/v5/order/realtime` reconciliation. Settings: group-by (symbol/sub-acct/manager), show/hide closed-today, column set (uPnL, entry, mark, liq price, leverage, margin mode), sort, sub-account filter (owner-all vs manager-scoped). Visual: liq-proximity amber/red row warning.
15. **Risk Dashboard** — owner-level aggregate risk oversight w/ kill-switch. Inputs: LOCAL aggregation of private WS across all sub-accounts; `/v5/account/wallet-balance` REST periodic reconciliation. Settings: per-manager max-daily-loss/max-drawdown w/ auto-flatten-lockout, aggregate exposure caps (symbol/manager/portfolio), alert routing (push/email/in-app), owner-only lockout override. Feature: big "FREEZE" button per manager (immediate trading revoke). No DeepCharts/TV equivalent — CandleViewer-original, prop-firm risk-dashboard analog.
16. **Rule Builder (Custom Stops/Exits)** — no-code condition→action automation, extends Deep Pattern Builder concept to live order execution (not just visual flags). Inputs: any derived series (OHLCV, delta, CVD, OI, funding, regime, indicators) LOCAL; executes via same order path as View 13. Settings: condition editor (N inputs, AND/OR/NOT, comparison/math ops — mirrors DeepCharts' 4-input model per report 04 §18); action types (SL→breakeven, trail-by-N-ticks, partial-close%, time exit, full flatten); trigger mode (live-armed vs simulate-only); auto-backtest-on-save vs recorder history. UI: structured-form default (node-graph vs form is unconfirmed for DeepCharts — open question).
17. **Journal/Auto-Tracker** — automatic trade logging + post-session review. Inputs: private `execution` WS auto-logs every fill LOCAL; linked to Replay Mode via timestamp; manual tags/notes LOCAL. Settings: auto-tag rules (symbol/strategy/rule-source), review-period filters, stat set (win rate, expectancy, R-distribution, avg hold time), export CSV/PDF. Note: uncertain whether DeepCharts literally brands a feature "Auto-Tracker" (open question) — Journal spec is from project brief, not confirmed DeepCharts parity.
18. **Watchlist/Symbol Search** — symbol selection/screening entry point. Inputs: `/v5/market/instruments-info` REST (symbol list, tick/lot, category); `tickers.{symbol}` WS batch-subscribed for scanner columns (price/%chg/vol/funding/OI-Δ). Settings: column set, sort/filter rules, saved groups, category filter (spot/linear/inverse), fuzzy search. TV Watchlist = direct precedent; DeepCharts has none (futures/equities focus).
19. **Alerts** — condition-based notifications w/o constant screen-watching. Inputs: LOCAL evaluation against any live feed already consumed elsewhere; delivery in-app toast + optional push/email (external, outside Bybit scope). Settings: condition builder (reuses Rule Builder editor minus execution action), delivery channel, snooze/mute, one-shot vs recurring, per-symbol vs global. TV Alerts = direct precedent; DeepCharts has no strongly documented alert center.
20. **Account/Environment Switcher (Demo/Live)** — unambiguous demo↔live toggle. Inputs: REST/WS host selection (`api-demo.bybit.com` for demo vs mainnet market data host per report 08 §1.1); per-environment API key storage. Settings: active environment per session, per-sub-account environment binding, confirm-required toggle on switch to Live, distinct theme accent (live=red-accented chrome). Interaction: explicit typed/held confirm on Demo→Live; hotkey switching disabled (must be deliberate click). No DeepCharts/TV equivalent; broker sim/live toggle is closest precedent.
21. **Admin/Users** — owner-only manager/permission/API-key/audit management. Inputs: CandleViewer LOCAL user/auth store mapped to Bybit sub-account IDs; Bybit `create_sub_uid` + API key mgmt endpoints invoked via owner's Main-account creds. Settings: add/remove manager (bounded by Bybit's 5/20 sub-account cap — must surface cap in UI), per-manager permission scope (read-only vs full trading), risk-limit assignment (feeds View 15), API key rotation/IP-whitelist, audit log viewer. No DeepCharts/TV equivalent — prop-firm back-office analog.

## Cross-cutting notes
- Single configurable global hotkey layer should span all views (not per-view schemes) — flagged as design requirement, not yet detailed.
- Demo/Live isolation (View 20) must gate every trading-capable view (13 Terminal, 14 Positions/Orders, 4 DOM click-to-trade, 16 Rule Builder "Arm Live") — no live order placement while badge=Demo, and vice versa.
- Heuristic-vs-true-MBO labeling required: Views 1, 4, 9, 10 (iceberg/stop-run/order-count footprint) must show visible "(estimated)" badge in-UI, not just in docs.
- Recorder dependency: Views 3 (Profile), 12 (Replay), 17 (Journal), and any Composite/long-lookback mode of Views 6–10 are only as deep as local recorder has run — empty/partial-history states must be explicitly designed.

## Numeric limits/defaults
- Diagonal-imbalance threshold default: 300% (Views 1, 9).
- Value Area %: default 70% (View 3).
- Imbalance stack depth default: min 3 consecutive levels (View 9).
- Replay playback speed range: 0.5x–100x (View 12).
- Sub-account cap: 5 (regular tier) / 20 (upper tier) managers (View 21).
- Orderbook depth WS tiers: 50/200/500 (View 4); kline WS/REST + orderbook.50/200 for View 1.
