## 1. #220 — the recursive unknown-key check, run against our catalogue (`e0_build.py`)

This is the round-11 fix with the most direct bearing on the contracts, because #216 only ever looked at the root dict: a typo *inside* a state built a clean machine with a missing action and no warning under every strict setting.

**Verdict on our five contracts: clean at every level.** All five build under `strict_config=True` with zero findings, so nothing in B6–B10 was silently dropping an entry action or a transition at `c78ce99`.

The control is positive, not merely an absence. For each contract the script plants one typo at a *nested* site and requires a refusal:

| planted | example finding |
|---|---|
| state key (`entyr` for `entry`) | `position_protection.sl.attaching: 'entyr' (did you mean 'entry'?)` |
| transition key (`actionss`) | `position_protection.sl.flat on['POSITION_OPENED']: 'actionss' (did you mean 'actions'?)` |
| invoke key (`srcc`) | `position_protection.sl.attaching invoke[att]: 'srcc' (did you mean 'src'?)` |

15/15 refused, path-named, identical in both lanes. At `c78ce99` **every one of these fifteen built silently.** For B8 the state-key case is the one that matters commercially: a mistyped `entry` on `sl.attaching` means the stop-loss attach action never runs while the chart still reports `protected`.

**Harness note that is itself a finding about the fix.** The check is strict enough to catch the *test harness*: an `"_overlay"` marker key added to an overlay config was refused. The documented escape hatch works — renaming it `"x-overlay"` is accepted at every level, as the changelog claims. **CV constraint:** any house metadata we hang on catalogue JSON must use the `x-` prefix (or `meta`/`description`/`tags`), and our schema lint should enforce that.

## 4. Round-11 obligations on contract shapes (`e6_round11.py`, 8/8 × 2 lanes)

### #218 — a `raise(delay=)` heartbeat releases its clock handle

Overlay on B6 and B10 (a 1 ms ping-pong, the shape #212 legalised), polled to 200+ beats:

| chart | beats | **peak live clock handles** | `last_error` | `chain_trips` |
|---|---|---|---|---|
| B6 `twap` | 201 | **1** | None | 0 |
| B10 `alert` | 201 | **1** | None | 0 |

Identical in both lanes. Before #218 this list grew by one dead handle per beat for the life of the heartbeat — a slow leak with no error and no visible symptom, in exactly the self-paced pacer shape #212 had just made legal. A TWAP or alert-retry pacer running for a session at 100 ms would have accumulated hundreds of thousands of dead handles. **This is the round-11 fix with the most prospective value for B6–B10**, on the same footing as #213 last round: it does not touch the shipped JSON (which carries no timers) but it gates the pacers the OMS will add.

### #219 — reentrant `send(wait=True)`, and the audit of our stubs

**The library behaviour is confirmed and is the good one.** A true `async def` action installed on B10's `persist_fired_row` that awaits `interpreter.send("ACK", wait=True)` raises **`ReentrantWaitError`** — promptly, not after the 8 s watchdog. At `c78ce99` this shape deadlocked the run loop.

**The audit the mandate asks for: no catalogue action does this.** Two independent checks:

1. **Static.** No `"wait"` or `"sendTo"` key appears anywhere in B6–B10 JSON. Our contracts never specify an action as awaiting a receipt.
2. **By construction.** Every catalogue action in B6–B10 is a *pure* context/side-effect action — `bump_slices_done`, `persist_fired_row`, `record_child`, `apply_catch_up`, and the rest. None is specified to drive the machine; the charts move on `invoke` results and external events.

**So #219 is a no-op for our contracts — no our-contract change is required.** It is, however, a change worth writing into our house rules before the real implementations are authored, because the shape it now refuses is a natural one to reach for: "record the row, then acknowledge." **CV constraint:** an action must never await `send(..., wait=True)` on its own interpreter. Where an action genuinely must observe the downstream step, hand out the receipt (`asyncio.ensure_future(i.send(..., wait=True))`) and await it *outside* the step — which the fix explicitly still permits. Lint for an awaited `.send(` with `wait=True` inside any registered action.

### #221 — restore → re-persist without `start()`

Overlay on B6 `armed` arming `raise(SLICE_DUE, delay=5000, id="pacer")`. Advance 1 s, snapshot, restore with `minimum_version=3`, and re-persist **without calling `start()`**:

```json
orig        [{"kind":"event","type":"SLICE_DUE","payload":{},"remaining_ms":4000.0,"send_id":"pacer"}]
repersisted [{"kind":"event","type":"SLICE_DUE","payload":{},"remaining_ms":4000.0,"send_id":"pacer"}]
```

Byte-identical, both lanes. This is the journal-compaction / blob-migration path: a job that loads and rewrites snapshots without running them. At `c78ce99` that job silently dropped every armed deadline it touched, so a compaction pass over parked TWAPs would have produced a set of algos that restore permanently unpaced — the #213 failure re-introduced by an operational tool rather than by the engine. **CV constraint:** our migration/compaction tooling must round-trip `scheduled_sends`, and non-shrinkage of that list should be asserted as a job invariant.

### #222 — a chain trip is sticky

B10 with `maxIterations: 4` and a self-raising `SPIN`:

| observation | value |
|---|---|
| `chain_trips` after the storm | **1** |
| `last_chain_error` after one benign handled event (`DISABLE`) | **still latched** (`RunawayChainError`) |
| `last_error` at that moment | `None` (per-step read, as documented) |
| `on_chain_budget_exceeded` firings | **1** — exactly one per trip |
| after `clear_chain_error()` | latch `None`, `chain_trips` **still 1** |

Both lanes. This is the difference between "the alert machine discarded work at 09:41" and no record at all: post-#212 a heartbeat guarantees a benign event arrives and, at `c78ce99`, erased the only evidence. **CV constraint:** journal `chain_trips` as a monotonic counter and alert on any increment; read `last_chain_error` for the detail and call `clear_chain_error()` only from an explicit operator acknowledgement, never from the event loop.

### C-07b (B18 `kill_switch`, sha1 `4e9e8a9b60be`) — OUR-CONTRACT, Blocker

```
async def : denied RELEASE -> status='error' (UnhandledEventError);
            authorised RELEASE returns ok, final=['kill_switch.engaged'], bricked: true
def       : identical
```

Unchanged, both kinds. This is documented opt-in policy (`onUnhandled: "error"` plus #170: a guard-denied event *is* unhandled) meeting a chart with no unguarded fall-through — so the first denied `RELEASE` errors the interpreter and the subsequently *authorised* `RELEASE` can never land. A kill switch that cannot be released is the worst failure mode this machine has. **The round-6 Amendment-6 removal still has not landed in the JSON.** Config-only fix: an ordered unguarded `RELEASE` fall-through arm that audits the denial as a no-op.

Note the interaction with D3 above: under the catalogued `onUnhandled: "error"` the B18 halt is attributable to the *contract* (dispositions are `errored`, never `chain_budget`), and under `defer` the same drive completes with 0 dropped. The library is not the constraint here; we are.

### New CV constraints from this round

1. House metadata on catalogue JSON must use the `x-` prefix (or `meta` / `description` / `tags`) — #220 now refuses anything else, at every level. Add to schema lint.
2. No registered action may await `send(..., wait=True)` on its own interpreter (#219). Hand out the receipt and await it outside the step. Add to lint.
3. Journal `chain_trips`; alert on increment; call `clear_chain_error()` only on operator acknowledgement (#222).
4. Snapshot migration / compaction tooling must round-trip `scheduled_sends` and assert non-shrinkage (#221).
5. Carried forward and re-confirmed: pin `minimum_version=3` on every restore; never register a user action whose name collides with a built-in; built-in action parameters must nest under `params` (`{"type":"raise","params":{"event":…,"delay":…}}`) — the flat spelling is refused with a clear message, which cost one harness iteration here and would cost a chart author the same.
