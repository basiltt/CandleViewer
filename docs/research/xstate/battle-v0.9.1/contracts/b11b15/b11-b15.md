## 2. Shutdown recipe (#239) + restore hook (#240): `h1_shutdown_recipe.py`

For each of B11–B15: reach steady state. Then, **without yielding to the run
loop**, enqueue 5 inbox events (`seq` 0–4), 3 `send_priority(wait=False)`
events (5–7) and one `send(wait=True)` (99). Then `drain_pending()` → persist →
`stop()` → `from_snapshot(..., minimum_version=3, plugins=[stub])` → `start()`,
and replay the drained events.

| Check (×5 machines × 2 lanes) | Result |
|---|---|
| drained order `[5,6,7,0,1,2,3,4,99]`: priority lane first, then inbox | ✅ 10/10 |
| drained ∪ processed-before = all 9 events, disjoint | ✅ 10/10 |
| the `wait=True` receipt resolves with `error=InterpreterStoppedError` (no hang) | ✅ 10/10 |
| `on_interpreter_start` on boot: `restored_from_snapshot=False` | ✅ 10/10 |
| `on_interpreter_start` on restore via `plugins=`: fires **once**, `True` | ✅ 10/10 |
| restored configuration == pre-shutdown configuration | ✅ 10/10 |
| replay: every drained event delivered **exactly once** | ✅ 10/10 |
| `chain_trips == 0`, `dropped_receipts == 0`, no `on_error`, status running | ✅ 20/20 (pre + post) |

API note for our wrapper (not a defect): the drained `wait=True` receipt
**resolves** to `Receipt(changed=False, error=InterpreterStoppedError)`. It does
not raise. CHANGELOG says "failed with", which matches how `Receipt.error` is
used elsewhere. Our shutdown code has to check `receipt.error`.
