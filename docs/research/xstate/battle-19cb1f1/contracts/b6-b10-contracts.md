First, the JSON question. In `battle-f28719c/contracts/`, `B16.machine.json` is **byte-identical** to `B16.catalogue.json` (sha1 `9d8ad9937417`), and `B18.machine.json` to `B18.catalogue.json` (sha1 `4e9e8a9b60be`). So there is no "later contracts pass" to have fixed them.

Repro: `g9_c04_c07b.py` (standalone, charts inlined, exits 1 while either Blocker is present). 6 / 6 rows **PRESENT** in both lanes.

### C-04 (OUR CONTRACT, Blocker) — elevation outlives the session

`session` is a parallel chart; the `elevation` region handles only `STEP_UP_OK`, `STEP_UP_FAILED`, `ELEVATION_DEADLINE` and `REVOKE`. `LOGOUT`, `IDLE_DEADLINE` and `ABSOLUTE_DEADLINE` revoke `auth` and are **not handled in `elevation` at all**:

| drive | configuration after | `elevated_until` |
|---|---|---|
| `MFA_OK → STEP_UP_OK → LOGOUT` | `{auth: revoked, elevation: elevated}` | `9999999` |
| `… → IDLE_DEADLINE` | `{auth: revoked, elevation: elevated}` | `9999999` |
| `… → ABSOLUTE_DEADLINE` | `{auth: revoked, elevation: elevated}` | `9999999` |
| `MFA_OK → REVOKE → STEP_UP_OK` | `{auth: revoked, elevation: **elevated**}` | `9999999` |

The last row is the sharper one: elevation is **acquirable after revocation**. `auth.revoked` is `type: "final"`, but a final state in one region does not stop a sibling region from taking a transition, so `STEP_UP_OK` still elevates a dead session.

**This is ours, not the library's.** The engine implements parallel-region semantics correctly; the chart simply never tells `elevation` that the session ended. **Fix in the JSON:** add `LOGOUT` / `IDLE_DEADLINE` / `ABSOLUTE_DEADLINE` (or a single `SESSION_ENDED`) to `elevation.elevated` targeting `normal` with `clear_elevated`, and gate `normal`'s `STEP_UP_OK` on a guard that reads `auth` — or, cleaner, hoist elevation under `auth.active` so revocation exits it structurally.

### C-07b (OUR CONTRACT, Blocker) — a guard-denied `RELEASE` bricks the kill switch

B18 as catalogued sets `onUnhandled: "error"`, and `engaged`'s only `RELEASE` transition carries `guard: owner_and_elevated`. When the guard denies, no transition is selected, the event is *unhandled*, and the policy halts the machine:

| engine | status after a denied `RELEASE` | `last_error` | value |
|---|---|---|---|
| async `Interpreter` | `error` | `UnhandledEventError` | `engaged` |
| `SyncInterpreter` | `error` | `UnhandledEventError` | `engaged` |

A *wrong button press* — the right operator without elevation, or the wrong operator — permanently destroys the only path out of a trading halt. Nothing can be released afterwards; the interpreter drops every subsequent event (`Interpreter 'kill_switch' is error; dropping event 'RELEASE'`). This is also what masks the priority-preemption measurement on the unmodified machine.

**Also ours.** `docs/plan/28-statechart-catalogue.md` already records the decision — "`onUnhandled: "error"` … **no longer B18**" — but the JSON still says `"error"`. **Fix:** remove `onUnhandled: "error"` from B18 (leaving the machine default / `defer`), or add an explicit denied-release transition on `engaged` with the negated guard, targeting itself with an `audit_release_denied` action. The second is better: it makes the denial auditable instead of silent.

**Verdict on both:** carried, unchanged, **Blockers on any runtime**. They gate B16 and B18, not B6–B10, and they are contract edits — no library change and no wrapper is required for either.
