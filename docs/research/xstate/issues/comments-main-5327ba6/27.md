Verified on main @ 5327ba6 (pre-0.8.1). `actionErrorPolicy: "continue"|"rollback"|"fail"` ships as specified: `"rollback"` restores context and the pre-transition state, withdraws self-`raise`d events (new since 0.8.0, documented as unable to undo `sendTo`), and skips the context checkpoint on no-action transitions (reproduced ~0.998x of baseline on an idle rollback machine, vs. the previously-reported 0.776x); `"fail"` stops the interpreter with `status == "error"` and an `interpreter.error` (`TransitionFailedError`) whose `__cause__` is the original exception; the default `"continue"` reproduces 0.7.0 behaviour byte-for-byte and additionally fires `on_transition_failed` and sets `last_transition_ok = False`; `PluginBase.on_transition_failed` has a no-op default so 0.7.0-style plugins still load; the same policy is honoured on `start()`'s initial-entry path; the default-flip `DeprecationWarning` uses a process-wide latch. Two literal-wording deviations noted for the record (not blockers): the unknown-policy rejection raises `InvalidConfigError` rather than `ValueError`, and `failed_actions` is surfaced via the new `on_transition_failed` hook + `last_transition_ok` rather than as an extra argument on `on_transition` itself. **Disposition: close**, with a follow-up suggested (not blocking) to add an explicit `SyncInterpreter`-side re-verification of the same criteria and a fresh-subprocess check of the once-per-process warning latch.

## Ride-along finding — F-7 (Medium): the checkpoint-skip predicate does not model `always` / `on` action lists

The new "skip the context checkpoint when the transition runs no actions"
optimisation is a real and welcome win (reproduced at 0.9978×–1.056× of
baseline on an idle `rollback` machine, versus the 0.776× before it). One note
for the record, because it is a behaviour change that the CHANGELOG lists only
as a performance improvement:

The skip predicate asks whether the transition, the exited states and the
entered subtree declare any action. It does **not** model an `always`
transition on the *target* whose own action list will run as part of the same
macrostep. Verified *safe* in the case tested (`repro/f_rollback_gap.py`), but
the predicate is narrower than the invariant it has to uphold, so the safety is
incidental rather than structural.

Suggest a targeted test pinning that a transition into a state with an
`always` (or `on`) action list still checkpoints, before this optimisation
becomes load-bearing.

## Ride-along note — rollback cost in the release notes

"≈ 0.98× of the default" is measured on transitions that declare **no actions
at all**. Measured on an otherwise identical two-state machine on this commit:
0.949× with no actions, **0.878× with actions**; and `bench_j_policies.py`'s
50 000-event burst gives armed `rollback` at **0.854×** and
`rollback_and_defer` at **0.774×**. All of these are defensible numbers; only
one is in the CHANGELOG. Suggest qualifying the claim with "on transitions that
run no actions", so nobody budgets capacity from it.
