Verified on main @ 5327ba6 (pre-0.8.1). `WrongThreadError`'s message is corrected as specified: it names the `asyncio.run_coroutine_threadsafe(interp.send(...), loop)` idiom explicitly, states that it is also rejected since 0.8.0 (not just the bare `send()` call), and points the caller to `send_threadsafe()`. Confirmed both forms raise `WrongThreadError` immediately on the calling thread, `send_threadsafe()` reliably delivers 200/200 cross-thread events, and the "Changed in 0.8.0" behavioural break is documented in both the CHANGELOG and the interpreters guide's new "Sending from Another Thread" section. The original LC-43 repro's own harness is now stale (it assumed silent data loss with no exception; it now crashes on the very first send with the *correct* `WrongThreadError`) — recommend updating that script to `pytest.raises(WrongThreadError)` rather than measuring delivery counts, but this is a test-script follow-up, not a library defect. **Disposition: close.**
