Verified on main @ 5327ba6 (pre-0.8.1). This is **FIXED**.

`send_threadsafe()` now runs the same `_check_strict()` guardrail as
`send()` (`interpreter.py:897`), on the calling thread, before
`run_coroutine_threadsafe` schedules anything — an unknown event type
raises `UnknownEventError` and a schema-rejected payload raises
`InvalidEventPayloadError`, both from a foreign thread, with nothing
queued or processed. Static `raise` targets are now validated at
`create_machine()` time on `strict` machines
(`validation.py:_collect_unknown_raises`), with a `difflib`-based "Did you
mean" suggestion; a dynamic (callable) `raise` target is left alone at
build time (as it must be) and is still checked at runtime via the same
`_check_strict` call used for external sends.

Verified with a new standalone script covering all of the above (10/10
assertions pass, exit 0). The `strict` feature itself remains an opt-in
(`strict=False` default, unchanged 0.7.x silent-no-op behaviour), which is
correct per the issue's own stated backwards-compatibility plan.
