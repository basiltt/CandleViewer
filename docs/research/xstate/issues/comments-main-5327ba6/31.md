## Ride-along finding — F-10 (Low): `_SIBLING_FALLBACKS_WARNED` is an unbounded module-global

The once-per-`(source, target)`-pair throttle is the right design and is
verified working. The set backing it (`resolver.py::_SIBLING_FALLBACKS_WARNED`)
is a module-global keyed on `(source.id, target)` that is never trimmed, so a
long-lived process that builds many machines accumulates one entry per distinct
pair, forever. Small, but it is unbounded growth keyed on user data. A bounded
`lru_cache` or a per-machine set would close it without changing the observable
throttling behaviour.
