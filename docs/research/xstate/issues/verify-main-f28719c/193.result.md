# #193 — def-service executor handoff moved into the engine-held task

**Classification: FIXED-OPT-IN**

## Summary
The proposed fix option (a) was taken: the executor handoff for a plain
`def` service now happens inside a task the engine holds (`_settle()`,
registered with `task_manager`), so a state exit — via rollback or an
`always` roll-forward — cancels that task *before* the callable is ever
submitted to the executor, exactly like a coroutine service's task is
never started. This closes the specific, named defect: an abandoned `def`
service's result landing in a state the machine already left
(`cursor=4242` in the original repro).

"FIXED-OPT-IN" rather than plain FIXED because criterion 1
(`test_invoke_is_cancelled_on_state_exit`) as literally worded implies a
`CANCEL` sent *while the service is running* pre-empts it on **both**
spellings; the library's own resolution — and its own regression test
(`test_stale_completion_never_lands_in_exited_state`) — explicitly keeps
`def`'s documented, pre-existing contract that the entering *step* awaits
the service before the next event (including `CANCEL`) is even processed
(#116/#149 parity with `SyncInterpreter`), so a `def` service already
mid-flight when `CANCEL` arrives finishes and its `onDone` still applies
inside the state that invoked it — it is *not* cancelled mid-run. Only
*arming* (a service not yet submitted, when the transition that armed it
is unwound) is unwound. This is an explicit, documented scope narrowing in
the CHANGELOG ("The cancellation half of the report is the documented
plain-`def` contract on both engines") — not silent, but it means
criterion 1's literal "CANCEL delivered while running" case does not
change behaviour for `def` (only `async def` is interruptible there).

## Residual

Criterion 1, read literally as "CANCEL pre-empts a running `def` service
same as `async def`", is **not** fixed and is not going to be — the fix
instead formalized the pre-existing #116/#149 in-step-await contract for
`def` and scoped #193 to arming-time cancellation (rollback / roll-forward
before submission), which criteria 2 and 3 fully cover. Anyone depending on
mid-run cancellation of a `def` service must still make it `async def` or
offload cancellation cooperatively — this is now explicit in the
`start()`-adjacent docs and `production-characteristics.md`, not a gap left
undocumented.
