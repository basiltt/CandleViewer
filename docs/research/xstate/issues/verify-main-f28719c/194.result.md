## Acceptance criteria (from CHANGELOG #194, reopened #181)

1. Bound is per child, not aggregate over N children (async def): confirmed
   — 1 and 5 children with 0.5s each entry settle in ~0.51s concurrently,
   not 5×0.5s serially.
2. Tight `children_timeout` bounds `start()` near the timeout for `async def`
   children regardless of N: confirmed (0.21s/0.20s vs 0.2s timeout, both n=1
   and n=5).
3. WARNING always fires on overrun, including the previously-silent `def`
   (non-yielding) case: confirmed — `warned=True` in all 4 overrun rows,
   including both `def` cells that previously suppressed the WARNING
   together with the timeout failure (original repro
   `post-6db65d8/new/repro/R8-03_children_timeout_def_noop.py` showed
   `warning_logged: true` too on the current `f28719c` — re-run below).
4. Documented residual limitation: a non-yielding plain-`def` entry action
   still cannot be pre-empted mid-execution (single OS thread, no `await`
   point) — `start()` still blocks for the full child duration in that case.
   This is explicitly documented (interpreter.py:2872-2891, docs) as *not* a
   promise the bound can keep; the fix here is that this case is no longer
   silent (WARNING fires) and no longer under-reports (`overrun_factor`
   correctly reflects reality). The changelog entry states this outcome
   exactly ("the WARNING fires whenever the allowance was exceeded,
   including the single-threaded case a bound cannot pre-empt — which the
   docs now state").

## Original repro re-run on f28719c

`post-6db65d8/new/repro/R8-03_children_timeout_def_noop.py` → **exit 1**
(still reports `result: FAIL`) because it asserts `bounded=True` even for the
plain-`def` non-preemptable case — i.e. it pins the OLD, stronger (and
undeliverable-on-CPython) expectation that `def` bring-ups are also bounded
in wall-clock time. That expectation was explicitly retracted by the fix:
the CHANGELOG and the source now document that a non-yielding `def` entry
action cannot be pre-empted on the event-loop thread. The three real
defects the issue reported — no-op bound for `async def` (false: confirmed
bounded), aggregate-not-per-child scaling (false: confirmed per-child), and
suppressed WARNING (false: WARNING now always fires) — are all fixed. The
repro's own `bounded` field conflates two different things: "the bound was
honored" vs. "the WARNING correctly reports an overrun on the
non-preemptable case," and only the former was ever promised to be
unconditional; the latter promise (never silent) is what's fixed.

Verbatim tail of re-run:
```
{
  "entry_kind": "def", "children": 1, "child_entry_seconds": 3.0,
  "children_timeout": 0.2, "start_seconds": 3.02, "bounded": false,
  "overrun_factor": 15.1, "warning_logged": true
}
```
`warning_logged: true` on both `def` rows (previously `false`/suppressed) —
this is the actual regression target of #194 and it is fixed.

## Residual

None beyond the documented, intentional single-thread pre-emption limit for
non-yielding `def` entry actions (stated in source comments and docs).
