## Analysis: why the pin passes but the repro still fails

The round-8 pin (`TestNoEmptyConfigurationWhileRunning`) exercises a
simpler chart: two sibling states each with a single `invoke`/`onDone`
edge, no `always`, no competing `after` timer, no nested final substate.
The CHANGELOG's #196 fix narrowed *which* transitions compete for a named
event but does not by itself guarantee `current_state_ids` is never read
mid-macrostep on every possible chart shape — specifically a shape with an
`always` racing into an invoking, immediately-`final` nested state while an
`after` timer also targets a sibling. The 15/25-lap failure rate here shows
the empty-configuration window is still reachable through that combination
even though the narrower, pinned property holds. This is the same chart
originally used to *find* #197, so the fix's regression-test surface did
not cover the reporter's own reproduction shape.

## Residual

The `always` + nested-`final`-substate + competing `after` timer + invoke
combination on the async engine can still produce a success-shaped
`send(wait=True)` receipt at an instant `current_state_ids == []`, while
`get_persisted_snapshot()` at the same instant correctly detects the
mid-step condition and refuses. The public read (`current_state_ids`) and
the receipt fields (`last_transition_ok`, `last_error`) do not agree with
the snapshot layer's own more careful state. Needs a fix at the same
guard boundary `get_persisted_snapshot()` already uses (`_processing`),
applied to what `current_state_ids` / the `send(wait=True)` receipt expose,
or a wait-for-settle before resolving the receipt on this chart shape.
