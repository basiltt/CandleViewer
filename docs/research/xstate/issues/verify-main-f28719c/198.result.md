## Acceptance criteria (from gh issue #198)
Agreement check between `configuration` and `state_ids` on restore was
one-sided (`snapshot.get("configuration") or snapshot["state_ids"]`),
letting an emptied/absent field silently "lose" instead of being treated
as disagreement. Criteria verified:
1. `version >= 1` running snapshot with `state_ids` emptied, `configuration`
   intact -> must be REFUSED.
2. `version >= 1` running snapshot with `configuration` dropped, `state_ids`
   intact -> must be REFUSED.
3. A genuine, untampered `version >= 1` snapshot round-trips (no false
   positive).
4. A legacy v0 payload (`state_ids` only, no `configuration`/`version`)
   still accepted.

## Fix location
`src/xstate_statemachine/persistence.py::check_shape()`, lines 216-242:
adds a `versioned = version >= 1` branch that, for a `status == "running"`
snapshot, fails with `SnapshotCorruptError` if `configuration` is `None`,
empty, or `state_ids` (leaves) is empty — closing exactly the one-sided gap.
`base_interpreter.py:1683` calls `check_shape(..., version=version)` before
`restore_ids = snapshot.get("configuration") or snapshot["state_ids"]`
(line 1725) ever runs, so the vulnerable `or` is now unreachable for a
tampered versioned payload.
