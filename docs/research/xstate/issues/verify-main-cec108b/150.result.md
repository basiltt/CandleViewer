## Analysis

The fix (`internal` parameter on `send_threadsafe`, per CHANGELOG #150 entry
and `interpreter.py:1046-1090` docstring) works correctly and is verified:
passing `internal=True` explicitly, or inheriting the action's `contextvars`
context (`contextvars.copy_context().run(i.send_threadsafe, ...)`), correctly
classifies the send as internal and it is budgeted identically to the direct
`await i.send()` route (21 vs 21), tripping `RunawayChainError` with
`last_transition_ok=False`.

However, the **default** call —`i.send_threadsafe("T")` with no `internal=`
argument, from a plain `threading.Thread` started inside an action — is
**still classified as external and unbudgeted** (60 executions, no error).
This is the CHANGELOG's own documented caveat: *"a plain `threading.Thread`
should pass `internal=True`"* — i.e. the fix is opt-in, not automatic. The
original issue's repro and its own summary ("The documented hand-off-to-a-
worker pattern is therefore the one route on which `maxIterations` is
unenforceable") describe exactly the **default-argument** case as the
defect, and that case is unchanged: a caller who does not know to pass
`internal=True` still gets an unbounded self-feed.

The pinned test `tests/test_round5_findings.py::TestThreadsafeSelfSendBudgeted`
only exercises the `flag` (`internal=True`) and `ctx` (context-inheriting)
modes — it does not test the plain-default-argument case that the original
repro (and the issue title) describe, so its passing does not contradict this
finding.

Docs: `docs/_guide/interpreters.md` "Sending from Another Thread" section
documents `send_threadsafe()`'s validation and `WrongThreadError` behaviour
but does **not** mention the `internal` parameter, its default classification
behaviour, or the action-spawned-thread caveat at all (`grep -n "internal="
docs/_guide/interpreters.md` → no matches). Acceptance criterion 5 (docs)
is unmet.

## Fix location

`src/xstate_statemachine/interpreter.py:1046` (`send_threadsafe` signature
and docstring) — `internal: Optional[bool] = None` parameter added;
classification defers to `_issued_from_own_action()` (a `ContextVar` read)
when `internal is None`, which is `None`/false for a plain `threading.Thread`
per Python's context-inheritance rules (pre-3.14, or 3.14 without
`thread_inherit_context`).

## Residual

The **default**, no-argument `send_threadsafe()` call from a plain
`threading.Thread` spawned inside an action — the case the original issue
reproduces and titles the defect after — remains unbudgeted and can still
starve `maxIterations` silently. The fix requires the caller to opt in via
`internal=True` or manual context propagation; nothing changes the default
behaviour a caller gets by just calling `send_threadsafe("T")` the way the
existing docs (pre- and post-fix) show it. Docs do not warn about this
opt-in requirement.
