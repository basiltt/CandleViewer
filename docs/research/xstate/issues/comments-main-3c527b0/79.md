Re-verified on `main` @ `3c527b0`. The wildcard/`onUnhandled`/`strict`
exemption is now decided by provenance (`Event.system`, `is_system_event()`,
`ENGINE_EVENT_TYPES = (DoneEvent, ErrorEvent, AfterEvent)`) rather than by
name prefix:

- a user-sent `done.review` is now matched by `"*"` and by `"done.*"`,
  trips `onUnhandled: "error"` when unhandled, and is rejected by `strict`
  when undeclared — all previously false negatives;
- the case-variant `DONE.review` is likewise treated as ordinary user
  traffic;
- engine-minted `done.invoke.*` / `after.*` remain fully exempt (checked a
  `strict` machine with both `invoke`/`onDone` and `after` declared —
  no false "unhandled", no interference);
- `escalate` still works unchanged, still delivers `ErrorEvent` to the
  parent's `onError`;
- `Event.system` cannot be set from the public `send()` API (no such
  parameter), so a user cannot spoof engine provenance;
- `SYSTEM_EVENT_PREFIXES` is kept and still importable (used now only as a
  build-time `strict`/`raise` validation fallback and for docs);
- the build-time reserved-namespace warning introduced earlier in the
  0.8.1 cycle no longer fires — correctly withdrawn now that its premise
  (name-based exemption) no longer holds.

The predecessor repro (`new-0.8.0/repro/N-08_error-done-namespace-invisible.py`,
originally filed as N-8 and folded into this issue) also now exits 0.

**Disposition: close as fixed.** All 10 acceptance criteria pass; no
regression to the 0.8.0 `escalate` / `onUnhandled` behaviour.
