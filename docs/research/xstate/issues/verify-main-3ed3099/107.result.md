## Original repro

`docs/research/xstate/issues/post-5e07ba8/new/repro/R4-11_priority_lane_not_persisted.py`
still **exits 1** as written — but this is a test-harness artifact of the
repro script, not a persisting defect. The script cancels the run-loop task
to simulate a crash, which the interpreter's cancellation handler correctly
flips to `i.status = "error"` (a *separate*, intentional fix — CHANGELOG:
"an externally cancelled run loop flips `status` to `error` ... instead of
leaving a dead machine reporting `running`", #114). The repro never resets
`i.status` back to `"running"` afterward (unlike the pinned regression test
`TestPriorityLanePersisted`, which explicitly does
`i.status = "running"` before pumping the clock). Because `RealClock`/
`SimulatedClock`'s fired-timer callback (`_fire` in
`interpreter.py:_deliver`) checks `if self.status != "running": return`
before delivering into the priority lane, the repro's timer callback bails
out early and the priority queue stays empty — reproducing the *absence* of
an event to snapshot, not the *original* defect (the lane being excluded
from the snapshot logic itself).

Re-running the identical scenario with the one-line `i.status = "running"`
reset (matching the pinned test's setup) shows the underlying defect is
fixed:

```
priority_queue: ['after.1000.lanes.waiting']
snapshot pending: ['after.1000.lanes.waiting']
restored states: ['lanes.expired'] fired: 1
```

i.e. once the timer is actually allowed to fire into the priority lane, it
is present in the snapshot and survives restore — the #107 defect is gone.
The repro's own exit-1 status reflects an assumption (that `pump()` still
delivers after an unresetted `status="error"`) that the codebase now
correctly refuses by design (#114), not the #107 regression itself.

## Residual

None found for #107 itself. Recommend the original repro script be updated
upstream to reset `i.status = "running"` after the simulated-cancellation
step, to avoid conflating the (fixed, and intentional) #114 status-normalization
behavior with the #107 persistence behavior it is meant to isolate.
