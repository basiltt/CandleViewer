## Residual

None as a functional defect. The check runs per-evaluation rather than at
build time (item 2's stated fallback, explicitly acceptable per the issue),
so an ambiguous `stateIn` guard that is never actually exercised at runtime
(e.g. a dead branch) will not be caught until/unless it fires — a minor gap
vs. the build-time-preferred option, not a correctness bug. Named test files
(`tests/test_state_in_guard.py::*`) don't exist verbatim; coverage exists
under `tests/test_round4_findings.py` instead.
