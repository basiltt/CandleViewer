**Note:** this script pre-dates the new API — it never passes
`restart_timers=` and checks `has_dormant_invocations`
(services)/`pending_invocations()`, not `has_dormant_timers` (timers,
introduced by this fix). `restart_services=True` alone does re-arm timers
too, per the fix's design ("the static default is documented... `restart_timers`
defaults to the `restart_services` choice so 'bring it all back' is one
flag" — `base_interpreter.py:1433-1434`), so on inspection the
`restart_services=False` branch is *expected* to leave the timer dormant
(matches observed) and is not itself a failure signal for this repro.

## Verbatim output — new verification script

`docs/research/xstate/issues/verify-main-3ed3099/128_after_timer_rearm.py`
(exercises: re-arm + dormancy flip, no-restart dormancy signal, and a
deadline whose wall-clock value had already passed before the snapshot was
taken):

```
  restart_timers=True: dormant_before_start=True dormant_after_start=False mid=['timeout_demo.waiting']/False final=['timeout_demo.expired']/True
  no restart: dormant=True status=running states=['timeout_demo.waiting']
  elapsed-before-restore: states=['timeout_demo.expired'] fired=True
crit_rearm_and_dormancy: PASS
crit_dormant_without_restart: PASS
crit_elapsed_before_restore_fires_promptly: PASS
RESULT: PASS
```

- `crit_rearm_and_dormancy`: confirms `has_dormant_timers` is `True` before
  `start()` on a restored snapshot, flips to `False` once `restart_timers=True`
  re-arms it, and the re-armed timer restarts from a full fresh delay (not
  preserving the pre-snapshot elapsed time) — matching the documented
  SCXML `<send delay>` restart-from-zero contract.
- `crit_dormant_without_restart`: confirms `has_dormant_timers` stays
  `True` and `status` remains `"running"` (documented as not a liveness
  signal) when timers are not restarted — the deadline never fires.
- `crit_elapsed_before_restore_fires_promptly`: confirms a deadline whose
  wall-clock value had already elapsed by snapshot time still fires
  promptly (within one fresh delay window) after restore with
  `restart_timers=True`, rather than never firing or requiring a second
  stacked delay.
