## Residual — criterion 3 / 5 not met

The issue's criterion 3 is about a "v1-style record with no
`scheduled_for`/`fired_at` keys." Two distinct cases exist:

1. **True v1 record** (no `"kind"` key at all, only `{"type": "after.500"}`):
   `restore_event` derives `kind` from the event-name shape
   (`ENGINE_EVENT_SHAPES`), which maps an `"after."`-prefixed name to
   `kind = "system"`, **not** `kind = "after"` (only the explicit
   `record.get("kind")` value ever produces an `AfterEvent`). So a true v1
   record restores as a plain `Event`/`system_event`, which has no
   `scheduled_for`/`fired_at` attributes at all — it does not "restore them
   as `0.0`" because there is no `AfterEvent` object in that path to begin
   with. This is arguably a *stronger* form of "not a false on-time claim"
   than the criterion literally asks for, since there is no lateness field
   present to misreport, but it does not match the criterion's literal
   wording ("restores them as `None`").

2. **v2 `"after"`-kind record that is itself missing the keys**
   (`{"kind": "after", "type": "after.500"}`, e.g. hand-written or from a
   hypothetical future writer that omits them): `restore_event` still
   defaults via `float(record.get("scheduled_for", 0.0))` →
   **`0.0`, not `None`** — the exact false-on-time defect the issue
   describes, still present for this specific shape. `float(None)` would
   raise, so a literal `None` default was never wired in; the fallback
   value is unconditionally `0.0`.

In practice, every `"after"`-kind record this library itself ever writes
(post-fix) always carries both keys, so this residual is not reachable via
the persist→restore path in this codebase — only via a hand-crafted or
third-party-written record. `tests/test_round4_findings.py` does not test
this missing-keys-on-a-v2-record case at all (no
`test_after_event_missing_lateness_fields_restore_as_none` test exists, nor
an equivalent). Criterion 3's plain-English intent (do not affirmatively
claim "on time" when the info isn't there) is satisfied for the
library-generated v1/v2 paths that actually occur, but not for the exact
byte-for-byte case named in the criterion.

## Overall

The primary defect — real lateness telemetry silently reset to `0.0` on
every persist→restore round-trip that this library performs in practice —
is fixed (criteria 1, 2, 6, and the equivalent of 4 all pass). The literal
"restores as `None`, not `0.0`" guarantee for a hand-crafted/malformed
`"after"`-kind record missing the keys (criterion 3) is not implemented,
and no dedicated test (criterion 5) exists for it. Classified PARTIAL.
