## Fix location

- `src/xstate_statemachine/events.py:239-269` — the identity sentinel `_ENGINE_MARK` was replaced with a dedicated `_EngineMark` singleton class implementing:
  - `__deepcopy__(self, memo)` → returns `self` (line ~259), so `copy.deepcopy` no longer reconstructs a new object.
  - `__reduce__(self)` → returns the string `"_ENGINE_MARK"`, which pickle resolves as the module attribute on unpickling (line ~265-266), so a pickle round-trip reproduces the *same* singleton rather than a new `object()`.
  - `_ENGINE_MARK: Any = _EngineMark()` (line 269) is the single instance used everywhere `is_system_event`/`system_event` compare against.
- `is_system_event` (`events.py:282`) unchanged in logic — still an `is` identity check — but now correctly holds across `deepcopy`/`pickle` because the sentinel itself preserves its identity through both protocols.
- `tests/test_round4_findings.py:1294-1298` — `test_provenance_survives_deepcopy_and_pickle` asserts `is_system_event` is `True` after `deepcopy` and pickle round-trip of a system event, and explicitly asserts `is_system_event(copy.deepcopy(Event("T")))` is `False` for a plain user event (anti-forgery check, matching the issue's "a plain user `Event.__reduce__` never sets that flag" requirement).
