## Residual

**Confirmed defect persists on `SyncInterpreter`.** The fix was applied only
to the async engine's `_execute_transition`/target-resolution path; the sync
engine's equivalent code path (which raises the same `StateNotFoundError`
under `strict_targets=False`) was never wired to call `_report_resolve_error`
or otherwise dispatch `on_resolve_error`. Since the library's stated design
principle throughout round 4 is engine parity, and the *original repro*
specifically exercises `SyncInterpreter`, this is a genuine residual gap,
not a stale-repro issue — the repro is testing exactly the engine that
remains broken. Recommend re-filing/reopening against `SyncInterpreter`
specifically.
