## Fix location

`src/xstate_statemachine/base_interpreter.py:3000-3016` (`ESCALATE` action branch):

```python
declared = self.id
if self.parent is not None and declared.startswith(self.parent.id + ":"):
    declared = declared[len(self.parent.id) + 1 :].split(":")[0]
escalate_event = ErrorEvent(
    type=f"xstate.error.actor.{self.id}", error=err, src=declared
)
```

`src` is now stripped down to the declared invoke id (`"kid"`) so it matches
`_collect_eligible_transitions`'s `event.src == inv.id` check. `type` still
carries the runtime id (unchanged, so a literal `on: {"xstate.error.actor.<runtime>": ...}` still works).

## Residual

None found. The declared-id stripping logic (`declared.startswith(self.parent.id + ":")`)
assumes the runtime id is always `parent.id + ":" + declared_id[:optional suffix]`;
this matches the actor-id construction scheme used throughout the codebase and is
exercised correctly here. The wildcard `"*"` handler still does not see the escalate
event (by design — it is a system/error event, consistent with #97/#98's provenance
model), which is expected behaviour and not a defect per this issue's scope.
