# #99 verify — main@3ed3099

**Title:** `SyncInterpreter` never delivers `onError` for a failed invoked
child machine; the parent parks in the invoking state

## Classification: FIXED

## Criteria table

| # | Criterion | Result |
|---|---|---|
| 1 | Sync: parent with `onError` handler transitions to it when the invoked child machine fails | ✅ |
| 2 | Async: same scenario, for parity | ✅ |
| 3 | Sync: parent with **no** `onError` handler — unhandled child failure fails the parent (`status="error"`, `error` set) instead of parking forever at `status="running"`, `error=None` | ✅ |
| 4 | Async: same scenario, for parity (CHANGELOG: *"an unhandled invoked-child failure fails the parent on both (#99)"*) | ✅ |

## Fix location

`src/xstate_statemachine/sync_interpreter.py:1218-1235` — `#99` comment:
*"a child that ENDED IN ERROR must satisfy `onError`, not..."*; on
`child.status == "error"` it now synthesises and delivers an `ErrorEvent`
to the parent (`onError` handler if declared; otherwise via the same
unhandled-failure path that fails the parent, matching the async engine's
`_deliver_invoked_completion` for `status == "error"`).
