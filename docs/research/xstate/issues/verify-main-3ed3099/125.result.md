- **Async engine (`Interpreter`)**: fixed. `ARM`'s receipt correctly reports
  `['m_defer_replay.b']` (its own transition only); `LATE`'s replay happens
  afterward as its own macrostep and reaches `c`.
- **Sync engine (`SyncInterpreter`)**: **not fixed**. `send("ARM", wait=True)`
  still returns a `Receipt` reporting `m_defer_replay.c` — the post-replay
  state — identical to the pre-fix defect.

## Root cause of the residual gap

- Fix location (async only): `src/xstate_statemachine/interpreter.py:1432-1440`
  ("📨 #125: replay deferred events as their OWN macrosteps") and
  `:1521-1537` ("🏛️ #125: replay is NOT folded into this event's macrostep
  any more"). `_resolve_receipt` for the triggering event
  (`interpreter.py:1431`) is called *before* `_replay_pending` is checked
  and the deferred events are re-queued for a later macrostep
  (`interpreter.py:1436-1440`).
- `SyncInterpreter.send()` (`src/xstate_statemachine/sync_interpreter.py:507-541`)
  has no equivalent split. It appends the event, calls
  `self._process_event_queue()` (which drains the *entire* queue including
  any deferred events re-queued at the head via `extendleft` at
  `sync_interpreter.py:809-818`), and only after the full drain builds the
  `Receipt` from `self.current_state_ids` (`sync_interpreter.py:534-541`).
  There is no per-macrostep receipt boundary on this engine — a deferred
  replay triggered mid-drain still lands inside the same `send()` call's
  Receipt.

## Residual

The fix is engine-asymmetric: correct on `Interpreter` (async), not applied
to `SyncInterpreter`. The new regression test
(`TestReplayIsItsOwnMacrostep`) only covers the async engine, so this gap is
untested and the original repro (which targets the sync engine) still fails
by design intent of the fix, not because it "assumes superseded behaviour."
Any caller relying on `SyncInterpreter.send(..., wait=True)` for
per-event audit attribution is still exposed to the original defect.
