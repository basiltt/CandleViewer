## Original repro

`docs/research/xstate/issues/post-5e07ba8/new/repro/R4-12_always_root_target_empties_configuration.py`
now exits 1 on `create_machine()` itself (raises `InvalidConfigError` at
line 39, before the repro's own runtime assertions execute) — this is the
expected new behavior: the repro was written to observe the runtime symptom
(empty configuration) of a defect that is now caught earlier, at build time,
so the machine is never built at all. The repro's non-zero exit code here
reflects an uncaught `InvalidConfigError` propagating out of the script
(it does not `try/except` around `create_machine`), not a persisting defect
— the intended defensive behavior (rejecting the bad config) is exactly what
fires.

## Residual

None found. The class of "typo target resolves to the machine root" configs
described in the issue (both `always` and `on`) is now rejected uniformly at
build time with an actionable message, and non-root targets are unaffected.
