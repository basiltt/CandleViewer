CHANGELOG claim for #114: "a hook raising `asyncio.CancelledError` is contained like any other failure, and an externally cancelled run loop flips `status` to `error` and fails pending receipts instead of leaving a dead machine reporting `running`" — confirmed.

## Fix location

- `src/xstate_statemachine/interpreter.py:1446-1471` — the `except asyncio.CancelledError:` handler in the run-loop: if `self.status == "running"` when a `CancelledError` reaches this level, it calls `self._die(RuntimeError(...))` to publish the failure (rather than silently leaving `status` as `"running"`), while deliberately not touching `status` unconditionally (to avoid clobbering an orderly `stop()`'s own transition).
- Plugin-hook containment (`_SafePlugin`, referenced at interpreter.py:1452) intercepts a hook-raised `CancelledError` before it reaches the run-loop's own `except asyncio.CancelledError`, so a hook-manufactured cancellation never kills the loop; it is instead reported via `on_plugin_error`/`last_plugin_error`.
- `_die()` (interpreter.py ~899-1128) calls `_fail_all_receipts()` on the failure path, so a pending/subsequent `wait=True` receipt is failed rather than hung.
