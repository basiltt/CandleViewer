## Result: FIXED

`drain_pending()` returns `[priority..., inbox...]` in priority-first order on every chart we tried. A `wait=True` receipt on a drained event now resolves with `error=InterpreterStoppedError('drained: ...')` and `changed=False`, so the waiter no longer hangs. A full drain → persist → stop → restore → start → replay round-trip replays each event exactly once.

Optional follow-up, not blocking: if the caller drains *without* stopping, the machine keeps running, but the receipt error still says "stopped". A dedicated `EventDrainedError(InterpreterStoppedError)` subclass would let callers tell the two cases apart.
