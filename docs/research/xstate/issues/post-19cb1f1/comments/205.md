# Comment for issue #205 — `from_snapshot(minimum_version=, expected_machine_hash=)`

**Action:** comment + **close**
**Disposition:** **FIXED — verified, closing**

---

Verified on `main` @ `19cb1f1` (PR #211, commit `4dbf86e`; unreleased 0.8.1).
Build identified **by commit** — `__version__` still reports `0.8.0`. Both
parameters refuse an untrusted payload on **both** engines:

- `minimum_version` → `SnapshotVersionError` with a `.minimum` attribute on a
  version-0 downgrade;
- `expected_machine_hash` → `SnapshotDriftError` on mismatch **or absence**,
  regardless of the payload's own version.

The second half — "regardless of version" — is the part that matters and it
holds: **the payload can no longer select its own level of checking.**

The docstring, API reference and snapshot guide all now state the trust boundary
explicitly ("a fingerprint against accidental drift, not a MAC"). We had asked
for the word "checksum"; "fingerprint, not a MAC/authentication" is semantically
equivalent and arguably clearer, since it names what it is *not*. Accepted.

Verify script: `205_snapshot_authenticity.py`, all criteria met.

**One residual, filed separately, not blocking this close:** the restore path
re-enqueues via `_enqueue_restored` → `_put_inbox`, which bypasses the
`_check_strict` call at the `send()` call site (`base_interpreter.py:1767`). So
a restored `done.invoke.q` or a restored undeclared `BOGUS` is accepted under
`strict:True` (`onUnhandled:"error"` does still catch both). That contradicts
the restore contract documented at `events.py:403-414`, and it is the delivery
mechanism for the migration problem we filed against #203.

Worth stating plainly for anyone reading this issue as a security control: we
tested the claim rather than accepting it, and **a hand-edited snapshot with no
event forgery at all** restores a machine to an arbitrary state with arbitrary
context. `machine_hash` being a fingerprint rather than a MAC is therefore the
correct and honest description — but it means **the only real boundary is
signing the whole snapshot**, and the docs should say so in as many words rather
than leaving the reader to infer it from "not a MAC". We do this in our own
envelope (HMAC tag over the whole blob, verified before `from_snapshot`) and
recommend the docs recommend it.

Closing.
