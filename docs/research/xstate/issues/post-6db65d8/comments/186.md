# Comment for issue #186 — `configuration` outranks `state_ids` on restore

**Action:** **reopen, narrowed**
**Disposition:** **FIXED for contradiction; the rule is ONE-SIDED**

---

Verified on `main` @ `6db65d8` (merge of PR #191, `fix/0.8.1-round7`; unreleased
0.8.1) as part of our adoption audit (#26). Build identified **by commit** —
`__version__` still reports `0.8.0` on this tree. CPython 3.13.7, Windows 11,
fresh venv. Every claim below was reproduced in a clean process before it was
written down, and **every service-bearing check was run with both `def` and
`async def` services**.

**Fixed for the case it was filed against.** Contradictory `configuration` /
`state_ids` are refused as `SnapshotCorruptError`, and agreeing or absent-field cases
still restore normally with no over-refusal.

**Reopening narrowly: the agreement rule short-circuits when either field is empty.**
The unmet criterion is `state_ids` (leaves) must be a subset of `configuration`
(ancestor closure) whenever `configuration` is present — but the guard is written as
`if configuration is not None: ... if leaves and not full: fail(...)`, so emptying
`state_ids` (rather than contradicting it) lets a forged `configuration` relocate the
machine — the check never runs, so there is nothing to contradict. The same holds
symmetrically for an emptied `configuration`. Since the attacker-or-corrupt input in
the original report is the *same input* that can empty a list, the fix is bypassed by
a strictly simpler mutation than the one it refuses. Filed separately as **R8-08**.

This looks like an `and` that should be an `or`, or an emptiness pre-check before the
agreement test: an empty field on a `version >= 1` payload should be treated as
disagreement, not as "no opinion".

Thank you — round-8 scorecard and the full write-up are in #26.
