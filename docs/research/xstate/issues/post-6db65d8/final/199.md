## Summary

`get_persisted_snapshot()` called from inside the `on_interpreter_start`
plugin hook returns a **torn** blob — `status: "running"` with an **empty**
`state_ids`/`configuration` — on both the async `Interpreter` and the
`SyncInterpreter`. #182 correctly closed the *initial-descent* window (the
in-flight guard now covers the whole `start()` descent, so a snapshot from
an entry action or `on_action_execute` is refused). `on_interpreter_start`
fires a few lines *before* that guard is set, so it sits just outside the
window #182 established and produces exactly the torn shape #182 was filed
to prevent.

## Environment

- Commit: `6db65d8` (unreleased 0.8.1, merges #191)
- Python: 3.13.7 (also reproduces on the CI-pinned interpreter)
- OS: Windows 11 Pro 10.0.26200
- Install: editable (`pip install -e .`) against the `main` branch worktree

## Minimal reproduction

```python
"""R8-09 STANDALONE: `get_persisted_snapshot()` called from the
`on_interpreter_start` plugin hook returns a TORN blob -- `status:
"running"` with an EMPTY configuration -- on both engines.

#182 made the initial descent a guarded macrostep: `_processing`
(async)/`_is_processing` (sync) is set True before `_enter_states(...)`
runs, so a snapshot taken from an entry action or `on_action_execute` is
refused with `SnapshotMidStepError`. `on_interpreter_start` fires a few
lines EARLIER -- `status` has already been flipped to "running" but the
guard flag is not yet set and no state has been entered -- so the hook is
one step outside that window and the blob it can request is accepted, torn.

Source (interpreter.py, async engine):
    self.status = "running"
    ...
    for plugin in self._plugins:
        plugin.on_interpreter_start(self)   # <- guard not set yet
    ...
    self._processing = True
    await self._enter_states([self.machine], init_event)
Same shape in sync_interpreter.py: `on_interpreter_start` runs, THEN
`self._is_processing = True` is set for `_enter_states(...)`.

Exits 1 while any row from the hook reports `status=="running"` with an
empty `state_ids`/`configuration`; exits 0 once the hook is brought inside
the same in-flight window.
"""
import asyncio
import json

from xstate_statemachine import (
    Interpreter,
    MachineLogic,
    PluginBase,
    SyncInterpreter,
    create_machine,
)
from xstate_statemachine.exceptions import SnapshotMidStepError

CFG = {
    "id": "r3b",
    "initial": "a",
    "context": {"n": 0},
    "states": {
        "a": {"entry": ["bump"], "invoke": {"src": "s", "onDone": {"target": "b"}}},
        "b": {},
    },
}


def bump(i, c, e, a):
    c["n"] = c.get("n", 0) + 1


def make_service(kind):
    def svc(i, ctx, e):
        return {"v": 1}

    async def asvc(i, ctx, e):
        return {"v": 1}

    return svc if kind == "def" else asvc


class Recorder(PluginBase):
    def __init__(self):
        self.rows = []

    def on_interpreter_start(self, i):
        try:
            self.rows.append(("returned", i.get_persisted_snapshot()))
        except SnapshotMidStepError as e:
            self.rows.append(("refused", str(e)[:60]))


def mk(kind):
    return create_machine(
        CFG, logic=MachineLogic(actions={"bump": bump}, services={"s": make_service(kind)})
    )


async def one(kind, engine):
    p = Recorder()
    if engine == "async":
        i = Interpreter(mk(kind)).use(p)
        await asyncio.wait_for(i.start(), 10)
        live = i.get_persisted_snapshot()
        await i.stop()
    else:
        i = SyncInterpreter(mk(kind)).use(p)
        i.start()
        live = i.get_persisted_snapshot()
        i.stop()
    disp, blob = p.rows[0]
    row = {
        "engine": engine,
        "kind": kind,
        "disposition": disp,
        "status": blob.get("status") if disp == "returned" else None,
        "state_ids": blob.get("state_ids") if disp == "returned" else None,
        "configuration": blob.get("configuration") if disp == "returned" else None,
        "healthy_state_ids": live.get("state_ids"),
    }
    if disp == "returned":
        try:
            r = (
                Interpreter.from_snapshot(mk(kind), blob)
                if engine == "async"
                else SyncInterpreter.from_snapshot(mk(kind), blob)
            )
            row["restore"] = "ACCEPTED"
            row["restored_state_ids"] = sorted(getattr(r, "current_state_ids", []))
            row["restored_status"] = r.status
        except Exception as exc:
            row["restore"] = f"refused:{type(exc).__name__}"
    return row


async def main():
    rows = [await one(k, "async") for k in ("def", "async def")]
    rows.append(await one("def", "sync"))
    bad = [
        r
        for r in rows
        if r["disposition"] == "returned" and r["status"] == "running" and not r["state_ids"]
    ]
    result = "FAIL" if bad else "PASS"
    out = {"result": result, "rows": rows, "torn": bad}
    print(json.dumps(out, indent=2, default=str))
    print(f"OBSERVED: {len(bad)}/{len(rows)} rows torn ({result})")
    print(
        "EXPECTED: 0 -- get_persisted_snapshot() from on_interpreter_start must "
        "either refuse (SnapshotMidStepError) or return a settled, non-empty "
        "configuration, matching the #182 in-flight window"
    )
    return 1 if bad else 0


raise SystemExit(asyncio.run(main()))
```

## Observed behaviour

Fresh run at `6db65d8`, `PYTHONIOENCODING=utf-8 PYTHONUTF8=1`:

```
OBSERVED: 3/3 rows torn (FAIL)
EXPECTED: 0 -- get_persisted_snapshot() from on_interpreter_start must
either refuse (SnapshotMidStepError) or return a settled, non-empty
configuration, matching the #182 in-flight window
```
Exit code: `1`.

All 3 rows (async engine × `def` service, async engine × `async def`
service, sync engine × `def` service) show `disposition: "returned"`,
`status: "running"`, `state_ids: []`, `configuration: []`, while the same
interpreter's `get_persisted_snapshot()` taken immediately after `start()`
returns (`healthy_state_ids`) is non-empty (`["r3b.a"]` for the async
engine, `["r3b.b"]` for the sync engine, which settles the `onDone`
transition synchronously with a `def` service). The torn blob also fails to
restore: `from_snapshot(...)` raises `AttributeError` in all 3 rows, so the
blob is not merely torn but unusable for its stated purpose.

## Expected behaviour

Per #182 (CHANGELOG): the in-flight guard must cover "the whole `start()`
descent", so that `get_persisted_snapshot()` called from *any* hook that
fires during that descent either raises `SnapshotMidStepError` (per
`base_interpreter.py`'s `_step_in_flight()` contract, documented on
`get_persisted_snapshot()`: "raises `SnapshotMidStepError` if a macrostep is
in flight") or, if allowed to return at all, returns a settled,
non-empty configuration — never a `status: "running"` blob with zero
active states.

## Root cause analysis

Async engine, `interpreter.py:557-566`:

```python
self.status = "running"
self._bind_loop()
self._event_loop_task = self._spawn_run_loop()

try:
    for plugin in self._plugins:
        plugin.on_interpreter_start(self)      # <- guard not set yet
    ...
    self._processing = True                     # <- #182's guard, set AFTER
    await self._enter_states([self.machine], init_event)
```

Sync engine, `sync_interpreter.py:340-378`, same shape:

```python
self.status = "running"
...
for plugin in plugins:
    plugin.on_interpreter_start(self)            # <- guard not set yet
...
self._is_processing = True                       # <- #182's guard, set AFTER
try:
    self._drive(self._enter_states([self.machine]))
finally:
    self._is_processing = False
```

`_step_in_flight()` (`base_interpreter.py:1304`) reads `_processing` /
`_is_processing`; both are `False` at the moment `on_interpreter_start`
runs on both engines, because `status` is flipped to `"running"` *before*
the plugin loop, and the guard is set *after* it, immediately ahead of
`_enter_states(...)`. #182's comment in `interpreter.py` even documents the
intent ("the initial descent IS a macrostep... the flag is cleared in the
`finally` below") but the plugin-notification loop that precedes
`_enter_states` is not inside that guarded region, so `on_interpreter_start`
is the one caller left outside the window #182 established.

## Impact

**General:** low blast radius in isolation (a torn blob's `AttributeError`
on restore is at least loud), but a sharp edge for anything that treats
`get_persisted_snapshot()` as safe to call from any lifecycle hook — which
`on_interpreter_start` invites, since "persist on startup" is a natural
pattern for an audit or recovery plugin.

**Order-management scenario:** a plugin that persists an audit trail entry
on every interpreter start for an order machine would silently write a
blob describing a "running" order with no active state, and discover the
defect only later, when something tries to restore from it and gets an
opaque `AttributeError` instead of the expected order state. Our own
wrapper avoids this only via a specific, undocumented-to-upstream rule
("never snapshot before the post-start settle") that we maintain
*because* of this hook's behaviour.

## Proposed fix

Extend #182's guarded region to cover the plugin-notification loop that
calls `on_interpreter_start`, on both engines: set `_processing` /
`_is_processing` to `True` before that loop (immediately after
`status = "running"`), not just before `_enter_states(...)`. This makes
`_step_in_flight()` return `True` for the duration of `on_interpreter_start`
on both engines, so `get_persisted_snapshot()` called from that hook raises
`SnapshotMidStepError` exactly as it already does from `on_action_execute`
and from an entry action.
