## Summary

`DoneEvent` and `AfterEvent` are publicly exported, publicly documented `NamedTuple`s with
no provenance field. `is_system_event` (`events.py:272`) returns `True` for them on a bare
`isinstance` check, so they are exempt from `strict` and `onUnhandled` — any caller can
construct one and drive a real `onDone` transition while the genuine service is still
running. The same trust extends to `restore_event()`: an attacker-authored snapshot record
reconstitutes a trusted `DoneEvent` with no integrity check, and that object then drives
`onDone` on a live machine — a wire vector, not only in-process misuse.

import asyncio
import json
import os
import sys
import threading

from xstate_statemachine import Interpreter, MachineLogic, create_machine
from xstate_statemachine.clock import SimulatedClock
from xstate_statemachine.events import AfterEvent, DoneEvent, restore_event, is_system_event

FAIL: list[str] = []

SPEC = {
    "id": "sec",
    "initial": "a",
    "strict": True,
    "onUnhandled": "error",
    "states": {
        "a": {
            "invoke": [{"id": "k", "src": "svc", "onDone": {"target": "done_", "actions": ["stash"]}}],
        },
        "done_": {},
    },
}


def build(kind: str):
    def svc_def(i, c, e):  # noqa: ANN001
        import time
        time.sleep(30)  # never completes within this probe's lifetime

    async def svc_async(i, c, e):  # noqa: ANN001
        await asyncio.sleep(30)

    def stash(i, c, e, a):  # noqa: ANN001
        c["got"] = getattr(e, "data", None)

    return create_machine(
        json.loads(json.dumps(SPEC)),
        logic=MachineLogic(
            services={"svc": svc_def if kind == "def" else svc_async},
            actions={"stash": stash},
        ),
    )

    """Hand-built DoneEvent is exempt from strict/onUnhandled; async drives onDone."""
    for kind in ("def", "async"):
        i = Interpreter(build(kind), clock=SimulatedClock())
        await i.start(children_timeout=0.2)
        await asyncio.sleep(0.02)
        before = sorted(i.current_state_ids)
        forged = DoneEvent(type="done.invoke.k", data={"forged": True}, src="k")
        try:
            await i.send(forged)

        await asyncio.sleep(0.05)
        after = sorted(i.current_state_ids)
        moved = after != before

        if moved:
            FAIL.append(f"check1/{kind}: forged DoneEvent drove onDone ({before}->{after})")
        elif i.status == "running":
            FAIL.append(f"check1/{kind}: forged DoneEvent exempt from strict/onUnhandled")
        await i.stop()
    d, a = DoneEvent(type="done.invoke.k", data={}, src="k"), AfterEvent(type="after.1.x")
    if is_system_event(d) or is_system_event(a):
        print("  [check1/surface] DoneEvent/AfterEvent pass isinstance-only is_system_event()")

    rec = {"kind": "done", "type": "done.invoke.k", "data": {"forged": True, "px": 9e9}, "src": "k"}

    print(f"  [check2] restored={ev!r} is_system_event={is_system_event(ev)}")

        await i.start(children_timeout=0.5)
        await asyncio.sleep(0.05)
        before = sorted(i.current_state_ids)
        await i.send(ev)
        await asyncio.sleep(0.2)
        after = sorted(i.current_state_ids)
        got = i.context.get("got")
        print(f"  [check2/{kind:<5}] before={before} after={after} ctx.got={got}")
        if after != before:
            FAIL.append(f"check2/{kind}: snapshot-forged DoneEvent drove onDone, ctx.got={got}")
        await i.stop()

On the `async` engine, the forged in-process `DoneEvent` **and** the one reconstituted from
an attacker-authored record both drive `['sec.a'] -> ['sec.done_']` while the real service
is still sleeping for 30s. On the `def` engine the forgery is not immunity but a second
failure mode: `strict`/`onUnhandled: "error"` do not fire, so the forged event is silently
accepted and swallowed with no transition and no error signal.

## Expected behaviour

The documented invariant at `docs/api/index.md:1193` is "provenance, not name": events are
supposed to be validated by an authorship marker, not merely by matching `type` string.
`Event` implements this — it carries the `#85` provenance sentinel checked by
`_issued_from_own_action()`/`is_system_event`. `DoneEvent` and `AfterEvent`, whose entire
purpose is to assert engine authorship of a completion, are documented and exported
(`__all__`) with the same expectation but no such field exists to check. XState v5 binds
`onDone` to the child actor's own lifecycle (an invoked actor only reports its own
completion); this port instead matches on name plus `event.src == inv.id`
(`base_interpreter.py:4484`) with no liveness check on the invocation, which is what lets a
forgery — in-process or restored from a snapshot record — land against a still-running
service.

## Root cause analysis

- `events.py:272` — `is_system_event(event)` does a bare
  `isinstance(event, ENGINE_EVENT_TYPES)` check. `DoneEvent`/`AfterEvent` are plain
  `NamedTuple`s with no `.system`/`._provenance` attribute (confirmed via the repro's surface
  check), so any externally constructed instance of the right type passes.
- `base_interpreter.py:4484` — the invoke-completion match,
  `if isinstance(event, (DoneEvent, ErrorEvent))`, checks only `event.src == inv.id`. There is
  no check that invocation `inv.id` is still outstanding, so a `DoneEvent` for a real (but
  still-running) or even nonexistent invocation is accepted as a completion.
- `events.py:392` — `restore_event()` reconstitutes a `DoneEvent` from a plain dict
  (`{"kind": "done", "type": ..., "data": ..., "src": ...}`) with no signature or integrity
  check over the record, and the result is `is_system_event() == True` — fully trusted.

## Impact

**General.** Any code path that can inject an event into a running interpreter — a
malformed persisted snapshot with attacker-controlled `pending_events`, a misbehaving
plugin, or a bug elsewhere in the caller's own event-construction code — can forge a
`done.invoke.<id>` and drive a transition and its `onDone` actions with attacker-chosen
`data`, bypassing `strict`/`onUnhandled` entirely.

**Order-management scenario.** A forged `done.invoke.<fill-service>` commits a fabricated
fill price and quantity into context via the `onDone` action while the real venue call is
still outstanding — the repro demonstrates exactly this shape (`ctx.got={'forged': True,
'px': 9000000000.0}`). Under `def` services, `strict` also fails as a detection control at
the same time, so there is no compensating alarm.

## Proposed fix

Three independent fixes, each useful on its own:

1. Give `DoneEvent`/`AfterEvent` a private provenance field set only by the engine at
   construction time, and make `is_system_event` read that field instead of doing a bare
   `isinstance` check.
2. Add a liveness check at `base_interpreter.py:4484`: a `done.invoke.<id>` should only match
   if `<id>` names an invocation that is currently outstanding on the interpreter.
3. Strip (or refuse to restore) completion-kind records in `pending_events` on
   `restore_event()`/snapshot load, or bring `pending_events` under the same integrity check
   already applied to the rest of the snapshot blob.

## Acceptance criteria

- `test_doneevent_forgery_rejected[def]` / `test_doneevent_forgery_rejected[async]` —
  constructing a `DoneEvent`/`AfterEvent` naming a live invocation and sending it at a
  `strict`/`onUnhandled: "error"` machine either raises/enters the error state (does not
  silently swallow) or fails validation before matching a transition; the invoking child's
  `onDone` is never reached while its real service is still outstanding.
- `test_doneevent_forgery_no_liveness_bypass` — a `DoneEvent(type="done.invoke.<id>")` for an
  invocation that is not currently outstanding on the interpreter does not drive its `onDone`.
- `test_restore_event_rejects_forged_done_event` — `restore_event()` given an
  attacker-authored `{"kind": "done", ...}` record either fails integrity validation or
  produces an event that is not treated as `is_system_event() == True`.
- All tests parametrised over both `def` and `async def` service kinds and, where
  applicable, both `Interpreter` and `SyncInterpreter`.
- `repro/R8-05_doneevent_forgery.py` exits `0` once fixed.
