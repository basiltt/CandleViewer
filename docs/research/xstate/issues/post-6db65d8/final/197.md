## Summary

`await send(EV, wait=True)` can resolve at an instant when `current_state_ids == []`, with a
success-shaped receipt: `ok=True`, `err=None`, `status="running"`. The window is transient
(it heals within roughly 500ms), but at that instant `get_persisted_snapshot()` correctly
refuses with `SnapshotMidStepError` — the library knows it is mid-step — while the public
`current_state_ids` read and the caller's own receipt do not agree.

## Minimal reproduction

```python
"""Standalone repro for R8-07: `await send(EV, wait=True)` can resolve
success-shaped (ok=True, err=None, status='running') at an instant when
`current_state_ids == []`, while `get_persisted_snapshot()` correctly refuses
at the same instant. Exits 1 while present, 0 once fixed.
"""
import asyncio
import logging
import os
import sys
import threading
import warnings

warnings.simplefilter("ignore")
logging.disable(logging.CRITICAL)

from xstate_statemachine import Interpreter, SyncInterpreter, MachineLogic, create_machine
from xstate_statemachine.exceptions import SnapshotMidStepError, SnapshotCorruptError
FAIL = []
CFG = {
    "id": "m", "initial": "a", "maxIterations": 38,
    "after": {"17": {"target": "#m.a.c"}},
    "states": {"a": {
        "initial": "a", "always": {"target": "#m.a.a.a"},
        "states": {
            "a": {"initial": "a", "invoke": {"id": "inv", "src": "svc"},
                  "states": {"a": {"type": "final"}}},
            "c": {},
        },
    }},
}


async def async_svc(i, c, e):
    return {"ok": 1}

def plain_svc(i, c, e):
    return {"ok": 1}

def mk(svc):
    import copy
    return create_machine(copy.deepcopy(CFG), logic=MachineLogic(services={"svc": svc}))

def snap(it):
    try:
        it.get_persisted_snapshot()
        return "PRODUCED"
    except (SnapshotMidStepError, SnapshotCorruptError) as e:
        return f"REFUSED:{type(e).__name__}"

async def trial(svc):
    it = Interpreter(mk(svc))
    await asyncio.wait_for(it.start(), 10)
    for ev in ("GO", "GO", "PING", "NOPE"):
        try:
            await asyncio.wait_for(it.send(ev, wait=True), 8)
        except (asyncio.TimeoutError, Exception):
            continue
        if not list(it.current_state_ids):
            row = ("EMPTY", it.last_transition_ok, it.last_error, it.status, snap(it))
            await it.stop()
            return row
    await it.stop()
    return ("ok",)

def run_sync():
    it = SyncInterpreter(mk(plain_svc))
    it.start()
    empty = not it.current_state_ids
    for ev in ("GO", "GO", "PING", "NOPE"):
        try:
            it.send(ev)
        except Exception:
            pass
        empty = empty or not it.current_state_ids
    it.stop()
    return empty

async def main(n=15):
    print("EXPECTED: await send(EV, wait=True) never resolves ok=True/err=None while\n"
          "current_state_ids == [] (or the snapshot side agrees it's mid-step).\nOBSERVED:")
    sync_empty = run_sync()
    print(f"  sync engine, plain def svc: ever EMPTY config = {sync_empty}")
    if sync_empty:
        FAIL.append("sync engine produced an empty configuration")

    for name, svc in (("async def", async_svc), ("plain def", plain_svc)):
        hits, sample = 0, None
        for _ in range(n):
            r = await trial(svc)
            if r[0] == "EMPTY":
                hits += 1
                sample = sample or r
        print(f"  async engine, {name:<9} svc: EMPTY config {hits}/{n}")
        if sample:
            _, ok, err, status, snapshot = sample
            print(f"    ok={ok} err={err} status={status} snapshot={snapshot}")
            if ok is True and err is None and snapshot.startswith("REFUSED"):
                FAIL.append(f"{name}: receipt success-shaped (ok=True,err=None) "
                             f"while snapshot refused ({snapshot}) over empty configuration")

    print("\nFAILURES:", FAIL if FAIL else "none")
    if FAIL:
        print("VERDICT: FAIL (defect present)")
        sys.exit(1)
    print("VERDICT: PASS (defect fixed)")
    sys.exit(0)

def _watchdog(timeout=60.0):
    def _kill():
        print("WATCHDOG: repro hung; aborting", file=sys.stderr)
        os._exit(2)
    t = threading.Timer(timeout, _kill)
    t.daemon = True
    t.start()


if __name__ == "__main__":
    _watchdog(60.0)
    asyncio.run(main())
```

## Observed behaviour

Fresh run, `PYTHONIOENCODING=utf-8 PYTHONUTF8=1`, exit code `1`:

```
EXPECTED: await send(EV, wait=True) never resolves ok=True/err=None while
current_state_ids == [] (or the snapshot side agrees it's mid-step).
OBSERVED:
  sync engine, plain def svc: ever EMPTY config = False
  async engine, async def svc: EMPTY config 15/15
    ok=True err=None status=running snapshot=REFUSED:SnapshotMidStepError
  async engine, plain def svc: EMPTY config 0/15

FAILURES: ['async def: receipt success-shaped (ok=True,err=None) while snapshot refused (REFUSED:SnapshotMidStepError) over empty configuration']
VERDICT: FAIL (defect present)
```

The `async` engine's `async def` service lane hits the empty window on essentially every
trial in this run (15/15; the register notes run-to-run jitter, typically 9–15 of 15). The
`sync` engine and the `async` engine's `plain def` lane never show it. On the `async def`
lane, at the instant `current_state_ids == []`, `it.last_transition_ok` is `True`,
`it.last_error` is `None`, and `it.status` is `"running"` — a success-shaped receipt — while
`get_persisted_snapshot()` at the same instant correctly raises `SnapshotMidStepError`.

## Expected behaviour

The chain-end/"step complete" test and the snapshot-write refusal test are meant to agree on
what "mid-step" means — `interpreter.py` already applies one predicate to decide whether a
persisted snapshot may be produced (raising `SnapshotMidStepError` when it is unsafe to do
so), and the caller's `await send(..., wait=True)` receipt is documented as resolving once
"the step completed". Those two should never disagree: if the snapshot side judges the
interpreter mid-step (leaf configuration momentarily empty), the receipt side should not
simultaneously report `ok=True, err=None, status="running"` as if the step had cleanly
finished with a live configuration.

## Root cause analysis

`interpreter.py:1719-1735` (the chain-end test that decides whether `_chain_tripped`/
`_raise_depth` get reset and, transitively, whether the `send(wait=True)` future is allowed
to resolve) checks only:

```python
if (
    self._raise_depth == depth_before
    and self._chain_owed == owed_before
    and not self._internal_queue
    and not self._priority_queue
    and not self._threadsafe_self_sends_in_flight
):
    self._raise_depth = 0
    self._chain_tripped = False
```

i.e. "raised nothing, armed nothing, owes nothing, queues empty" — it does not include "the
configuration has at least one active leaf". A completion published by
`_publish_completion` can land between the exit set of the outgoing state and the entry set
of the next `always`-chained state, so the caller's receipt resolves in that gap while no
leaf is active in `current_state_ids`. The snapshot-write path (guarded separately, raising
`SnapshotMidStepError`) already tests for this same condition and correctly refuses; the
chain-end test that gates the `send(wait=True)` receipt does not apply the equivalent
predicate.

## Impact

**General.** `await send(...)` resolving `ok=True, err=None, status="running"` is exactly
the "the step completed, and normally" signal an external caller relies on. Reading
`current_state_ids` immediately afterward is the natural next line of any caller code; it
returns `[]`, which any router or supervisor built to distinguish "no active machine" /
"terminated" from "mid-transition" will misclassify. The condition self-heals within roughly
500ms and no state is corrupted, so this is a **transient false read on the observation
surface**, not data loss — but it lands specifically on the `async def` service spelling,
which is the one the library's own docs recommend.

**Order-management scenario.** A router that gates order submission or cancellation on "is
this account's session machine currently in a live state" would, on this false read, treat a
perfectly healthy in-flight session as absent for approximately half a second and could
reject or misroute a legitimate order during that window.

## Proposed fix

Add the leaf-non-empty condition to the chain-end test at `interpreter.py:1719-1735` — the
same predicate the snapshot-write path already applies to decide `SnapshotMidStepError` —
so that `send(wait=True)` does not resolve, and `current_state_ids` reads do not surface an
empty configuration, until at least one active leaf exists. `#142`/`#143` already unified the
snapshot write and read sides behind one predicate; this is the same treatment extended to
the receipt side.

## Acceptance criteria

- `test_send_wait_never_resolves_over_empty_configuration[async def-async]` — for an `async
  def` invoked service under the reproduced config (`always` chain into an invoking child),
  no `await send(EV, wait=True)` call ever resolves with `current_state_ids == []`
  regardless of the reported `ok`/`err`/`status` fields, across at least 50 trials.
- `test_send_wait_agrees_with_snapshot_midstep[async def-async]` — whenever
  `get_persisted_snapshot()` would raise `SnapshotMidStepError` for the interpreter's current
  internal state, a concurrently-resolving `send(wait=True)` receipt must not report
  `ok=True, err=None`.
- Parametrised over `def`/`async def` service kinds and over `Interpreter`/`SyncInterpreter`
  where applicable (the sync engine already never shows the defect; a regression test should
  keep asserting that).
- `repro/R8-07_send_wait_resolves_over_empty_configuration.py` exits `0` once fixed.
