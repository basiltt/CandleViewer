# #168 — async chain budget completion-exemption

**Classification: PARTIAL**

## Acceptance criteria (from issue body)
Bug: `interpreter.py:1427` (now ~1546) exempted every `is_system_event`
(completion) from the chain budget unconditionally, so an invoke ping-pong
cycle made entirely of `done.invoke` laps ran unbounded on `Interpreter`
while `SyncInterpreter` tripped `RunawayChainError`.

Fix required: mirror the sync engine's `spare = is_completion and not
tripped` — only the FIRST completion arriving at the trip is spared; every
later self-generated event (completion or not) is cut until an external
event resets the chain.

## Verification (`168_chain_budget_completion_exemption.py`)

Uses a **plain-`def`** service (the shape the pinned regression test
`TestAsyncInvokeCycleTrips` in `tests/test_round6_findings.py:154-208` uses).

| # | Criterion | Result |
|---|-----------|--------|
| 1 | async trips `RunawayChainError` on the ver↔arm invoke cycle | ✓ |
| 2 | trips promptly (≈12 laps), not thousands unbounded | ✓ |
| 3 | `on_event_dropped('chain_budget')` fires | ✓ |

```

```

## Residual: gap for coroutine (`async def`) services — the cycle is UNBOUNDED

The pinned test (`TestAsyncInvokeCycleTrips`) and my verification script both
use a **plain `def`** service. Substituting an **`async def`** service in
the identical ver↔arm cycle reproduces the ORIGINAL #168 defect in full:
the cycle never trips at all.

```python
async def svc(interp, ctx, evt):
    laps.append(1)
    return {"ok": 1}
# ... 1s of running:
# laps 14492  raise_depth 0  status running  last_ok True
```

**Root cause of the residual:** the fix at `interpreter.py:1540-1598`
(and the `_deliver_priority` counting at `interpreter.py:2277-2292`) only
charges `_raise_depth` for:
- `send()` calls made *from inside a running user action*
  (`_issued_from_own_action()`, `interpreter.py:1972-1975`, gated on
  `_ACTIVE_ACTION_OWNER`), and
- `_deliver_priority()` calls made while `self._processing` is `True`
  (`interpreter.py:2277-2292`) — this is what makes the plain-`def`
  path (`_finish_plain_service` → `_deliver_priority`, `interpreter.py
  :2657-2696`) and the actor-completion path count, because both plain
  services and actor bring-ups are awaited/delivered *inside* the
  entering macrostep (`_await_inline_services` /
  `_await_actor_bringups`), so `_processing` (or the action-owner
  context) is still `True` when the completion lands.

A genuine coroutine service (`_invoke_service_task`, `interpreter.py
:2359-2420`) runs as an independent `asyncio.Task` created by
`_invoke_service` (`interpreter.py:2520-2522`) and calls `await
self.send(done_event)` (`interpreter.py:2414`) from OUTSIDE any
macrostep — by the time it resolves, the run loop has already
returned to `await self._next_event()` and `self._processing` is
`False`. `send()` therefore takes the plain `_enqueue()` path
(`interpreter.py:854-860`), which never touches `_raise_depth` at all.
Each lap of the ver↔arm cycle, when built from coroutine services,
completely bypasses the chain budget — the exact defect #168 was
filed against, just narrowed from "every completion" (pre-fix) to
"every completion delivered by a genuinely-async invoked service"
(post-fix).

This is a real gap in coverage, not a benign difference: coroutine
services are the async engine's headline feature ("Coroutine services
still run as tasks: they genuinely await, and that is the async
engine's whole reason to exist" — comment at `interpreter.py:2508`),
so an invoke cycle built from `async def` services — the most natural
thing to write on this engine — still hangs the safety net that #166/
#167/#168 exist to provide.

## Code reference

- Fixed path (plain service / actor completion):
  `src/xstate_statemachine/interpreter.py:1540-1598` (dequeue guard),
  `2277-2292` (`_deliver_priority` counts while `_processing`).
- Unfixed path (coroutine service): `src/xstate_statemachine/
  interpreter.py:2359-2420` (`_invoke_service_task`) → `2414`
  (`await self.send(done_event)`) → `854-860` (`_enqueue`, no
  `_raise_depth` charge because `_issued_from_own_action()` is False
  once the task resumes outside the macrostep).

## Verdict

FIXED for the two shapes the pinned tests target (plain-`def`
service completions, actor `onDone`/`onError`, and `always`
re-entering an invoking child). NOT FIXED for a cycle built from
coroutine (`async def`) invoked services — the async engine's
signature feature — which still runs completely unbounded and silent,
exactly as before the round-6 fix. Downgraded from FIXED to PARTIAL.
