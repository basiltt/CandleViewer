# #171 — await Interpreter.start() returns with initial invoke children registered

**Classification: FIXED**

## Acceptance criteria (from issue body)
`await Interpreter.start()` returned while the initial macrostep was still
settling: a MachineNode child invoked from the initial entry set was not
yet in `_actors`, so an immediate `sendTo("kid")` was lost to
`unresolved_target`; `SyncInterpreter.start()` did not have this gap. Ask:
either await the initial macrostep's inline services and actor
registration inside async `start()`, or expose `children_ready()`. Fix
chosen: `start()` now awaits actor bring-ups (not a plain service's
result — that stays off-loop per #149).

## Original repro

`docs/research/xstate/issues/post-cec108b/new/repro/R6-11_start_returns_before_children_ready.py`
still exits 1 — but its own bug-detection predicate
(`state_immediately_after_start != ["parent.done"] and
reached_done_eventually`) is a plain-`def`-service scenario, which is
*intentionally* still true post-fix: #171's ask was specifically about
**invoke-child (MachineNode) registration**, and the accompanying
"Mitigating" section of the issue explicitly separates that from a plain
service's result (which #149 requires to stay un-awaited by `start()`).
Re-run confirms the plain-service body already ran (`service body already
ran: True`) and `done` is reached ~9 ms later — i.e. the SAME shape as
before the fix, which is correct: `start()` was never supposed to block on
a plain-def service's completion. The repro's exit code should be read as
"plain-service completion is still not awaited by start()" (expected,
unchanged, and correct per #149), not as evidence #171 is unfixed; #171's
actual target (actor bring-up) is separately confirmed above.

## Code reference

`src/xstate_statemachine/interpreter.py:559-563` — `start()` calls `await
self._await_actor_bringups()` after `_settle_transient_transitions()`, so
the entering macrostep's `_actor_bringups` tasks (`interpreter.py
:2485-2495`, appended when a MachineNode invocation is dispatched) are
drained before `start()` returns. `_await_actor_bringups`
(`interpreter.py:2586-2594`) is the same helper `_await_inline_services`
uses on every subsequent macrostep, so the invariant is now identical at
`start()` and at every later step.
