# #172 — `send_threadsafe(internal=True)` in-flight counter leak

**Classification: FIXED**

## Acceptance criteria (from issue body)

1. The in-flight counter (`_threadsafe_self_sends_in_flight`) must balance
   on every terminal outcome of a self-issued `send_threadsafe`: delivered,
   refused, cancelled, or loop stopped before the coroutine ran — not just
   when `_deliver` happens to run.
2. `_raise_depth`'s reset must not be permanently gated off as a
   consequence of a leaked counter.

## Fix location

`src/xstate_statemachine/interpreter.py`, `send_threadsafe()` (~line 1140)
and `_threadsafe_self_send_settled()` (line 1248-1250):

```python
fut = asyncio.run_coroutine_threadsafe(_deliver(), self._loop)
if self_issued:
    # #172: balance the increment on EVERY terminal outcome...
    fut.add_done_callback(self._threadsafe_self_send_settled)
return fut

def _threadsafe_self_send_settled(self, _fut: Any) -> None:
    """#172: one self-issued `send_threadsafe` reached a terminal state."""
    self._threadsafe_self_sends_in_flight -= 1
```

The increment still happens on the calling thread at issue time (as
before); the decrement now happens via a `Future.add_done_callback`, which
fires for every terminal outcome of a `concurrent.futures.Future`
(success, exception, or cancellation) — including the case where the loop
is closed/stopped before `_deliver()` ever runs. This directly replaces
the old leak path where the decrement lived only inside `_deliver`.

## Original repro (`R6-12_threadsafe_self_send_counter_leak.py`)

That script manually mutates the private counter
(`i._threadsafe_self_sends_in_flight += 1`) to *simulate* the leak shape
rather than driving it through the real `send_threadsafe()` API, so it
still exits `1` on 221ce7c — that is expected and does not indicate the
bug is present; it is testing a hand-rolled scenario the real code path no
longer reaches. Re-run for the record:

```
in-flight counter before=0 after stop()=1
_raise_depth after stop()=0
BUG CONFIRMED: ...
exit=1
```

This is **stale**, not residual: the manual-mutation harness bypasses the
new done-callback wiring entirely (it never calls `send_threadsafe`), so
it cannot observe the fix. `172_threadsafe_counter_leak.py` exercises the
real API and passes.
