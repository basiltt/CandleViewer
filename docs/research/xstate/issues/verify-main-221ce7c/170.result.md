# #170 — Receipt.denied False for a guard that crashed under guardErrorPolicy="raise"

**Classification: FIXED**

## Acceptance criteria (from issue body)
A guard that raises under `guardErrorPolicy: "raise"` used to set
`Receipt.denied=True` (because `_is_guard_satisfied` returns `False` on
the raise path, and that unconditionally set `_guard_denied_this_step`),
mislabelling a crash as a "the guard returned False" denial. Fix:
`(denied, error is None)` must discriminate all three cases — false/denied,
crash/error, true/passed — on both engines.

## Verification (`170_receipt_denied_crashed_guard.py`)

| Case | sync denied | sync error | async denied | async error |
|------|-------------|------------|---------------|-------------|
| guard returns `False` | `True` | `None` | `True` | `None` |
| guard raises (`RuntimeError`) | `False` | `RuntimeError` | `False` | `RuntimeError` |
| guard returns `True` | `False` | `None` (transitioned) | `False` | `None` (transitioned) |

```
[sync false] denied=True error=None -> True
[sync crash] r=Receipt(..., error=RuntimeError('guard boom'), denied=False) -> True
[sync true] denied=False error=None -> True
[async false] denied=True error=None -> True
[async crash] r=Receipt(..., error=RuntimeError('guard boom'), denied=False) -> True
[async true] denied=False error=None -> True
RESULT: PASS
```

All three cases are correctly discriminated on both engines.
