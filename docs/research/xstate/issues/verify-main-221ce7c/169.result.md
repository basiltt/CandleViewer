# #169 — snapshot from inside entry/exit action refused at root

**Classification: FIXED**

## Acceptance criteria (from issue body)
`get_persisted_snapshot()` called from inside an ENTRY action was ACCEPTED
on both engines because the guard was `in_flight AND NOT legal`; inside an
entry action the new leaf is already legal (one leaf active) while context
writes from that same entry are still in flight, so a torn
`configuration=['oms.filled']` + `context={'filled_qty': 0}` snapshot
persisted and restored cleanly. Fix: at the ROOT, `in_flight` alone must
refuse — legality stays the (separate) test for the bounded wait used when
a CHILD actor is caught mid-step by its parent.
