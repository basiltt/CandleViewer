**Classification: NOT-FIXED** (Case D specifically; Cases A/B/C confirmed fixed)

Resolve **all** outstanding receipts at `stop()` — including receipts for
concurrent `send()` calls that reuse the SAME `Event` instance (Case D) —
with `InterpreterStoppedError`. A pinned test for Case D specifically; the
existing coverage (Cases A/B/C) already passes.

Every one of 160 receipts across 20 trials (8 racers/trial) resolved as
ordinary success (`error is None`), **zero** resolved with
`InterpreterStoppedError`, and there were no crashed/unexpected outcomes.
In this exact harness the race window consistently favors "delivered
before stop() takes effect" for every racer rather than reproducing a
receipt that's abandoned mid-flight — i.e. `stop()` is not observed to
proactively resolve any outstanding duplicate-instance receipt with
`InterpreterStoppedError` in this scenario; whether that's because none
are actually still in-flight by the time `stop()` runs, or because the
resolve-on-stop path silently misses reused-instance duplicates, both
read as "no `InterpreterStoppedError` ever surfaces for Case D here" —
which is the failure mode the issue describes.

## Cross-check: does the narrower round-6 test pass anyway?

`tests/test_round6_findings.py::TestReceiptsRacingStop
.test_ok_receipts_equal_applied_events` — 17/17 round-6 tests pass,
including this one. That test's invariant is **`ok == applied`** (the
number of successful receipts equals the number of times the context
mutation actually ran) and **`ok + stopped == 12`** — it does NOT assert
that any receipt is ever `InterpreterStoppedError`; with a 0.001s action
and only a single `await asyncio.sleep(delay)` before `stop()`, all 12
sends can legitimately complete before `stop()` takes effect, satisfying
`ok == applied == 12, stopped == 0` without ever exercising the
"abandoned mid-flight" path the issue is about. This is a materially
weaker check than the issue's acceptance criterion ("a pinned test for
case D specifically") — the round-6 suite does not actually pin Case D's
`InterpreterStoppedError` guarantee; it pins a different, easier-to-
satisfy invariant that happens to also hold when Case D is broken.

**NOT-FIXED**.

## Residual risk

A caller relying on "every outstanding send racing `stop()` either
succeeded or got `InterpreterStoppedError`, distinguishably" for a reused
`Event` instance cannot rely on that guarantee. Financial-OMS-relevant:
an order-submission caller reusing an `Event` object across retries could
receive an ordinary success receipt for a send that raced a shutdown,
which is the exact ambiguity the issue flags as unacceptable for that
domain.
