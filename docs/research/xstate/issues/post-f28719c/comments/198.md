Confirmed fixed on both engines. A `version ≥ 1` running payload with an emptied or dropped `configuration` **or** `state_ids` is refused; v0 payloads are still accepted unchecked, which the docstring documents as deliberate.

One small compatibility note, filed Low (`R9-14`) rather than argued here: this also refuses a `version: 1` running blob with **no** `configuration` key at all, which previously restored. The CHANGELOG names only the emptied-field shape, so anyone with v1 blobs written by an older build may want that spelled out in the release notes.
