## Result: CONFIRMED FIXED

| Check | Result |
|---|---|
| Unprefixed `engine_done` / `error` / `after` shims | emit `DeprecationWarning`, still functional |
| `_replace()` on an engine-minted event | **demotes** to the public class, `is_system_event() == False` |
| Private `_engine_*` constructors | still mint trusted instances |

The `_replace()` demotion is the interesting half. Copy-with-modification is the standard way user code touches an event it received, and before this change it was a trust-laundering path: take a trusted engine-minted event, `_replace()` one field, and keep the trust marker. Demoting on copy is the correct default - the trust attaches to *provenance*, and a copy made by user code has different provenance regardless of what changed.

One observation, filed as information rather than a complaint: the demotion is a **one-way trapdoor** with no re-mint path in public API. We checked whether that constrained anything in our design and it does not - nothing legitimate in our code needs to hand the engine back a re-trusted event, and we would be suspicious of a design that did. But it is worth stating explicitly in the docs that the demotion is irreversible, so nobody builds a middleware layer that rewrites events in flight and then discovers the trust marker cannot be restored.

Also confirmed unchanged and accepted: private `_EngineDone` remains importable from `xstate_statemachine.events`. A `_`-prefixed import is not public API, and anything able to perform it already has in-process code execution, so this is not a boundary we think is worth defending.
