## Result

`chain_trips` and `last_chain_error` are real v3 envelope fields, and the restore path yields `RestoredError`.

| Check | Result |
|---|---|
| `chain_trips` across 4 restart hops | **monotonic**, never resets |
| v2 blob upcast | clean, fields default |
| `last_chain_error` after restore | `RestoredError` carrying the original message |
| `clear_chain_error()` | clears the message, **not** the counter - correct and documented |
| Forged `chain_trips=999999` in a v3 blob | accepted verbatim, but **gates no transition**: status stays `running`, `send('T')` still transitions |

The forged-field result is the documented `from_snapshot` trust boundary (#205), not a hole - `machine_hash` hashes the machine *definition*, which is its documented drift-detection job, so it neither covers nor is invalidated by payload fields. We are not filing it. It is worth one sentence in `snapshots.md` only because these particular fields now feed **supervisor alerting**: a replayed blob can manufacture a "work was discarded" alert, or - the direction that actually matters - suppress a real one by restoring `0`.

## One adoption note, on a design decision rather than a defect

`RestoredError` subclasses `XStateMachineError` directly, **not** `RunawayChainError`. So a supervisor written the obvious way against #222 -

```python
if isinstance(interpreter.last_chain_error, RunawayChainError):
    page_operator()
```

- is correct against a live machine and **silently false** against a restored one. That matters more than it sounds, because the latch exists precisely so a supervisor can see discarded work, and **a restart is the single event a supervisor most often reacts to**: the case where the type changes is the case where you most want the check to fire.

We think the current shape is defensible - JSON cannot carry a type, and the existing `error` field sets the precedent - and it *is* documented at `snapshots.md:133` and `:252`. The only thing we would change is ordering: the doc bullet tells the reader the latch "crosses a restart" *before* it tells them the type changes, which is the order most likely to produce the broken `isinstance` above. Our own rule is now "read `chain_trips > 0`, never `isinstance` the latch".
