# LC-02 — `always` self-target deadlocks silently, no config-time diagnostic

**GitHub issue:** [#29](https://github.com/basiltt/xstate-statemachine/issues/29)
**Library version verified:** 0.8.0 (this checkout, commit `9bf6065`)
**Verification script:** `verify-0.8.0/LC-02_always-self-target-deadlock.py`
**Original repro:** `repro/LC-02_always-self-target-deadlock.py`

## Classification: **FIXED-DEFAULT**

This is a build-time validation fix, always on (no policy flag governs
whether the check runs — it is part of `validate_machine()`, invoked
unconditionally by `create_machine()`). The *only* related escape hatch,
`strict_targets=False`, downgrades a **different** class of error (unresolved
targets, LC-08) to a warning and does not apply to this non-progressing
`always` self-target check — confirmed no such flag suppresses this
diagnostic.

## Original repro result

`repro/LC-02_always-self-target-deadlock.py`: **exit 1**, but not because the
defect persists — because `create_machine(SELF_LOOP, ...)` now *raises*
`InvalidConfigError` before the repro can reach its runtime deadlock-detection
logic, and the script (written to assert the old runtime symptom) treats the
unhandled exception as a crash/failure:

```
xstate_statemachine.exceptions.InvalidConfigError: Machine 'm' has non-progressing 'always' transitions:
  m.loop: always self-target can never make progress -- the transition does not re-enter the state, so 'entry' will not re-run. Add "reenter": true, route via an intermediate state, or give the transition actions that mutate context.
```

This is the exact fix the issue asked for (acceptance criterion #8 explicitly
anticipates this: "the repro must be updated to assert the validation error
rather than the converged state"). The repro script's exit 1 is an artifact of
never having been updated, not evidence of a live defect.

## Residual gap

None in the library behavior. The only gap is that `repro/LC-02_always-self-target-deadlock.py` was not updated (as the issue itself anticipated) to assert the new build-time exception instead of a runtime convergence state — it currently just crashes with an uncaught `InvalidConfigError`. Recommend updating the repro script (or retiring it in favor of the new verification script) so CI doesn't misreport this as an open defect.

## Recommended CandleViewer constraint

**MUST keep `strict_targets` at its default (`True`)** — do not pass
`strict_targets=False` on any CandleViewer machine, since that escape hatch
(intended for LC-08 target-resolution migration only) downgrades a related
but distinct validation to a warning; confirm in code review that it is never
set. No additional per-machine flag is needed for the self-target check
itself since it runs unconditionally.
