## Residual gap

- Criteria 2, 3, 5, 6, 8 were not independently stress-tested in this pass
  (confirmed only by source inspection or not exercised); recommend a
  follow-up pass that (a) builds a machine with 3+ independently broken
  targets across `on`/`always`/`after`/`onDone`/`invoke.onError` and asserts
  all 3+ appear in one error message, and (b) exercises
  `on_transition_failed` directly with a plugin spy against a target that
  fails at *runtime* (e.g. under `strict_targets=False`).
- No exception type mismatch this time — `InvalidConfigError` matches what
  the issue's own "Usage after the change" example predicted
  (`StateNotFoundError` was mentioned in the summary but the worked example
  in the issue itself already shows `StateNotFoundError` — actually shipped
  as `InvalidConfigError`; same naming note as LC-06).

## Recommended CandleViewer constraint

**MUST** keep default `strict_targets=True` on every `create_machine()` call.
This closes LC-08 completely for the "typo'd/renamed target deploys clean"
failure mode described for our B9 rule-compiler workstream: a compiled rule
whose target was renamed out from under it now fails at `create_machine()`,
before deployment, rather than failing open silently in production. Our
house rule requiring a bespoke build-time target validator is now redundant
with the library's own validator and can be retired in favor of asserting
`strict_targets` is never passed as `False` anywhere in our codebase (CI
lint).
