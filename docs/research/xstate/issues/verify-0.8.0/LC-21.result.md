# LC-21 — persisted snapshots carry no schema version or machine identity

**Classification: FIXED-DEFAULT** (with a documented, sensible opt-out: `verify_machine_hash=False`, default `True`)

CHANGELOG [0.8.0][wave 2] (#45): "Snapshot envelope v1 — Persisted snapshots
gain `version`, `machine_id`, `machine_hash` (a 16-hex structural
fingerprint), and `taken_at`. `from_snapshot` refuses a newer `version` with
`SnapshotVersionError` and a mismatched id or hash with
`SnapshotDriftError`; `from_snapshot(..., verify_machine_hash=False)` opts
out after a migration. Unversioned 0.7.x payloads restore exactly as
before." New module `persistence.py` owns the format contract;
`SNAPSHOT_VERSION = 1`.

## Residual gap

- Cosmetic-edit hash stability (`meta`/description changes must NOT
  invalidate `machine_hash`) not independently re-verified in this pass.
- Nested/child-actor snapshot versioning (`_persist_actors` re-emission
  path carrying its own version) not independently re-verified in this
  pass — worth a follow-up given the issue explicitly called this out as a
  gap that "can outlive several releases inside a parent's snapshot."
- Docs not audited.

## Recommended CandleViewer constraint

- CandleViewer's application-owned envelope (`cv_schema_version` +
  hand-rolled `machine_hash` + upcaster registry, described in the issue's
  "Current workaround") can be **retired** in favor of the library's native
  `version`/`machine_hash` fields — this removes an entire class of
  drift-between-envelope-and-payload risk the issue called out as
  workaround weakness #1.
- MUST NOT pass `verify_machine_hash=False` except as a one-shot, logged,
  explicitly-reviewed migration step (per the library's own documented
  intent) — never as a standing default, since that reintroduces the exact
  LC-23 silent-semantic-drift hazard (order stuck forever after a guard is
  added to a still-reachable state id) this issue exists to close.
- Recommended: add a boot-time integration test that intentionally adds a
  guard to a live CandleViewer machine and asserts `from_snapshot` raises
  `SnapshotDriftError` on old snapshots, to pin this contract in
  CandleViewer's own CI (mirrors `test_machine_hash_changes_when_a_guard_is_added`).
- Follow-up recommended (not blocking adoption): independently verify
  nested actor snapshot versioning before relying on multi-actor (order +
  leg) machines surviving a multi-release upgrade unattended.
