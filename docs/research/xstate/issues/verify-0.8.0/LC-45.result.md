# LC-45 — Hot-path allocation and INFO logging — Verification on 0.8.0

**Classification: FIXED-DEFAULT**

Both symptoms from the issue are fixed unconditionally — no policy flag, no opt-in.

## What changed (from CHANGELOG.md [0.8.0])

- "Per-event `INFO` log calls on the hot path are now `DEBUG` (#55, part 1). Measured overhead of running at `INFO` on the filer's OMS machine dropped from 2.53× to ~1.0×." (Changed section)
- `models.py:894-905` (source comment "⚡ #55 part 2"): `StateNode.__init__` now precompiles `_on_partials` (sorted list of `.*`-suffixed descriptor keys) and `_on_has_wildcard` (bool for bare `*`) **once**, at machine-construction time. `_matching_descriptors` consults these instead of rescanning every `on` map key on every ancestor walk per event.

The `_select_transitions` per-event `leaves`/`sorted`/`guard_cache` allocation (item 1 in the issue) and the `_is_descendant` f-string micro-optimisation (item 3, downgraded to non-bug in the original issue's own verification) were **not** independently re-checked line-by-line against 0.8.0 source beyond confirming the descriptor index exists; the issue's own acceptance criteria treat the INFO→DEBUG change and the descriptor index as the two load-bearing fixes, both confirmed below.

## Residual gap

- Ratio-under-load is occasionally noisy (observed up to 1.35× in one run out of four), so the strict `< 1.10` criterion isn't always met on this machine, though it is never anywhere near the original 2.5–4× regression.
- `_select_transitions`'s per-event `leaves`/`sorted`/`guard_cache` allocation (issue item 1) was not independently confirmed to have been restructured — only that it no longer dominates `tottime` the way the original profile showed. It's plausible the descriptor-index fix alone accounts for most of the win, since `_matching_descriptors` was cited as ~72% of tottime originally.
- Criteria 2, 4, 5 (lifecycle logging still at INFO, wildcard/internal-event exclusion, `_is_descendant` equivalence) were not independently re-verified in this pass.

## Recommended CandleViewer constraint

None required — this fix is default-on and unconditional. No `actionErrorPolicy`-style opt-in needed. CandleViewer can safely attach an INFO handler to `xstate_statemachine` in production (e.g. for lifecycle events) without reintroducing the previously-measured 3–4× hot-path penalty, since per-event/guard/entry-exit logging is now at DEBUG.
