## Classification: **FIXED-OPT-IN**

Option needed: `onUnhandled: "defer"` (or `"error"`) on `create_machine()`.
**Default remains `"ignore"`**, which preserves 0.7.x's silent-drop behaviour
for state/context — the difference from 0.7.0 is that the drop is now
observable via the `on_unhandled_event` plugin hook under every policy,
including the default.

## Residual gap

None in the library. `repro/LC-03_unhandled-events-discarded.py` was written
for 0.7.0 and never updated to set `onUnhandled="defer"`, so it necessarily
still observes default-policy behavior and reports "DEFECT REPRODUCED". Not a
library gap.

## Recommended CandleViewer constraint

**MUST set `onUnhandled="defer"` on every production machine that can
legitimately receive an event slightly ahead of a state transition it depends
on (e.g. exchange fills/acks racing state changes)**, or `onUnhandled="error"`
where an unhandled event indicates a genuine protocol violation that should
halt the machine rather than silently continue. Never rely on the
`"ignore"` default in trading-critical state machines. Additionally, tune
`defer_max` (via whatever config knob backs `DEFER_MAX`) to a value that
comfortably exceeds worst-case burst size for each machine, and monitor
`on_unhandled_event`'s `"dropped"` disposition as an alerting signal.
