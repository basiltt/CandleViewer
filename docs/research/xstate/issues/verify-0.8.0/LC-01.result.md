# LC-01 — action raises still committed transition, no error channel

**GitHub issue:** [#27](https://github.com/basiltt/xstate-statemachine/issues/27)
**Library version verified:** 0.8.0 (this checkout, commit `9bf6065`)
**Verification script:** `verify-0.8.0/LC-01_action-raise-commits-transition.py`
**Original repro:** `repro/LC-01_action-raise-commits-transition.py`

## Classification: **FIXED-OPT-IN**

Option needed: `actionErrorPolicy: "rollback"` (or `"fail"`) on `create_machine()`.
**Default remains `"continue"`**, which preserves 0.7.x's committed-transition
behaviour byte-for-byte — the difference from 0.7.0 is that the failure is now
**observable** (`interpreter.last_transition_ok`, `on_transition_failed` hook)
even under the default.

## Residual gap

None in the library. The only residual gap is that `repro/LC-01_action-raise-commits-transition.py` was written for 0.7.0 and asserts the *old* buggy behavior is still absent; it does not construct the machine with `actionErrorPolicy` set, so it necessarily still observes default (`"continue"`) semantics and reports "DEFECT REPRODUCED". This is expected under the opt-in design — CandleViewer must not rely on the un-updated repro script as a regression gate; it must use the new verification script (or set the policy explicitly in its own machines).

## Recommended CandleViewer constraint

**MUST set `actionErrorPolicy="rollback"` (or `"fail"` for machines where a
half-built state must stop the world) on every production machine.** Do not
rely on the library default; the default intentionally preserves the
committed-transition behavior that caused LC-01 (now just observable). Add a
lint/CI check that greps machine configs for a missing `actionErrorPolicy` key
and fails the build.
