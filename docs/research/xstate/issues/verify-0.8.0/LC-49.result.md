# LC-49 — No hierarchical state.value — Verification on 0.8.0

**Classification: FIXED-DEFAULT**

## What changed (from CHANGELOG.md [0.8.0])

Added section (wave 2): "`interpreter.value` (#58) — the active configuration in XState's hierarchical form: a leaf key for an atomic root, `{parent: child}` for compound (innermost collapses to a string), one key per region for parallel, `{}` before `start()`. Tree-walked, so state keys containing `.` are safe. `matches()` now also accepts a partial value dict. Snapshots carry a derived `"value"` key; restore ignores it."

Confirmed in source: `BaseInterpreter.value` (base_interpreter.py:549), `_value_of` (575), `matches()` (611) accepting both string and dict forms.

Unconditional additive property — no policy flag, single mode to verify.

## Residual gap

- Criteria 2 (atomic root), 5 (nested parallel inside compound), and 6 (final leaf specifically) were not independently re-verified with dedicated test machines in this pass — the verification script's `DOTTED_CFG` has a compound (non-parallel) root with one level, close to criterion 2/3 but not a pure atomic-root case, and the parallel machine's `final` state (`life.filled`) was declared but never entered.
- `SyncInterpreter` was not independently exercised (only async `Interpreter`); per the 0.8.0 "one core algorithm" refactor both engines share `BaseInterpreter.value`/`_value_of`, so divergence is unlikely but unconfirmed.
- `from_snapshot(...)` ignoring a persisted `"value"` key (rather than trusting it) was not independently re-tested — only that the key is present and correct going forward.

## Recommended CandleViewer constraint

None required — unconditional additive property. CandleViewer's WebSocket projection can now use `interp.value` directly instead of maintaining a bespoke id-string projector, closing the exact gap described in the original issue (region-scoped UI updates for the `life` × `protection` parallel topology). Recommend replacing the custom `value_from_ids()` projector with `interp.value` and adding a regression test asserting equality between the two during a migration window, then deleting the custom projector.

No follow-up GitHub comment needed — core capability (hierarchical `value`, parallel regions, dotted-key safety, snapshot integration, dict/string `matches()`) is fully resolved per the issue's Observed/Expected criteria; remaining gaps are verification-depth gaps (untested edge cases), not functional gaps in the library.
