# LC-05 — `raise` queued behind pending external events (no macrostep)

**GitHub issue:** [#36](https://github.com/basiltt/xstate-statemachine/issues/36)
**Library version verified:** 0.8.0 (this checkout, commit `9bf6065`)
**Verification script:** `verify-0.8.0/LC-05_raise-not-macrostep.py`
**Original repro:** `repro/LC-05_raise-not-macrostep.py`

## Classification: **FIXED-DEFAULT**

This is a default-semantics fix, not a policy/option — there is no flag to
opt into it and no flag that disables it. Both `Interpreter` (async) and
`SyncInterpreter` now hold raised events in a separate internal queue that is
drained to exhaustion before the next external event is taken, matching the
SCXML `mainEventLoop`/`microstep` algorithm and XState v5. The 0.7.x
interleaving (external event arriving mid-transition winning the race) is
gone unconditionally.

## Recommended CandleViewer constraint

None required beyond upgrading to 0.8.0 — this fix is unconditional and
requires no per-machine configuration. CandleViewer's order machine (which
relies on `raise EVALUATE` after a fill to re-check risk limits atomically
before any external fill can interleave) can now rely on this guarantee by
default. Recommend adding a regression test in CandleViewer's own suite
pinning the macrostep-ordering guarantee for the `EVALUATE` self-raise, since
this is exactly the production scenario the issue's "CandleViewer" impact
section described.
