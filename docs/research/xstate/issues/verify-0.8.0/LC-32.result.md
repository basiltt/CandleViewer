# LC-32: terminal machines not reaped — 0.8.0 verification

**Classification: FIXED-DEFAULT**

## Summary

CHANGELOG `[0.8.0]` "[wave 2] Reaching a top-level final state now tears
down" (#57): child actors are stopped, `after` timers and invoked services
cancelled, and the actor-system registration removed the moment `status`
becomes `"done"`/`"error"` — not only when `stop()` is later called.
`status`, `output`, `error`, `context` remain readable; `stop()` on a
already-`done` machine is a no-op that keeps `status == "done"`. Applies
unconditionally — no opt-in flag.

## Residual gap

None found for the primary defect. Both original symptoms are fixed:
(1) a `done` machine's children are stopped and the system registry is
cleared immediately on completion, without an explicit `stop()`; (2) `stop()`
after completion is a clean no-op that leaves the registry empty. The
`context`/`output` retention requirement (documented as intentional, not
opt-in `release_context_on_done`) is satisfied.

Caveat: the **original repro script exits 0** but its own internal
`RESULT: NOT REPRODUCED` line is based on the *pre-0.8.0* leaked-state
literal check (`leaked_on_done = bool(interp._actors) or (child.status ==
"running")`) which is now trivially false — this is a *correct* pass, not a
false one. It also crashed on
`child._event_loop_task.done()` handling because `child` itself becomes
`None`-like after teardown removes the entry — but this doesn't affect the
final exit code since the leak conditions evaluate as absent either way.
Re-run confirmed exit 0 with sensible output.

## Recommended CandleViewer constraint

- No longer necessary to hand-roll an application-level reaper/supervisor
  for completed order machines — 0.8.0 tears down children, timers,
  invoked services and the system registry automatically the instant an
  order machine reaches a top-level final state (`filled`/`cancelled`/
  `rejected`).
- `interp.stop()` in a `finally` block remains **safe** (documented as a
  no-op on an already-`done` machine) but is no longer strictly required
  for cleanup — keep it anyway for the "never reached a final state"
  (crashed/cancelled) code paths, since that's the case where teardown
  still depends on an explicit `stop()`.
- `interpreter.context` / `.output` remain valid to read after completion —
  the OMS's post-fill reporting code that reads final context does not
  need to snapshot it before any teardown call.
