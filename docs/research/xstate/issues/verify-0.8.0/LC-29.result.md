# LC-29: invoke.input static and ignored — 0.8.0 verification

**Classification: FIXED-DEFAULT**

## Summary

CHANGELOG `[0.8.0]` "[wave 2] `invoke.input` may be a callable" (#42):
`InvokeDefinition.resolve_input(context, event)` accepts `fn({context,
event})` and `fn(context, event)` forms, is resolved per spawn, deep-copied,
and now passed to invoked **child machines** as their creation `input`
(`interpreter.py` `_spawn_and_manage_actor`, `child_input =
invocation.resolve_input(self.context, None)` →
`Interpreter(actor_machine, input=child_input, ...)`). This is unconditional
— both defects described in the issue are fixed by default, no opt-in flag.

## Residual gap

None functionally — both defects in the issue summary ("stored verbatim as
a function object" and "discarded outright for child machines") are fixed.
The only "gap" is that the **original repro script's specific assertion**
(a plain-dict child's `context["snapshot"]` key gets overwritten by
`input`) was never the documented contract — XState's `input` lands at
`context["input"]` for a context factory to consume, and 0.8.0 correctly
implements exactly that, explicitly declining to clobber existing dict
keys. The repro predates the library's finalized design decision on that
edge case; it is not a sign of a remaining defect once you use the
documented `context` factory pattern (as the new verify script does).

## Original repro re-run

```
OBSERVED type(invoke.input) with a callable = function
EXPECTED it to be resolved per-spawn against {context, event} (a dict)
OBSERVED spawned child context = {'snapshot': None, 'input': {'snapshot': {'venue': 'X', 'size': 7}}}
OBSERVED spawned child .input  = {'snapshot': {'venue': 'X', 'size': 7}}
EXPECTED context = {'snapshot': {'venue': 'X', 'size': 7}} (invoke.input seeds the child)
RESULT: REPRODUCED (invoke.input static + ignored)
(exit code 1)
```

This is misleading at face value — `.input` is now correctly `{'snapshot':
...}` (previously `None`), and the value **does** reach the child (visible
at `context['input']`) — but the script's hard assertion
`child.context.get("snapshot") == {...}` fails because the plain-dict child
never had a context factory to consume `input`. The new verify script uses
a context factory child and confirms the full contract works.

## Recommended CandleViewer constraint

- MUST give any invoked child machine that needs `invoke.input` a callable
  `context` factory (`context: lambda args: {...args["input"]}`), not a
  plain dict — a plain-dict child only gets `input` stashed under the
  `"input"` key and must read it explicitly in an entry action if it wants
  fields under existing key names.
- Callable `input` (both `fn(ctx, evt)` and `fn(args)` forms) can now be
  used for the profile-snapshot pattern described in the issue (freezing a
  leg's `profile_snapshot` at spawn time); the deep-copy is confirmed, so
  the "parent mutates profile mid-flight" hazard the issue raised is
  resolved.
