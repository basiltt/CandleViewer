## Original repro (`repro/LC-37_arity-misclassification.py`)

Exit code: **1**, but the printed evidence shows the fix is live:

```
UserWarning: MachineLogic subclass method 'is_filled' has arity 1, which matches
no logic contract (guard=2, service=3, action=4); it was NOT registered.
Decorate it with @action / @guard / @service to state the role.
UserWarning: MachineLogic subclass method 'record_fill' was registered as a
service by arity (3), but that arity is ambiguous: service (or a 3-arg action).
...
OBSERVED registries (decorated): {'record_fill': ['actions'], 'is_filled': ['guards'], 'submit_order': ['services']}
EXPECTED registries: {'record_fill': ['actions'], 'is_filled': ['guards'], 'submit_order': ['services']}
```

Part 2 of the original repro (decorated case) now matches `EXPECTED` exactly —
the misclassification the issue reported is gone for decorated code. It still
exits 1 because part 1 (undecorated, arity-based) is **unchanged by design**:
the issue's own proposed fix explicitly keeps arity as a fallback for
undecorated methods and only asks that ambiguous cases warn loudly, which they
now do. The original script's hard `observed != EXPECTED` check for the
undecorated case is inherently unsatisfiable without breaking the
backwards-compatible fallback the issue itself requested.

## Residual gap

The undecorated arity-based fallback is retained (as designed) and can still
misfile: an undecorated 3-arg method intended as an action lands in
`services`. This is now always accompanied by a `UserWarning`, so it is no
longer *silent*, but it is not *prevented*. This matches the issue's own
"Backwards compatibility" section, which proposed warnings now and a stricter
mode later (a `MachineLogic(strict=True)` upgrade to hard errors was proposed
but not confirmed present in this pass).

## Recommended CandleViewer constraint

- MUST decorate every `MachineLogic` subclass method with `@action`, `@guard`,
  or `@service` explicitly; do not rely on arity inference.
- MUST treat any `UserWarning` from `machine_logic.py` as a build failure in
  CI (e.g. `-W error::UserWarning` for tests that construct `MachineLogic`
  subclasses), since it flags exactly the misclassification class this issue
  describes.
