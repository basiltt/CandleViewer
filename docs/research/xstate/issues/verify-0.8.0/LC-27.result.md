# LC-27 — no clock injection / virtual time — Verification on 0.8.0

## Classification: **FIXED-DEFAULT**

`Clock` protocol, `RealClock`, and `SimulatedClock` are shipped and exported
from the package root. `Interpreter`/`SyncInterpreter(clock=...)` is
accepted unconditionally (keyword-only, `RealClock()` default) — there is no
flag gating the *capability*; only the *choice of clock* is opt-in (which is
the correct design — production code keeps `RealClock` by default,
tests opt into `SimulatedClock`).

## Fix location

- CHANGELOG: "**[wave 3] Injectable `Clock`** (#48, #49, #50) -- `Clock`
  protocol, `RealClock` (default) and `SimulatedClock` (virtual time),
  passed as `Interpreter(clock=)` / `SyncInterpreter(clock=)`; invoked and
  spawned children inherit the parent's clock."
- `src/xstate_statemachine/clock.py` — new module: `Clock` (Protocol),
  `RealClock`, `SimulatedClock` with `.increment(ms)` / `.set(ms)`.
- `src/xstate_statemachine/base_interpreter.py:345` —
  `__init__(..., clock: Optional[Clock] = None, ...)`,
  `self.clock: Clock = clock if clock is not None else RealClock()`.
- `src/xstate_statemachine/__init__.py:119,224-227` — `Clock`, `RealClock`,
  `SimulatedClock` exported.

## Residual gap

- Child-actor clock inheritance (invoked/spawned children sharing the
  parent's clock) was not independently exercised.
- Timer-cancel-clears-handle and `SyncInterpreter`-side clock tests were
  not independently exercised.
- The *original* repro script is stale and should be updated/retired now
  that the feature exists correctly — flagged via follow-up comment below
  rather than modified (per instructions not to edit it).

## Recommended CandleViewer constraint

- **SHOULD** adopt `SimulatedClock` in all tests of `after`-driven timeout
  logic (order timeouts, TWAP/VWAP slice pacing, peg re-price windows) to
  eliminate real-time sleeps from the test suite — this was the entire
  point of filing LC-27 and it is now fully available with no opt-in
  friction beyond passing `clock=SimulatedClock()` at construction.
- **MUST** verify child-actor clock inheritance explicitly in a
  CandleViewer-specific test before relying on it for any parent/child
  invoke relationship with its own `after` timers, since this was not
  independently re-verified in this pass.
- No production-code change needed: leaving `clock=` unset preserves
  0.7.x wall-clock behaviour exactly.
