# #43 — one asyncio task per invoked child — verification on main@3c527b0

**Classification: FIXED**

Library: xstate-statemachine, commit `3c527b0` (merge of PR #83, `2459c82`), 0.8.1-unreleased (`__version__` still reports `0.8.0`).
Script: `43_one-task-per-invoked-child.py` in this directory. Exit code: **0**.

## Fix location

`base_interpreter.py` / `interpreter.py`: `_ACTOR_POLL_INTERVAL` and the
per-child `while child.status == "running": await asyncio.sleep(...)`
manager task are gone. Completion is now pushed from the child's terminal
listener the instant its status flips (`interpreter.py` diff, `2459c82`);
exiting the owning state stops children directly instead of relying on the
poll loop to notice. New tests: `tests/test_actor_perf.py` (`TestActorTaskBudget`,
`TestInvokedActorBringUpEdges`).

The original LC-28 repro (`repro/LC-28_actor-poll-two-tasks.py`) now **fails to even run** against 3c527b0 because it directly asserts on the removed `_ACTOR_POLL_INTERVAL` private attribute (`AttributeError`) — this is expected: the repro was written to detect the *presence* of the poll constant, and that constant's removal is exactly the fix. The new script here supersedes it using only public API surface (`asyncio.all_tasks()`, `Interpreter._actors`, `call_later` spy) so it exercises the acceptance criteria without depending on internals slated for removal.
