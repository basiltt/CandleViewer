### Fix location

`src/xstate_statemachine/events.py:79-265`:
- `Event._provenance: Any = field(default=None, init=False, compare=False, repr=False)` (line 122) — no public constructor param.
- `Event.system` is a read-only `@property` (line 126-129).
- `_ENGINE_MARK: Any = object()` (line 240) — unexported identity sentinel.
- `system_event()` (line 256-265) is the only path that sets `_provenance` to `_ENGINE_MARK`, via `object.__setattr__` (required because `Event` is frozen).
- `is_system_event()` (line 243-253) checks `event._provenance is _ENGINE_MARK` — identity comparison, not equality, so an attacker who obtains a copy or writes `True`/another object into `_provenance` still gets `False`.

### Additional probes beyond the GitHub AC text

Per the task's list of specific claims, I additionally verified:
- **`Event(system=True)` TypeErrors** — confirmed (constructor rejects unknown kwarg).
- **`Event.system` read-only** — confirmed (`AttributeError`-class exception on assignment via frozen dataclass).
- **Sentinel not reachable via `copy.copy`/`copy.deepcopy`** — confirmed non-system after copy.
- **`dataclasses.replace`** — confirmed a plain user event does not become system via `replace`; also spot-checked that `replace()` on an *engine*-minted event's `type` field yields `is_system_event() == False` for the replaced object (informational: `dataclasses.replace` does not pass `init=False` fields to `__init__`, so it silently *drops* provenance rather than forging it up — safe direction, not a bypass, but worth noting for anyone relying on `replace()` to clone an engine event and expecting it to remain exempt).
- **`pickle` round-trip** — confirmed plain event stays non-system after `pickle.dumps`/`loads`.
- **`__dict__`/`object.__setattr__`** — confirmed setting `_provenance = True` or any object other than the real `_ENGINE_MARK` singleton does not forge system status (identity check holds); an attacker would need to obtain a reference to the actual sentinel object, which is never exported.
