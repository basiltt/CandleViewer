# #99 — `SyncInterpreter` onError for a failed invoked child machine — verify on main@5e07ba8

## Verdict: PARTIAL

Sync-side fix is correct and complete. Criterion 4 ("both engines escalate, or both park, not one of each") is **violated**: the sync engine now fails the parent when an invoked child *machine* fails unhandled, but the async engine still parks silently for the identical config. This is the exact asymmetry #99 was filed to close — it has moved to the other engine instead of being closed.

## Fix location (sync — correct)

`src/xstate_statemachine/sync_interpreter.py:1144-1165` (`_queue_actor_done`):

```python
# 💥 #99: a child that ENDED IN ERROR must satisfy `onError`, not
#    fall through as "did not reach final". Same shape as the async
#    engine's `_deliver_invoked_completion`; with no handler the
#    parent fails like it does for a failing callable service.
if child.status == "error":
    failure = child.error or RuntimeError(...)
    error_event = ErrorEvent(type=f"error.platform.{invoke_id}", error=failure, src=invoke_id)
    handled = self._has_error_handler_for_id(invoke_id)
    self.send(error_event)
    if not handled:
        self._fail(failure)
    return
```

## Missing counterpart (async — NOT fixed)

`src/xstate_statemachine/interpreter.py:2039-2073` (`_deliver_invoked_completion`, the async analogue used for invoked child **machines**, as opposed to `_invoke_service_task` at line ~1858 which is used for callable services):

```python
async def _deliver_invoked_completion(self, invocation, child, owner_id, status):
    await self._retire_invoked_child(owner_id, child, stop=False)
    if status == "error":
        failure = getattr(child, "error", None) or RuntimeError(...)
        await self.send(ErrorEvent(type=f"error.platform.{invocation.id}", error=failure, src=invocation.id))
        for plugin in self._plugins:
            plugin.on_service_error(self, invocation, failure)
        return   # <-- no _has_error_handler() check, no self._fail() call
    ...
```

Compare with the callable-service path in the SAME file, `_invoke_service_task` (~line 1858), which does have the parity logic:

```python
handled = self._has_error_handler(invocation)
await self.send(error_event)
...
if not handled:
    self._fail(e)
```

`_deliver_invoked_completion` (the invoked-**machine** completion path) never calls `_has_error_handler`/`_fail`. This is pre-existing from before 3c527b0 (as the original #99 report noted for sync) and the round-3 fix only patched the sync side; the async side of the SAME defect was missed.

## Residual

**Async engine**: an invoked child **machine** (not a plain callable service) that fails with no `onError` handler leaves the parent silently parked at `status='running', error=None` forever. This is strictly worse than the sync engine's (correct) new behaviour and reintroduces the asymmetry #99 exists to close — now in the opposite direction. Fix is mechanical: `_deliver_invoked_completion`'s `status == "error"` branch needs the same `_has_error_handler(invocation)` / `self._fail(failure)` pairing already present in `_invoke_service_task` a few hundred lines above it.
