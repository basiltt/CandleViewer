### Fix location

`src/xstate_statemachine/events.py`:
- `event_kind()` (268-281) — discriminator: `"done"`/`"error"`/`"after"`/`"system"`/`"event"`.
- `persist_event()` (284-302) — serialises every kind, including `ErrorEvent.error` via `repr()` (exceptions aren't JSON-safe) restored as `RestoredError`.
- `restore_event()` (305-335) — inverse; v1 (no `kind`) records re-derive provenance from `ENGINE_EVENT_SHAPES` name prefixes only for the exact engine shapes, "the one place a name is all we have."

`src/xstate_statemachine/base_interpreter.py`:
- `:1006` `"deferred": [persist_event(e) for e in self._deferred_events]` — persists deferred queue with the same helper.
- `:1229-1235` restore path re-materialises pending/deferred records via `restore_event`.

### Additional probes

- **v1 snapshots restore unchanged**: confirmed — a v1 record (no `kind`) for a plain user type restores as `Event`, non-system; for an engine-shaped name (`___xstate_statemachine_init___`, `error.platform.x`) it re-derives `is_system_event() == True` via the name-prefix fallback in `restore_event`.
- **v2 loaded by 0.8.0 code**: **not empirically testable** (would require running the actual 0.8.0 release, not this `main` clone, against a v2 payload) — documented here instead: 0.8.0's `from_snapshot` reads `record["type"]`/`record.get("payload")` directly off each pending/deferred dict (per the `3c527b0`-era code at `base_interpreter.py:1229/1235` before this fix). A v2 record for a `done`/`error`/`after` kind carries `data`/`error`/`src` keys instead of `payload`, so 0.8.0 code would call `.get("payload")` → `None` → `{}` and construct a plain `Event(type=..., payload={})`, **silently discarding** the `data`/`error` fields rather than raising. This is a **downgrade-compatibility gap**, not covered by the stated acceptance criteria (which only require v1→v2 forward compatibility, not v2→0.8.0 backward compatibility) — worth flagging as a residual, not a defect against #86/#87's own criteria.
- **`kind` field per record**: confirmed present on every persisted pending/deferred record.
- **#84 replay spot-check** (adjacent claim from the task): a deferred event's `Receipt.deferred` is `True`; after a snapshot round-trip the deferred event is restored exactly once into `_deferred_events` (no duplicate copy, no duplicate receipt/notification — there is only one `Receipt` object at the original `send(wait=True)` call site, and the restored interpreter has no mechanism that would re-issue it).
