## Fix location

`src/xstate_statemachine/sync_interpreter.py` (`_process_event_queue` /
runaway-trip handling, ~lines 617-730 per the `3c527b0..HEAD` diff): the
tripped-chain drop path now distinguishes `is_completion` (`DoneEvent` /
`ErrorEvent`) from ordinary self-generated events. A completion found in the
about-to-be-discarded tail is re-queued ahead of it (`keep`) rather than
dropped (`victims`); a completion that IS the tripping event itself is
processed directly rather than re-queued (avoiding an infinite re-trip loop).
`tripped` no longer causes categorical drop of `done.invoke`/`error.platform`
— only genuinely self-generated, non-completion events are discarded, and
each discard fires `on_event_dropped(reason="chain_budget")` (#77 criterion 6,
verified separately in `test_round3_findings.py::TestSyncRunawayObservable`).

## Residual

None against the stated criteria. Note per the CHANGELOG: a discarded
completion is never possible now, but a completion IS still *counted* against
the budget, so a pathological rollback→re-arm→done cycle remains bounded (by
design, not a defect) — this is exactly criterion 4's guarantee and is
exercised by `test_completion_arriving_mid_runaway_is_kept`.
