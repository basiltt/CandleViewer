## Residual — important scope note for the round-3 task's broader framing

The round-3 task framing asks whether **"`-W error::DeprecationWarning`
passes across the whole public surface."** Running the FULL suite under that
flag (`pytest -q -W error::DeprecationWarning`, 513s, 3269 passed / 8 failed)
shows it does **not** pass whole-suite — but **not because of `ErrorEvent.data`**.
All 8 failures are the same, pre-existing, unrelated deprecation:

```
DeprecationWarning: Target '.q' on state 'm.x.p' resolved to the SIBLING
'm.x.q' via the pre-0.8.0 fallback (XState reads a leading dot as 'child of
the source'). Write it unambiguously as '#m.x.q' -- or set 'strictTargets':
true on machine 'm' to disable the fallback. The fallback is removed in 1.0.
```
(`src/xstate_statemachine/resolver.py:105-116`, `_warn_sibling_fallback`)

Failing tests: `test_invoke_input.py::test_input_resolver_exception_becomes_on_error`,
`test_resolver.py::test_external_self_transition_target_resolution`,
`test_resolver.py::test_resolve_relative_state`,
`test_resolver.py::test_resolve_with_multiple_dots`,
`test_sync_interpreter.py::test_nested_entry_exit_actions_fire_correctly`,
`test_wave2_review_findings.py::test_default_kwarg_keeps_sibling_fallback`,
`tests_cli/test_main_execution.py::test_main_hierarchy_with_function_style`,
`tests_cli/test_round_trip.py::test_dot_relative_target_in_source`.

These tests deliberately exercise the deprecated relative-dot-target sibling
fallback (a `.7.x`-era feature slated for removal in 1.0, unrelated to #80's
`ErrorEvent`/#95's read-site fix) without disabling it or catching the
warning, so `-W error` on the whole invocation trips on the library's own
test fixtures, not on library *code paths* a normal caller would hit. This is
a **pre-existing** gap (present before #83/#95 and not introduced or claimed
fixed by #95) but it does mean the CHANGELOG's blanket claim "library no
longer reads `ErrorEvent.data`, so `-W error::DeprecationWarning` CI passes"
is true only for the `ErrorEvent.data` deprecation specifically, not for
`-W error::DeprecationWarning` as a global CI gate — a caller who turns that
flag on for their own suite will still see failures if their tests exercise
relative-dot-target resolution un-suppressed. Filed separately (not
reopening #95, whose own criteria are met): a new low-severity ride-along
candidate — "whole-suite `-W error::DeprecationWarning` is not clean;
sibling-fallback-exercising tests do not suppress the expected warning."
