# LC-28 (GH #43) — idle child actor still costs 2 asyncio tasks

## Classification: **NOT-FIXED** (task-count criterion; latency/mechanism criteria remain fixed)

CHANGELOG has **no entry for #43 in `[Unreleased]`** (checked: `grep -n "#43"
CHANGELOG.md` matches only the two `[0.8.0]` lines, both already accounted
for in the prior `verify-0.8.0/LC-28.result.md` pass). `_spawn_and_manage_actor`
is unchanged since 0.8.0: it still does `asyncio.create_task(self.
_spawn_and_manage_actor(...))` in `_invoke_service` (task #1, the "wrapper"
task) and separately `await child_interpreter.start()` inside it, which
itself creates the child's own event-loop task via `asyncio.create_task
(self._run_event_loop())` in `BaseInterpreter.start()`/`Interpreter.start()`
(task #2). The task this issue calls "the second task" was never removed —
only its *body* changed from a `sleep(0.005)` poll loop to `await
child_interpreter.wait_done()` (a future), which is the fix that **did**
land in 0.8.0 and remains in place.

## Fix location (what did/did not change)

- `src/xstate_statemachine/interpreter.py::_spawn_and_manage_actor` (around
  the `await child_interpreter.start()` / `await child_interpreter.
  wait_done()` block) — mechanism fixed (poll → future), task NOT collapsed.
- `src/xstate_statemachine/interpreter.py::_invoke_service`, case 1 (`if
  isinstance(service, MachineNode)`): `task = asyncio.create_task(self.
  _spawn_and_manage_actor(invocation, service))` — this is the wrapper task
  that was never removed. `_spawn_and_manage_actor` internally `await`s
  `child_interpreter.start()`, which itself spawns the child's own
  `_event_loop_task` — that pair is the "2 tasks per child."

## Residual gap

Identical to the 0.8.0 finding, unchanged in `[Unreleased]`: the "collapse
the second task" half of the proposed fix (item 3 in the original issue)
has still not landed. Every invoked/spawned child actor still costs **2**
asyncio tasks (the wrapper task created by `_invoke_service`, plus the
child's own event-loop task created by `child_interpreter.start()`), not
the targeted ≤1. The **latency** and **idle-CPU** wins from replacing the
poll loop with `wait_done()` are real and unchanged.

## Recommended CandleViewer constraint (unchanged from 0.8.0 pass)

- Continue to budget **2 asyncio tasks per invoked/spawned child actor**
  for capacity planning, not 1.
- `onDone` latency and idle-CPU/wakeup concerns remain resolved; only the
  per-actor task-count line item is unresolved.
