## Residual gaps

- The core defect — a user event named `done.review` or `error.myapp.validation` is silently invisible to `"*"` and exempt from `onUnhandled: "error"` — is **fully present, unchanged** on main. Options 1 (provenance-based exemption) and 2 (reject at build time) from the issue's "Expected" section were both declined; only option 3 (document + warn) shipped.
- The CHANGELOG explicitly defers the real fix: *"Provenance-tagged system events, which would lift the restriction entirely, are planned for 0.9."* This is an honest, documented deferral, not a silent gap — but it means the issue's literal acceptance criteria (2, 3, and 2 of the 3 named tests) do not pass and should not be marked closed as "fixed" without qualification.
- The one **new** risk this raises for the reserved-namespace pattern is: since `create_machine()` now warns for `done.review`/`error.validation`-style `on` keys, a strict CI setup that turns warnings into errors would break machines that previously worked (with the silent-drop bug). Worth flagging in follow-up guidance, not a regression against 0.8.0 behaviour itself.
