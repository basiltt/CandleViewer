# LC-42 (GH #39) — `send(event, wait=True)` with one Event instance in flight twice

## Classification: **FIXED** (additive; default `send()` unchanged)

Verified on `main @ 5327ba6` (pre-0.8.1). Same additive `Receipt`/`wait=True`/
`priority=True` surface as the 0.8.0 pass (unchanged since), **plus** the
`[Unreleased]` fix for #75/#39: "`send(event, wait=True)` no longer hangs
when one `Event` instance is in flight twice" via `Interpreter._detach()`
(`interpreter.py`, `_detach` staticmethod, called from `send()` when
`wait and event_obj is event_or_type`).

## Fix location

- `src/xstate_statemachine/interpreter.py`: `Interpreter.send()`, the guard
  `if wait and event_obj is event_or_type: event_obj = self._detach(event_obj)`
  (added since 0.8.0), and the new `_detach()` staticmethod immediately
  below `send()` — copies an `Event` via `dataclasses.replace`, a
  NamedTuple via `._replace()`, else `copy.copy`. Receipts are keyed on
  `id(event_obj)` of the **queued envelope**, which is now always distinct
  per `send(..., wait=True)` call even when the caller passes the exact
  same object twice — the caller's own instance is read, never written.
- CHANGELOG `[Unreleased]`: "`send(event, wait=True)` no longer hangs when
  one `Event` instance is in flight twice (#75, #39)."
