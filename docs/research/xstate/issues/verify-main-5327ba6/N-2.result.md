## Classification: **FIXED**

## Summary
`Clock.set_timeout` gained an explicit `sync: Optional[bool] = None` keyword
(`clock.py`). `SyncInterpreter.__init__` sets `self._clock_sync_lane = True`
and calls `self._set_timeout(...)` (a wrapper that passes `sync=True`)
instead of `self.clock.set_timeout(...)` directly, so the lane is now chosen
by the *owning engine*, not by whether a loop happens to be running on the
calling thread. `RealClock.set_timeout` still falls back to the old
ambient-context heuristic only when `sync` is left `None` (third-party
clocks/engines), preserving backward compatibility with the 0.8.0 `Clock`
protocol.

## Fix location
- `src/xstate_statemachine/clock.py`: `Clock` protocol and `RealClock.set_timeout`
  gain `sync: Optional[bool] = None`; branch is `if sync is None: <ambient
  heuristic>` else honor caller's explicit lane.
- `src/xstate_statemachine/sync_interpreter.py`: `self._clock_sync_lane = True`
  set in `__init__`; `_fire`/timer-arming call sites switched from
  `self.clock.set_timeout(...)` to `self._set_timeout(...)` (lines near the
  `after`-timer and delayed-send call sites, e.g. around the diff hunks
  touching `handle = self._set_timeout(_fire, ...)`).
