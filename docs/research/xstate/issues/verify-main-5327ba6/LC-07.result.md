# LC-07 / GH#31 — Verification on main @ 5327ba6 (pre-0.8.1)

## Classification: **PARTIAL**

Part 1 (child-first resolution) and Part 2 (build-time validation under the new default `strict_targets=True`) are both fixed. Two residual gaps remain:

1. The two engines still **disagree** at runtime when a caller opts out of build-time validation with `create_machine(..., strict_targets=False)` — the documented 0.7.x-compatible escape hatch that is only removed in 1.0. Under that opt-out, `SyncInterpreter` raises `StateNotFoundError` but the async `Interpreter` silently no-ops (state unchanged, no exception) — the exact "engines disagree" defect the issue reported, now confined to the escape hatch rather than the default.
2. The library's original repro script (`repro/LC-07_relative-dot-target-silent-noop.py`) now fails for an **unrelated** reason: an orthogonal calling-convention change (user action callables are now invoked as `impl(interpreter, context, event, action_def)` — 4 args including the interpreter — rather than the repro's `(context, event, action, name=name)` 3-parameter lambda shape). The repro's lambdas silently receive the wrong values in the wrong slots (`c=interp`, `e=context`, `a=event`, and `n` keeps its default), so `log.append(n)` never executes — this is a **test-script incompatibility**, not a regression of the dot-target fix itself (verified directly: with a corrected 4-arg action signature, resolution to `m.A.A2` and the exit/entry trace both work correctly).

## Residual gaps

1. **(blocks full "FIXED")** Runtime engine parity under `strict_targets=False` is not achieved: `SyncInterpreter` raises `StateNotFoundError` for an unresolvable dot target at `send()`-time; async `Interpreter` silently no-ops (matches the pre-0.8.0 behaviour this issue reported as the core defect, just now scoped to the opt-out path instead of the default). Acceptance criterion #4 is explicitly about this parity and is not met. Recommend a fast-follow before closing: route the async run loop's swallowed `StateNotFoundError` (still at `interpreter.py:479-487`-equivalent) through the new `on_transition_failed`/`on_unhandled_event`-style observability hooks so it is at least visible, matching what LC-48's fix elsewhere in this window (`#33`) already provides for other failure classes.
2. `repro/LC-07_relative-dot-target-silent-noop.py` needs updating for the library's unrelated (but real) action-callable signature change (`impl(interpreter, context, event, action_def)`, 4 positional args including the interpreter) before it can serve as a regression guard again; as written it currently fails for a reason orthogonal to LC-07 and should not be read as evidence the dot-target fix regressed.
3. Item A (once-per-pair warning) was verified by re-checking the same pair already warned about during crit2 in the same process; a stronger check would isolate this in a fresh subprocess to rule out any interference between checks, though the process-wide set (`_SIBLING_FALLBACKS_WARNED`) design makes cross-contamination between checks the expected (and desired) behavior here, not a test artifact.
