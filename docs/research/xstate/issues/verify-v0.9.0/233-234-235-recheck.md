## #233 — SyncInterpreter._enqueue_restored honours priority lane

one inbox event (`PING`, priority=False) then one priority event (`GO`,
priority=True), then `drain_pending()`.
- Result: `order: ['GO', 'PING']` — the priority record landed ahead of
  the inbox record despite being enqueued second.
- Code review (`sync_interpreter.py:718-735`): non-priority path appends;
  priority path inserts at `self._restored_priority_count` and
  increments the counter, giving FIFO-among-priority, priority-ahead-of-
  inbox — matches the docstring and the async engine's two-lane
  behaviour.
- No false positive: the fix is exercised directly, not just via a
  stale/vacuous assertion. **CONFIRMED fixed.**
