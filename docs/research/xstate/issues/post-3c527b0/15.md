## Summary

#79 moved the `"*"` matcher and the `onUnhandled` policy onto provenance, which is the right design and closes the reported `done.typo` / `done.review` cases. But `models.is_known_event` (`models.py:1552-1560`) is still a **name** test, now against `ENGINE_EVENT_SHAPES`:

```python
if event_type.startswith(ENGINE_EVENT_SHAPES):
    return True
```

So on a `strict` machine, any undeclared event whose name begins with one of the six engine shapes is accepted silently.

## Environment

- `xstate-statemachine`, `main` @ `3c527b0` (merge of PR #83). `__version__` reports `0.8.0`.
- CPython 3.13.7, Windows 11 x64 (10.0.26200)

## Minimal reproduction

Send each of the names below to a `strict=True` interpreter on a machine that declares none of them. Full script: `g14_strict_shape_residual.py`.

## Observed

```
  done.typo                        UnknownEventError     # fixed by #79
  done.review                      UnknownEventError     # fixed by #79
  error.validation                 UnknownEventError     # fixed by #79
  done.invoke.NEVER_INVOKED        ACCEPTED   <-- undeclared, strict did not fire
  done.state.NO_SUCH_STATE         ACCEPTED
  error.platform.NOT_A_SERVICE     ACCEPTED
  after.party                      ACCEPTED
  after.9999999                    ACCEPTED
  xstate.whatever                  ACCEPTED
  xstate.done.actor.ghost          ACCEPTED
  ___xstate_forged                 ACCEPTED
```

`after.party` is the nicest of these: it is not even a well-formed `after.` shape — no numeric delay — and strict mode waves it through.

The in-code comment acknowledges the tension (*"the one place a name is all we have"*), and narrowing `done.` → `done.invoke.` genuinely closes the reported case. The residual is still name-shaped, though, and it is exactly the surface `strict` exists to defend.

## Expected

`send()` already holds the event **object** at `_check_strict`, so the provenance flag is available there:

```python
if is_system_event(event):
    return          # engine-minted: exempt
# otherwise: name must be declared, whatever namespace it is in
```

The name test is genuinely needed only for **build-time** validation of `on` keys and static `raise` targets, where no object exists. Splitting the two would leave the runtime check fully provenance-based and the build-time check name-based, which is the intended architecture.

## Why this matters

A typo in the `after.` or `xstate.` namespace is silent under `strict` — and since these are also the namespaces where a name is easy to get subtly wrong (an actor id, a delay), a machine can carry a dead handler forever with strict mode on and reporting nothing. Consumers who adopt `strict` specifically to catch that class of mistake do not get it here.

## Acceptance criteria

1. On a `strict` machine, an undeclared user-sent event is rejected regardless of its name, including in the `done.invoke.`, `done.state.`, `error.platform.`, `after.`, `xstate.` and `___xstate` namespaces.
2. Engine-minted events remain exempt, verified by a machine that actually declares an `invoke`/`onDone` and an `after`.
3. Build-time `on`-key and static-`raise` validation is unaffected.
4. Test: `test_strict_rejects_undeclared_engine_shaped_names`, parameterised over the list above.
