## Ride-along — the checkpoint-skip predicate does not model `always` / `on` action lists (Medium)

The "skip the context checkpoint when the transition runs no actions" optimisation is a real win — we reproduce it at 0.9978×–1.056× of baseline on an idle `rollback` machine, versus 0.776× before it. One note for the record, since the CHANGELOG lists it only as a performance improvement and it is a behaviour change:

The skip predicate asks whether the transition, the exited states and the entered subtree declare any action. It does **not** model an `always` transition on the *target* whose own action list runs as part of the same macrostep. We verified it *safe* in the case we tested, but the predicate is narrower than the invariant it has to uphold, so the safety is incidental rather than structural.

Suggest a targeted test pinning that a transition into a state with an `always` (or `on`) action list still checkpoints, before this optimisation becomes load-bearing.

## Ride-along — rollback cost in the release notes

"≈0.98× of the default" is measured on transitions that declare **no actions at all**. On an otherwise identical two-state machine on this commit: 0.949× with no actions, **0.878× with actions**; and `benchmarks`' 50 000-event burst gives armed `rollback` at **0.854×** and `rollback_and_defer` at **0.774×**. All defensible numbers; only one is in the CHANGELOG. Suggest qualifying the claim with "on transitions that run no actions", so nobody budgets capacity from it.
