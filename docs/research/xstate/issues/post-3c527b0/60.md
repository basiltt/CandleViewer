## Ride-along — one remaining engine-parity gap, filed separately

`SyncInterpreter` still never converts an invoked **child-machine** failure into `onError`: the parent stays in the invoking state with `status='running', error=None` and never learns the child failed. The async engine handles this correctly (`interpreter.py:2028`, `_deliver_invoked_completion` with `status == "error"`).

Baseline comparison confirms this is **not** introduced by PR #83 — the sync `_invoke_service` changes in that commit are pure `DoneEvent` → `ErrorEvent` renames. We have filed it separately rather than here, but it is the kind of thing this issue exists to catch, and the new `test_actor_perf.py::TestErrorEvent::test_child_machine_failure_delivers_error_event` covers only the async engine.
