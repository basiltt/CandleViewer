# Comment for issue #79 (N-8) — `error.*` / `done.*` event names are invisible to `"*"` and `onUnhandled`

**Action:** comment+reopen
**Disposition:** REOPEN (fix still required: acceptance criterion 8 — provenance must not be settable by user code, and must survive a snapshot)

---

Verified on main @ 3c527b0 (pre-0.8.1). Re-verification after PR #83, as part of our adoption audit (#26). Build identified by commit — `__version__` still reports `0.8.0` on this tree. CPython 3.13.7, Windows 11.

**The reported defect is closed, and closed well.** Deciding system status by provenance rather than by name is the right design, and the user-facing symptoms are all gone:

| # | Acceptance criterion | |
|---|---|---|
| 1 | User event `done.review` matched by `"*"` | ✓ |
| 2 | …and by the `done.*` prefix wildcard | ✓ |
| 3 | …trips `onUnhandled: "error"` when unhandled | ✓ |
| 4 | `strict` rejects an undeclared user `done.review` | ✓ |
| 5 | Engine-minted `done.invoke.*` / `after.*` remain exempt | ✓ — checked on a `strict` machine declaring both `invoke`/`onDone` and `after`; no false "unhandled", no interference |
| 6 | `escalate` path unchanged | ✓ |
| 7 | Case variant `DONE.review` also treated as user traffic | ✓ — the case-variant trap is gone because *neither* spelling is exempt any more |
| 8 | **`Event.system` is not spoofable** | ✗ — see below |
| 9 | `SYSTEM_EVENT_PREFIXES` still importable | ✓ |
| 10 | The build-time reserved-namespace warning is withdrawn | ✓ — correctly, its premise no longer holds |

Criterion 8 holds against the `send(type, payload)` signature, but not against the `Event` object. `events.py:117`:

```python
system: bool = field(default=False, compare=False, repr=False)
```

That is an ordinary field on the **public** `Event` dataclass, so `Event("X", system=True)` is valid, supported, type-checked user code — and all three consumers trust it unconditionally (`base_interpreter.py:1539` skips `strict` *and* `event_schemas`; `:3258` skips `onUnhandled`; the wildcard matcher skips `"*"`). We confirmed the bypass on the async engine, on `SyncInterpreter`, and through `send_threadsafe`.

The name-based rule this PR removed was at least *hard to hit by accident*. A public dataclass field with load-bearing security semantics is an explicit opt-out any caller can set. We think the fix restored the exemption hole it was closing, through a different door.

**Two further gaps in the same mechanism, filed separately with repros:**

1. **Provenance does not survive a snapshot** — and this one is a behavioural regression against the previous commit. `base_interpreter.py:999-1010` persists only `type` and `payload`; `:1229`/`:1235` rebuild every deferred and pending event as `Event(type=..., payload=...)`, i.e. `system=False` unconditionally. An `escalate` event that was exempt before the snapshot comes back as user traffic: it now fails a machine configured `onUnhandled: "error"`, and is swallowed by `"*"`. Under the old name rule the exemption was a pure function of `event.type` and therefore gave the **same answer either side of a restore**. This is #79 meeting #47, and the CHANGELOG does not mention it.
2. **`strict` still exempts by name** via `ENGINE_EVENT_SHAPES`: `done.invoke.NEVER_INVOKED`, `done.state.NO_SUCH_STATE`, `error.platform.NOT_A_SERVICE`, `after.party`, `after.9999999`, `xstate.whatever` and `___xstate_forged` all pass undeclared. `after.party` is the nicest of these — not even a well-formed `after.` shape, and strict waves it through. Since `send()` already holds the event **object** at `_check_strict`, the provenance flag is available there; the name test is only needed for build-time `on`-key validation.

**Disposition: reopen** for criterion 8 (provenance settable by user code; provenance lost across a snapshot). Everything else in the issue is confirmed working and could be struck from the criteria list.

## Ride-along notes

**Dead constant with a now-false comment (Low).** `base_interpreter.py:275` still binds `_SYSTEM_EVENT_PREFIXES`, and grep confirms **zero** remaining readers — both former consumers were converted to provenance in this diff. The comment above it still says the constant is *"Shared by the wildcard matcher, the unhandled-event policy and strict mode so the three can never disagree about what counts as a system event"*, which describes the architecture this commit deleted. It is the single most misleading line left in that file for the next reader.

**Deleted tests were not replaced with coverage of the new surface (Low).** Three tests were correctly removed along with the withdrawn build-time warning, but neither the forged-`system` bypass nor the restore-provenance gap has a test. The feature traded a name-shaped attack surface for an object-shaped one and the object-shaped one is untested.

**The provenance API is undocumented and unexported (Low).** `is_system_event`, `system_event` and `Event.system` are the actual mechanism, and none is re-exported from the package root or mentioned in a user-facing doc (one passing mention of `Event.system` in the changelog). Meanwhile `ENGINE_EVENT_SHAPES` *is* announced in the CHANGELOG but is not re-exported either. A plugin author writing an `on_event_received` hook has no supported way to ask "did the engine mint this?" and will reach for the name prefixes this release deprecated in spirit.
