## Ride-along — error precedence across lifecycle phases (Low)

`send_threadsafe()`'s error precedence before `start()` is ambiguous: the strict/schema error and the not-started error race for which one surfaces. Observed on this commit: before `start()`, a `RuntimeError`; on a *stopped* interpreter, `UnknownEventError` for an unknown event but no raise at all for a known one.

Not a correctness problem — both are errors and both are honest — but a caller writing `except` clauses around a gateway cannot predict which arrives, and the answer changes with the interpreter's lifecycle phase. Worth documenting the intended precedence, or fixing it to be phase-independent.
