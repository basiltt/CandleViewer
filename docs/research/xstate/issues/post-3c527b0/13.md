## Summary

`base_interpreter.py:1779-1782` normalises a non-`Event` into an `Event` by reading `.data`:

```python
return Event(type=resolved.type, payload=getattr(resolved, "data", {}) or {})
```

For a `DoneEvent` that is a dict and correct. For an `ErrorEvent`, `.data` is the deprecated property returning the **exception**, so the resulting `Event.payload` is a `ValueError` rather than a mapping.

`Event.payload` is typed `Dict[str, Any]` and every other path in the library maintains that invariant, so a consumer doing the ordinary thing — `event.payload.get("k")` — gets an `AttributeError`.

(As a bonus, this site is one of the two places the library trips its own `ErrorEvent.data` `DeprecationWarning`.)

## Environment

- `xstate-statemachine`, `main` @ `3c527b0` (merge of PR #83). `__version__` reports `0.8.0`.
- CPython 3.13.7, Windows 11 x64 (10.0.26200)

## Minimal reproduction

Unit level:

```python
from xstate_statemachine.events import DoneEvent, ErrorEvent
# ... call the interpreter's _resolve_event_spec with each:
#   DoneEvent("done.invoke.svc", {"k": 1}, "svc")
#   ErrorEvent("error.platform.svc", ValueError("boom"), "svc")
```

End-to-end: a child whose service fails, with `sendParent` forwarding the triggering event upward — a standard supervision idiom. Full scripts: `g13_resolve_event_spec_errorevent.py` (unit) and `g13b_reachable.py` (end-to-end).

## Observed

```
DoneEvent  -> Event(type='done.invoke.svc', payload={'k': 1})       payload type: dict
ErrorEvent -> Event(type='error.platform.svc', payload=ValueError('boom'))
  isinstance(payload, dict): False
  event.payload.get(...) would now raise: AttributeError: 'ValueError' object has no attribute 'get'

# end-to-end, forwarded via sendParent:
forwarded event seen by parent: {'type': 'error.platform.svc',
                                 'payload': "ValueError('boom')", 'is_dict': False}
```

## Scope note

The shape bug **pre-dates** PR #83 — the same site previously read `DoneEvent.data`, which also held the exception. It is raised now because #80 is the natural moment to fix it: the type system finally has a place to put the exception, and `ErrorEvent.error` is that place.

## Expected

```python
if isinstance(resolved, ErrorEvent):
    return Event(type=resolved.type, payload={"error": resolved.error, "src": resolved.src})
```

— or preserve the `ErrorEvent` unchanged where the downstream path can take it. Either way, `Event.payload` should always be a `Dict[str, Any]`, as its annotation promises.

## Acceptance criteria

1. Resolving an `ErrorEvent` through `_resolve_event_spec` yields an event whose `payload` is a mapping, or preserves the `ErrorEvent`.
2. `sendParent` forwarding a triggering `ErrorEvent` delivers something the parent can read with `.get()` or with `isinstance(event, ErrorEvent)`.
3. No `DeprecationWarning` is emitted from this site.
4. Test: `test_resolve_event_spec_errorevent_payload_is_mapping`.
