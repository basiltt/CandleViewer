## Summary

`Event.system` is created by the engine and then thrown away at the first persistence boundary. `get_persisted_snapshot()` writes only `type` and `payload`; `from_snapshot` re-materialises every deferred and pending event as a plain `Event` with `system=False`.

An `escalate` event that was exempt from `onUnhandled` and `"*"` before the snapshot comes back as ordinary user traffic. A machine that restores with such an event in its inbox and `onUnhandled: "error"` goes to `status="error"` where it previously did not.

**This is a behavioural regression introduced by this release.** Under the previous name-based rule the exemption was a pure function of `event.type`, so it gave the **same answer before and after** a restore. Provenance makes it a function of in-memory state the snapshot does not carry.

## Environment

- `xstate-statemachine`, `main` @ `3c527b0` (merge of PR #83). `__version__` reports `0.8.0`; CHANGELOG targets 0.8.1.
- CPython 3.13.7, Windows 11 x64 (10.0.26200)

## Evidence

`base_interpreter.py:999-1010` persists only `type` and `payload`. `:1229` and `:1235` rebuild every record as:

```python
Event(type=record["type"], payload=record.get("payload") or {})
```

`Event.system` is `compare=False, repr=False` and is not in the serialised shape, so the flag cannot round-trip.

## Minimal reproduction

```python
import asyncio, json
from xstate_statemachine import Event, MachineLogic, create_machine
from xstate_statemachine.interpreter import Interpreter

UNH = {"id": "u", "initial": "a", "onUnhandled": "error",
       "states": {"a": {"on": {"GO": "b"}}, "b": {}}}
STAR = {"id": "s", "initial": "a",
        "states": {"a": {"on": {"*": {"target": "b"}}}, "b": {}}}

async def live(cfg, evt):
    it = Interpreter(create_machine(cfg, logic=MachineLogic()))
    await it.start(); await it.send(evt); await asyncio.sleep(0.1)
    out = (it.status, repr(it.error), set(it.current_state_ids))
    await it.stop(); return out

async def restored(cfg, evt):
    it = Interpreter(create_machine(cfg, logic=MachineLogic()))
    await it.start()
    it._put_inbox(evt)
    snap = json.dumps(it.get_persisted_snapshot())
    await it.stop()
    it2 = Interpreter.from_snapshot(snap, create_machine(cfg, logic=MachineLogic()))
    await it2.start(); await asyncio.sleep(0.1)
    out = (it2.status, repr(it2.error), set(it2.current_state_ids))
    await it2.stop(); return out

async def main():
    esc = Event(type="xstate.error.actor.kid", payload={"error": "x"}, system=True)
    print("onUnhandled=error, escalate event")
    print("  live          :", await live(UNH, esc))
    print("  after restore :", await restored(UNH, esc))
    print("'*' matcher, escalate event")
    print("  live          :", await live(STAR, esc))
    print("  after restore :", await restored(STAR, esc))

asyncio.run(main())
```

## Observed

```
onUnhandled=error, escalate event
  live          : ('running', 'None', {'u.a'})                          # exempt, correct
  after restore : ('error',   'UnhandledEventError(...)', {'u.a'})      # FAILS THE MACHINE

'*' matcher, escalate event
  live          : ('running', 'None', {'s.a'})                          # exempt, correct
  after restore : ('running', 'None', {'s.b'})                          # swallowed by "*"
```

A direct round-trip inspection confirms the cause:

```
restored: [('Event', 'xstate.error.actor.child', False),
           ('Event', 'USER_EVT', False)]
```

— the escalate event and the user event are indistinguishable after the round-trip.

## Expected

The exemption gives the same answer either side of a snapshot/restore.

Options, roughly in increasing cost:

1. Persist the flag (`"system": true` in the record) and honour it on restore. This changes the serialised shape, so it wants a schema-version bump.
2. Re-derive provenance on restore from the event type for the engine-minted shapes only (`ENGINE_EVENT_SHAPES`), accepting that this is the name rule again but *only* at the restore boundary where no better information exists.
3. Refuse to persist non-user events and document that a snapshot must be taken from a quiesced interpreter.

## Why this matters

It is silent and it is directional: the restored machine is *more* likely to fail than the live one, and the difference appears only after a crash — precisely when the operator is least able to reason about it. Any consumer whose recovery path is snapshot-based inherits a failure mode that did not exist on the previous commit.

This is the interaction of two features shipping in the same release (#79 provenance, #47 pending-event persistence) and the CHANGELOG does not mention it.

## Acceptance criteria

1. For every `onUnhandled` policy and for the `"*"` matcher, an engine-minted event in the inbox produces the same outcome whether the machine is live or restored from a snapshot taken at that moment.
2. If the persisted shape changes, the snapshot schema version is bumped and the upcast path is documented.
3. Tests: `test_provenance_survives_snapshot_roundtrip`, `test_restored_escalate_event_does_not_trip_on_unhandled`.
4. The CHANGELOG notes the interaction between #79 and #47.
