## Summary

`get_persisted_snapshot()` filters the inbox with `isinstance(e, Event)`. `ErrorEvent` and `DoneEvent` are `NamedTuple`s, not `Event`s, so an accepted-but-unprocessed invoke failure or completion is **not persisted** — no warning, no log line, no record.

#47 added `pending_events` to the snapshot precisely so that a crash between accept and process could not lose an event. #80 then routed **every** service and child-actor failure through a class that falls through that filter. A machine restores believing the invoke never failed, sits in the invoking state, and no `onError` ever fires.

## Environment

- `xstate-statemachine`, `main` @ `3c527b0` (merge of PR #83). `__version__` reports `0.8.0`; CHANGELOG targets 0.8.1.
- CPython 3.13.7, Windows 11 x64 (10.0.26200)

## Evidence

`base_interpreter.py:1007-1010`:

```python
"pending_events": [
    {"type": e.type, "payload": copy.deepcopy(e.payload)}
    for e in self.pending_events
    if isinstance(e, Event)          # <-- ErrorEvent / DoneEvent are NamedTuples
],
```

The restore side (`:1233-1236`) could not round-trip them anyway: it rebuilds everything as a plain `Event`, which has no `error` field and the wrong class for `isinstance(event, ErrorEvent)`.

## Minimal reproduction

```python
import asyncio
from xstate_statemachine import Event, MachineLogic, create_machine
from xstate_statemachine.events import DoneEvent, ErrorEvent
from xstate_statemachine.interpreter import Interpreter

CFG = {"id": "m", "initial": "w", "states": {
    "w": {"invoke": {"src": "svc", "id": "svc", "onError": {"target": "bad"}}},
    "bad": {"type": "final"}}}

async def blow(i, c, e):
    await asyncio.sleep(0.02)
    raise ValueError("boom")

async def catch_window(it, out):
    """Snapshot the instant the inbox is non-empty."""
    for _ in range(200_000):
        pending = it._snapshot_pending_events()
        if pending:
            out["pend"] = [f"{type(e).__name__}:{e.type}" for e in pending]
            out["snap"] = [r["type"] for r in
                           it.get_persisted_snapshot()["pending_events"]]
            return
        await asyncio.sleep(0)

async def main():
    # A) natural: a real failing invoke, snapshotted inside the accept->drain window
    it = Interpreter(create_machine(CFG, logic=MachineLogic(services={"svc": blow})))
    await it.start()
    out = {}
    await asyncio.wait_for(catch_window(it, out), 3)
    print("A) real inbox held    :", out.get("pend"))
    print("A) snapshot persisted :", out.get("snap"))
    await it.stop()

    # B) deterministic: park one of each kind
    it2 = Interpreter(create_machine(CFG, logic=MachineLogic(services={"svc": blow})))
    await it2.start()
    it2._put_inbox(ErrorEvent("error.platform.svc", ValueError("boom"), "svc"))
    it2._put_inbox(DoneEvent("done.invoke.svc", {"ok": 1}, "svc"))
    it2._put_inbox(Event("USER_EVT"))
    print("B) parked in inbox    :",
          [f"{type(e).__name__}:{e.type}" for e in it2.pending_events])
    print("B) snapshot persisted :",
          [r["type"] for r in it2.get_persisted_snapshot()["pending_events"]])
    await it2.stop()

asyncio.run(main())
```

## Observed

```
A) real inbox held    : ['ErrorEvent:error.platform.svc']
A) snapshot persisted : []                       <-- the failure is GONE

B) parked in inbox    : ['ErrorEvent:error.platform.svc',
                         'DoneEvent:done.invoke.svc',
                         'Event:USER_EVT']
B) snapshot persisted : ['USER_EVT']             <-- both engine events dropped
```

(A) is a real failing `invoke` on a real interpreter; the probe snapshots inside the window between the engine enqueuing the `ErrorEvent` and the run loop draining it. That window is short on a toy machine but is exactly as long as the current macrostep on a real one.

## Expected

Either the engine events round-trip, or their loss is loud.

1. **Round-trip them.** Persist a discriminator (`"kind": "error" | "done" | "event"`) plus `src`, and reconstruct the right class on restore. `ErrorEvent.error` is an exception and is not generally serialisable, so this needs a documented degradation — e.g. persist `repr(error)` and restore a `RuntimeError` carrying it, which is still infinitely better than losing the failure.
2. **Or refuse and say so.** `logger.warning("dropping %d non-Event pending event(s) from snapshot", n)`, and document that a snapshot should be taken from a quiesced interpreter.

Option 2 alone would have surfaced this; option 1 is what #47's stated guarantee implies.

## Why this matters

#47's stated purpose is that *"a crash between accept and process lost them with no trace; with it a restored machine resumes with its mailbox intact."* That guarantee now has a hole at exactly the events you least want to lose.

Pre-#80 a failure was a `DoneEvent` and was dropped the same way — the mechanism is not new. What #80 changed is the blast radius: from "invoke completions" to "all invoke completions **and** all failures". Every service failure and every child-actor failure now takes this shape.

The filter is silent. There is no way for a consumer to discover after the fact that a failure was dropped.

## Acceptance criteria

1. A snapshot taken while an `ErrorEvent` is pending either preserves it (restored machine reaches the `onError` target) or emits a warning naming the dropped event type and count.
2. Same for `DoneEvent`.
3. If the persisted shape changes, the snapshot schema version is bumped.
4. Tests: `test_snapshot_preserves_pending_error_event`, `test_snapshot_warns_on_dropped_engine_event`.
