## Summary of severity changes

No severity changes from the original register. All six defects were
independently reproduced this pass with the shipped scripts, all cited source
locations were re-read and confirm the claimed mechanism, and the original
severities (High/High/High/Medium/Medium/Medium) hold up under a
financial-OMS lens:

- **D-determinism-1** stays High: a lying `Receipt.deferred` flag on a
  correctly-processed event is silent wrongness on the exact API
  (`send(wait=True)`) an order-placement caller uses to know whether its
  request has been handled.
- **D-determinism-2** and **D-determinism-3** stay High: both mean the same
  recorded event script can produce a genuinely different trade outcome
  (fills vs. cancels) depending on unrecorded scheduling details or which
  engine replays it — a hard architectural constraint for any replay/audit
  design, not a cosmetic issue.
- **D-determinism-4**, **D-determinism-5**, **D-determinism-6** stay Medium:
  each is a real, reproducible gap (extra hook record, no clock-preserving
  resume, thread-safe send reordering) but each is either a constant/fixed
  offset, an explicitly documented limitation, or an avoidable-by-design
  concurrency hazard — none of them corrupt already-committed state or lie
  about a financially consequential fact the way D-determinism-1 does.
